# SPEC — CartList (담은 항목 목록)

작업 문서. 구현 산출물이 아니다.

## 0. 스펙 소스 판별

별도의 계약·요구사항 문서가 저장소에 없다 (README.md는 Vite 템플릿 안내문이라 요구의 근거가
아니다). 따라서 **요청 문장이 근거**이고, 근거 위치는 `요청 #n` (요청의 번호 매긴 항목) ·
`요청 본문` · `완료 조건`으로 표기한다.

§2가 만든 미확정 항목은 기본값과 대안을 §2의 표에 적고 기본값으로 진행한다. 확정은 사용자 몫이며,
표의 `선택 대기` 행이 되돌려 주는 질문 목록이다.

## 1. 명시된 것

- S1. `src/CartList.tsx`가 CartList 컴포넌트를 정의하고, `src/App.tsx`가 CartList를 렌더한다. `요청 본문`
- S2. 담긴 항목이 하나 이상이면 CartList는 각 항목을 한 줄로 렌더하고, 그 줄은 항목 이름 · 단가 ·
  수량 · 소계 네 값을 모두 표시한다. `요청 #1`
- S3. 각 줄의 소계는 그 줄의 `수량 × 단가`와 같다. `요청 #1`
- S4. 각 줄에는 수량 스테퍼가 있다 — 아이콘(기호)만 보이는 작은 버튼 두 개(−, +)이며, 버튼 안에
  보이는 텍스트 라벨은 없다. `요청 #2`
- S5. 어떤 줄의 + 버튼을 누르면 그 줄의 수량이 정확히 1 증가한다. `요청 #3`
- S6. 어떤 줄의 − 버튼을 누르면 그 줄의 수량이 정확히 1 감소한다. `요청 #3`
- S7. 한 줄의 수량을 바꿔도 다른 줄의 수량은 변하지 않는다. `요청 #3` (각 줄이 자기 수량을 갖는다는 #1·#3의 귀결)
- S8. 수량이 0이 된 항목은 더 이상 담긴 항목이 아니다 — 목록에 그 줄이 렌더되지 않고, 전체 합계에도
  포함되지 않는다. `요청 #4`
- S9. 목록 아래에 전체 합계가 표시되고, 그 값은 담긴 모든 줄의 소계 합과 같다. `요청 #5`
- S10. 시작 데이터는 CartList 모듈 안에 하드코딩된 항목 2~3개다. `요청 #6`
- S11. `npm run build`(= `tsc -b` 타입체크 + `vite build`)가 종료 코드 0으로 끝난다. `완료 조건`

### 2.2 추론으로 확정한 문장

- I1. 수량이 0이 되는 순간 그 줄은 DOM에서 사라지고, 되돌리는 수단(실행 취소·복구)은 제공하지
  않는다. `[추론]`
- I2. 수량 1인 줄의 − 버튼은 확인 절차 없이 즉시 그 줄을 제거하며, 라벨·모양은 다른 줄의 − 버튼과
  같다. `[추론]`
- I3. 수량은 0 미만이 될 수 없고(0에서 제거되므로 음수 수량은 렌더될 수 없다) 상한은 없다. `[추론]`
- I4. 두 아이콘 버튼은 각각 `"<항목 이름> 수량 줄이기"` · `"<항목 이름> 수량 늘리기"`를 접근 가능한
  이름으로 갖고, 안의 기호 문자는 보조기술에서 숨긴다. `[추론]`
- I5. 두 버튼은 네이티브 `<button type="button">`이라 Tab만으로 도달하고 Enter·Space로 활성화되며,
  커스텀 `tabIndex`를 두지 않아 Tab 순서가 시각적 순서와 같다. `[추론]`
- I6. 수량 숫자는 `aria-live="polite"` 영역이라 버튼을 누른 뒤 바뀐 값이 보조기술에 읽힌다. `[추론]`
- I7. 담긴 항목이 0개면 목록 대신 "담은 항목이 없습니다." 안내를 렌더하고, 전체 합계는 계속 표시하되
  0원이다. `[추론]`
- I8. 금액은 정수 원화이고, 천 단위 쉼표 + `원` 접미사로 표시한다. 표시 포맷은 실행 환경의 로케일·
  ICU 설정에 의존하지 않는다(직접 구현한 포매터). `[추론]`
- I9. 항목은 `{ id, name, unitPrice, quantity }` 네 필드를 갖고, `id`가 목록 key이자 수량 변경 대상의
  식별자다. `[추론]`
- I10. 담긴 항목 상태는 CartList 내부 `useState`가 소유한다. 서버 통신·localStorage 영속화·전역
  상태는 두지 않으므로, 새로고침하면 하드코딩된 시작 데이터로 돌아간다. `[추론]`
- I11. CartList는 선택적 `items` prop을 받아 시작 데이터를 덮어쓸 수 있고, 생략하면 하드코딩된
  기본값을 쓴다. `[추론]`
- I12. 마크업은 `<section>` 안의 `<ul>`/`<li>`이고, 전체 합계는 `<ul>`의 형제로 목록 뒤에 온다. `[추론]`
- I13. 스타일은 새 파일 `src/CartList.css`에 두고 기존 `src/index.css`의 색 토큰을 재사용한다. 시드
  템플릿의 `src/App.css`는 수정하지 않는다. `[추론]`
- I14. 세금·배송비·할인·쿠폰·재고·품절은 이 산출물의 범위 밖이며 전체 합계는 소계의 단순 합이다. `[추론]`
- I15. 문구는 한국어 고정이고 i18n 계층을 두지 않는다. 용어는 `단가`·`소계`·`합계`로 통일한다. `[추론]`
- I16. 수량 스테퍼 외에 줄을 지우는 별도 삭제(휴지통) 버튼은 두지 않는다. `[추론]`
- I17. 자체 테스트는 `src/*.test.tsx`로 남기고 `npm test`(vitest + jsdom)로 실행한다. `tsconfig.app.json`이
  테스트 파일을 `exclude`하므로 테스트는 `tsc -b` 대상이 아니다. `[추론]`
- I18. 금액 포매터는 컴포넌트 파일이 아니라 별도 모듈 `src/formatWon.ts`에 둔다 — 컴포넌트 파일이
  컴포넌트 외의 것을 export하면 fast refresh가 깨진다(oxlint `react/only-export-components`). `[추론]`
