스펙 소스: 계약·요구사항 문서 없음. **요청 문장이 근거**다 (2026-08-14 요청, 번호 1~6 + 완료 조건).
근거 표기는 `[요청 N]` = 요청의 N번 항목, `[요청 본문]` = 번호 없는 도입 문단, `[추론]` = 근거 없이 정한 것,
`[확정]` = 사용자가 직접 답한 것, `[확정 파생]` = 사용자의 답에서 논리적으로 따라 나와 더 이상 열려 있지 않은 것,
`[확정 위임]` = 사용자가 판단을 위임해 내가 정한 것 — 구속력은 `[확정]`과 같고 근거만 내 판단이다.

## 1. 명시된 것

1. `src/CartList.tsx`가 `CartList` 컴포넌트를 export한다. [요청 본문]
2. `src/App.tsx`가 `CartList`를 렌더한다. [요청 본문]
3. CartList는 담은 항목 각각을 목록의 한 줄로 렌더한다. [요청 1]
4. 각 줄은 항목 이름, 단가, 수량, 소계 네 값을 모두 표시한다. [요청 1]
5. 한 줄의 소계는 그 줄의 `수량 × 단가`와 같다. [요청 1]
6. 각 줄에 감소 버튼(−)과 증가 버튼(+) 두 개가 있다. [요청 2]
7. 두 버튼은 아이콘만 표시하는 작은 버튼이다 — 버튼 안에 보이는 텍스트 레이블이 없다. [요청 2]
8. 증가 버튼을 누르면 **그 줄의** 수량이 정확히 1 오른다 (다른 줄의 수량은 변하지 않는다). [요청 3]
9. 감소 버튼을 누르면 **그 줄의** 수량이 정확히 1 내려간다 (다른 줄의 수량은 변하지 않는다). [요청 3]
10. 수량이 0인 줄은 담긴 항목이 아니다 — 전체 합계에 기여하지 않는다. [요청 4]
11. 목록 아래에 전체 합계가 표시된다. [요청 5]
12. CartList는 시작 데이터를 컴포넌트 안에 하드코딩해 가진다 (외부에서 항목을 주입받지 않아도 동작한다). [요청 6]
13. `npm run build`(= `tsc -b` + `vite build`)가 종료 코드 0으로 끝난다. [완료 조건]
14. 수량이 0이 된 줄은 목록에서 사라지지 않는다 — 줄은 그 자리에 남고 "담기지 않음"으로 시각 구분되며, 합계에서만 빠진다. [확정 2026-08-14]
15. 수량이 0인 줄에서 증가 버튼을 누르면 그 줄은 수량 1로 다시 담긴 항목이 되고 합계에 다시 기여한다. [확정 2026-08-14]
16. 수량에 상한이 없다 — 증가 버튼은 어떤 수량에서도 비활성이 되지 않는다. [확정 위임 2026-08-14]
17. 단가와 소계는 단위 없이 숫자만 표기한다(`89,000`). 전체 합계만 `총 89,000원` 형태로 표기한다. [확정 2026-08-14]
18. 자동 테스트는 이번 범위에 포함하지 않는다 — 완료 판정은 `npm run build` 종료 코드 0뿐이다. [확정 2026-08-14]

### 2.2 추론으로 확정한 문장

- 항목은 `{ id, name, unitPrice, quantity }` 네 필드를 가지며 `id`가 줄의 안정적 식별자다 (React `key`). [추론]
- 담은 항목 상태의 소유자는 CartList 자신이다 — `useState`로 들고 있고, props를 받지 않는다. [추론]
- 시작 데이터는 항목 3개이고 모든 시작 수량은 1 이상이다. [추론]
- 수량의 하한은 0이다 — 수량은 음수가 되지 않는다. [확정 파생 — 0 상태가 화면에 머문다면 그 아래는 없다]
- 수량이 0인 줄에서 감소 버튼은 비활성(`disabled`)이다. [확정 파생]
- 수량의 상한은 없다. [확정 위임 2026-08-14 — 재고 개념이 없어 상한 숫자를 정당화할 근거가 스펙에 없다. 재고가 도입되면 그 값이 곧 상한이 된다]
- 단가·소계·합계는 정수 원 단위이고 `Intl.NumberFormat('ko-KR')` 천단위 구분을 쓴다. 부동소수 반올림 문제는 발생하지 않는다 (단가·수량이 모두 정수). [추론]
- `원` 단위를 붙이는 곳은 전체 합계 한 곳뿐이다 — 단가·소계는 숫자만이다. [확정 2026-08-14 → §1-17]
- 전체 합계는 **수량이 0보다 큰 줄들의 소계 합**이다 (수량 0인 줄의 소계 0은 어차피 합에 영향이 없다). [추론]
- 담긴 항목이 하나도 없으면(모든 줄의 수량이 0) 합계는 `0원`으로 표시되고, 수량 0인 줄들이 그대로 보이는 채로 "담긴 항목이 없습니다" 문구가 함께 나타난다. [확정 파생]
- 각 아이콘 버튼의 접근 가능한 이름은 `aria-label`로 준다 — 증가는 `"{항목 이름} 수량 늘리기"`, 감소는 `"{항목 이름} 수량 줄이기"`. 아이콘 글리프는 `aria-hidden`이라 이름에 섞이지 않는다. [추론]
- 두 버튼은 네이티브 `<button type="button">`이므로 Tab으로 도달하고 Enter/Space로 눌린다 — 커스텀 키 핸들러를 두지 않는다. [추론]
- 목록은 `<ul>`/`<li>` 시맨틱 마크업이고, 전체 합계는 목록 **밖**(뒤)에 둔다. [추론]
- 스타일은 `src/CartList.css` 하나를 새로 만들어 `src/index.css`의 기존 CSS 변수(`--text-h`, `--border`, `--accent` 등)를 재사용한다. 기존 파일의 스타일 규칙은 고치지 않는다. [추론]
- 자동 테스트 파일은 이번 범위에 포함하지 않는다 — 완료 조건이 `npm run build`뿐이고 테스트 작성 요구가 없다. [확정 2026-08-14 → §1-18]
- 서버·저장소 연동, 항목 추가/삭제 UI, 통화 전환, 국제화는 범위 밖이다. [추론]
