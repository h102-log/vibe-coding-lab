## 1. 명시된 것

- **S1** CartList는 담긴 항목 각각을 목록의 한 줄로 렌더한다. `[요청 1]`
- **S2** 각 줄은 항목 이름, 단가, 수량, 소계(= 수량 × 단가) 네 값을 모두 표시한다. `[요청 1]`
- **S3** 각 줄에 수량 스테퍼가 있고, 스테퍼는 감소(−)·증가(+) 버튼 두 개로 구성된다. `[요청 2]`
- **S4** 두 스테퍼 버튼은 아이콘만 표시하고 작다 — 버튼 안에 보이는 텍스트 라벨을 두지 않는다. `[요청 2]`
- **S5** 어떤 줄의 + 를 누르면 그 줄의 수량이 정확히 1 오르고, 다른 줄의 수량은 변하지 않는다. `[요청 3]`
- **S6** 어떤 줄의 − 를 누르면 그 줄의 수량이 정확히 1 내려가고, 다른 줄의 수량은 변하지 않는다. `[요청 3]`
- **S7** 수량이 0이 된 항목은 "담긴 항목"이 아니다 — 전체 합계에 그 항목의 소계가 더해지지 않는다. `[요청 4]`
- **S7a** 수량이 0이 된 줄은 목록에서 즉시 제거되며, 되돌리기(실행취소)는 제공하지 않는다.
  `[사용자 확정 2026-08-14 — Q1 답변 (A)]`
- **S8** 목록 아래에 전체 합계를 표시하며, 그 값은 담긴 모든 항목 소계의 합이다. `[요청 5]`
- **S9** 시작 데이터로 항목 2~3개가 컴포넌트 안에 하드코딩돼 있다. `[요청 6]`
- **S10** 컴포넌트는 `src/CartList.tsx`에 있고 이름은 `CartList`다. `[요청 본문]`
- **S11** `src/App.tsx`는 CartList를 렌더한다. `[요청 본문]`

## 2. 명시되지 않은 것

### 2-1. 침묵 지점 찾기 (네 방향)

**(a) S1~S12가 참이 되려면 추가로 정해져야 하는 것**
- S2의 "단가·소계"는 금액이다 → **통화·자릿수 표기 규칙**이 없다(침묵 #4).
- S4의 "아이콘만" 버튼은 보이는 텍스트가 없다 → **스크린리더가 읽을 이름**이 없다(침묵 #2).
- S7의 "담긴 것이 아니다"는 합계에서의 제외는 확정하지만 **화면에서의 처리**를 정하지 않는다(침묵 #1)
  → **해소됨: 사용자 확정으로 S7a가 됨.**
- S9의 "하드코딩"은 항목 식별자·이름·단가·초기 수량의 **구체값**을 정하지 않는다(침묵 #10).

**(b) 사용 흐름을 따라가며 만난 갈림길**
- 수량 1에서 − 를 누르는 순간 → 0 → 그 줄은 어떻게 되나(침묵 #1), − 버튼을 애초에 막을까(침묵 #3).
- 모든 줄이 사라진 뒤 화면에 무엇이 남나(침묵 #5).
- + 를 계속 누르면 어디까지 오르나(침묵 #6).
- 줄이 사라질 때 그 줄의 − 버튼에 있던 **키보드 포커스**는 어디로 가나(침묵 #7).

**(c) 범위 밖이라고 명시되지 않았지만 없으면 완성이라 부르기 어려운 것**
- 상태를 누가 소유하나 — 내부 `useState`인가, 부모가 주입하는 제어 컴포넌트인가(침묵 #8).
- 자동 테스트 — vitest·jsdom·Testing Library가 설치돼 있으나 완료 조건은 build뿐이다(침묵 #9).
- 스타일 — "작은 버튼"(S4)은 CSS 없이는 참이 되지 않는다(침묵 #11).

**(d) 요청 문장 자체의 해석이 갈리는 지점**
- 요청 4 "그 줄은 더 이상 담긴 것이 아니다"의 해석이 최소 셋으로 갈린다: ① 줄을 목록에서 제거
  ② 줄은 남기되 합계에서만 제외 ③ 제거하되 되돌리기(실행취소) 제공. → 조용히 고르지 않고 승격(Q1)
  → **사용자가 ①로 확정(2026-08-14). S7a.**
- 요청 6 "하드코딩해도 된다" = 허용이지 강제가 아니다 → props 주입 여지(침묵 #8)와 얽힌다.
