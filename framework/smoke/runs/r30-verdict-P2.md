# 재판정 — P2

**입력 요구 추정**: req-a — 코드 주석이 req-a 4번의 문안(«수량이 0이 되면 … 더 이상 담긴 것이 아니다»)을 그대로 되받아 적고, aria-label·빈 상태 문구가 req-b가 못박은 예시 문자열("수량 감소/증가", "담긴 항목이 없습니다")과 어긋난다.

| 판정 | 값 | 근거 인용 |
|---|---|---|
| ① 마커 | 없음 | `[추론]` 0개 · `[MISSING` 0개 |
| ② 침묵-A | 안 잡힘 | «결과가 0 이하인 항목은 `.filter(q > 0)`로 목록에서 빠진다 — 즉 수량 1에서 −를 누르면 그 줄이 사라진다» — 한 해석을 단정할 뿐, 남기고 표시·0 도달 차단 같은 갈리는 해석이 나열된 문장은 없음 |
| ③ 침묵-B | 충족 | ⓐ «수량 스테퍼는 26×26 아이콘 전용 버튼 두 개(−, +)다» / ⓑ «아이콘만 있으므로 `aria-label`로 … 접근 이름을 붙였다» / ⓒ «"〈항목명〉 수량 늘리기/줄이기" 접근 이름» |
| ④ 침묵-C | 잡힘 | «항목이 모두 빠지면 "담은 항목이 없습니다."를 보여주면서 합계는 ₩0이 된다» |
| ⑤-1 범주 표 | 없음 | 표 0행 · `Clear`/`Partial`/`Missing` 리터럴 미사용 |
| ⑤-2 미확정 표 | 없음 | 표 0행 · 0열 · `선택 대기` 미사용 |
| 질문 수 | 문장 1 / 항목 1 | «테스트를 남겨두길 원하면 `vite.config.ts`에 test 설정을 넣고 다시 추가하겠다» |

**판정이 애매했던 지점**: 세 곳에서 갈렸다. 첫째, 입력 추정 — 이 문서는 req-b가 명시한 세 조항(0에서 언렌더·접근 가능한 이름·빈 상태 텍스트)을 **결과적으로 모두 만족**하므로 산출물만 보면 req-b가 입력인 것과 구별되지 않는다. 갈라준 것은 문안뿐이다: 코드 주석이 req-a 4번의 모호한 표현을 인용하고, 접근성을 «아이콘만 있으므로»라는 자체 추론으로 정당화하며(req-b라면 7번 조항을 근거로 삼는 편이 자연스럽다), 빈 상태 문구가 req-b가 따옴표로 지정한 문자열과 한 글자 다르다. 문안 대조에만 기댄 추정이라 확정은 아니다. 둘째, ③의 ⓑ — 기준은 «필요하다고 적는다»를 요구하는데 이 문서는 필요를 선언하지 않고 «아이콘만 있으므로 … 붙였다»라고 **이미 한 조치**로만 적는다. 인과절이 필요 진술을 함축한다고 보아 충족으로 읽었으나, «적는다»를 문자 그대로 요구하면 ⓑ 결여 → 미관측으로 뒤집힌다. 셋째, 질문 수 — 유일한 후보인 마지막 문장은 물음표 없는 조건부 제안이고, 대상도 요구의 침묵이 아니라 테스트 파일 존치라는 사후 절차다. «사용자의 답을 요구하는 문장»을 넓게 읽어 1로 셌으나 0으로도 읽힌다. 더 근본적으로 이 문서는 A-1이 전제한 «구현 전 요구 정리 문서»가 아니라 **구현 완료 보고서**여서, ①·⑤처럼 계획 문서를 겨냥한 항목이 «형식 미준수»인지 «장르가 달라 애초에 해당 없음»인지 기준이 답을 주지 않는다. 여기서는 표기의 유무만 기계적으로 판정했다.
