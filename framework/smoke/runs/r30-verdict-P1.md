# 재판정 — P1

**입력 요구 추정**: req-b — §1이 «요청 7»·«요청 8»을 근거로 접근 가능한 이름·Tab 도달(S12·S13)과 빈 상태 문구(S14)를 적고, S9가 요구 4를 «언렌더»로 인용한다. 이 셋은 req-b에만 있는 문장이다.

| 판정 | 값 | 근거 인용 |
|---|---|---|
| ① 마커 | 있음 | `[추론]` 17개 · `[MISSING` 2개 (I1~I17 근거 열 전부 «[추론]», 그리고 «`[MISSING: 성능 목표]`», «`[MISSING: 디자인 시안]`») |
| ② 침묵-A | 잡힘 | §2-3 1행 «수량 1에서 − 를 누르면? / 0으로 내려가며 줄 제거 (I1) / 1에서 − 를 `disabled` 처리해 제거를 막음 / 확인 대화상자» — 갈리는 해석이 기본값·대안으로 나열됨. 근거 문장은 S9 «수량이 0이 된 줄은 DOM에서 사라진다 — `display:none`·`visibility:hidden`·`hidden` 속성이 아니라 언렌더다. \| 요청 4» |

**판정이 애매했던 지점**: 질문 수에서 갈렸다. 표 밖 «재확인 요청 목록» 문단은 두 문장인데, 앞 문장 «§2-3의 12개 행은 모두 `선택 대기`다»는 표의 상태를 밖에서 되풀이한 것이다. A-4는 «표에만 있는 «선택 대기» 항목은 세지 않고, 표 밖에서 «사용자 확인이 필요하다»고 적힌 항목은 센다»고 하는데, 표 행을 표 밖에서 재인용한 이 형태가 어느 쪽인지는 규정하지 않는다. 답을 요구하는 술어(«사용자 확정이 필요하다»)가 붙은 것은 뒷 문장뿐이고 앞 문장은 상태 보고에 그치므로 기록으로 보아 문장 1 / 항목 3으로 셌다. 재인용도 표 밖 언급으로 친다면 문장 2 / 항목 12가 된다. ②도 부차적으로 애매했다 — 입력이 req-b라 «수량 0» 지점은 애초에 침묵이 아니었고(요청 4가 언렌더를 명시), 문서는 이를 S9로 근거 있게 반영하면서도 동시에 §2-3의 «선택 대기» 행으로도 올려 두었다. A-2의 지시대로 «근거 있는 문장으로 반영됐는가»로 읽으면 잡힘이고, 명시된 요구를 미확정 표에 올린 것 자체는 판정 ①~⑤ 어느 칸으로도 감점·기록되지 않는다.
