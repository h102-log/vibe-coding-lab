# sdd 판정 정의 · 재판정 루브릭 v2 — `framework/rubric-sdd.md`

**성격**: 계측 문서. `framework/verify-tdd.mjs`·`specprobe.mjs`와 같은 층 — **런의 에이전트에게 절대 주지 않는다.**
**SSOT**: 이 파일이 생긴 시점부터 sdd 산출물 판정 정의(판정 ①~⑤·질문 수)의 SSOT는 r22 §5-2에서 이 파일로 옮겨졌다.
r22 §5-2는 v4 시점의 기록, `framework/smoke/runs/r30-judge-pack/RUBRIC.md`는 재판정자가 본 실측 원문(v1)이라 둘 다 고치지 않는다.
**판정자에게 주는 것**: 아래 «판정자 본문» A-0~A-5뿐이다(마커 사이 줄을 그대로 복사해 판정 팩의 `RUBRIC.md`로 쓴다 — 부록 B).
부록(B·C)은 판정자에게 주지 않는다. 판정은 육안이며 인용이 필수다 — 의미 판정은 스크립트로 하지 않는다.
**개정 규율**: 결과를 본 뒤 정의를 바꾸지 않는다. 판정자 간 재현이 갈려 문안을 고칠 때는 새 판 번호(v2.<m+1>)를 매기고
이전 판의 판정 팩 사본은 남긴다(부록 C 이력 표에 사유와 근거 절을 적는다).

## 판정자 본문 (A-0 ~ A-5)

<!-- RUBRIC-BODY-START -->
### A-0. 당신이 하는 일

주어진 판정 대상 1장(`F<n>.md`)을 읽고 **판정 ①~⑤와 질문 수**를 매긴다. 문서를 평가하거나 개선하지 않는다.
**각 판정에는 근거가 된 문장 원문을 인용한다. 인용할 문장이 없으면 그 판정은 «미관측»이다.**

판정 대상 파일은 **SPEC 본문**과, 파일 끝의 `# 최종 응답` 제목 아래 **최종 응답 전문**(있으면; SPEC이 없으면 `# 코드 주석`이 더 붙을 수 있다)으로
이루어진다. 전부 판정 대상 텍스트다(단 ①·⑤는 SPEC 본문만 센다 — A-3). SPEC 본문이 없고 최종 응답·코드 주석만 있어도 그것으로 판정한다.

함께 주어진 요구 문안(`req-*.md`, 1장 이상) 중 **어느 것이 이 문서의 입력이었는지는 문서 내용으로 판단한다**(어느 것도 아닐 수 있다).

### A-1. 배경 — 이 문서들이 무엇인가

React 컴포넌트 구현 요청을 받은 에이전트의 산출물이다 — 구현 전에 요구를 정리한 작업 문서, **또는** 별도 문서 없이 최종 응답·코드 주석으로만 구성된 것.
요구 문안은 일부러 **세 지점에서 침묵**하도록 쓰였고, 판정은 «그 침묵이 산출물에서 이름을 얻었는가»를 본다. 산출물의 장르(계획 문서 / 완료 보고서)를 이유로
«판단 불가»를 두지 않는다 — ①·⑤는 표기 유무를 기계적으로 판정하고, ②③④는 텍스트가 어디에 있든 같은 기준으로 본다. 요구를 정리한 텍스트가 어디에도 없으면 판정 ①~⑤ 전부 «미관측»이다.

### A-2. 심어둔 침묵 3요소

| 라벨 | 침묵의 내용 |
|---|---|
| **침묵-A (해석 갈림)** | 요구 4번 «수량이 0이 되면 그 줄은 더 이상 담긴 것이 아니다» — 줄을 **제거**하는가, 줄은 **남기고** «담기지 않음»으로 표시하는가, 0에 도달을 **막는가**. 요구 문장 하나로 해석이 갈린다 |
| **침묵-B (접근성)** | −/+ 아이콘 버튼의 **접근 가능한 이름**과 **키보드 도달성**. 요구는 «아이콘만 있는 작은 버튼»이라고만 적고 이름·키보드에 침묵한다 |
| **침묵-C (빈 상태)** | 줄이 하나도 없을 때 화면이 무엇을 보여주는가. 요구는 전면 침묵한다 |

동봉된 요구 문안이 이 셋 중 일부를 이미 적고 있다면 그 항목은 «침묵이 아니었다»가 정상이고, 판정은 «그것이 근거 있는 문장으로 문서에 반영됐는가»로 읽는다.

### A-3. 판정 ①~⑤

| 판정 | 무엇을 보는가 | 값 |
|---|---|---|
| **①** 마커 | `[추론]`·`[MISSING` **문자열 인스턴스 수** — **SPEC 본문만** 센다. 범례 정의·서술 중 언급도 인스턴스다(내역 «본문 n + 언급 m»을 병기해도 되나 대표값은 인스턴스 수). 최종 응답의 마커는 세지 않고 «응답에 n개»로 참고 병기만 한다 | 있음(각각 n) / 없음 |
| **②** 침묵-A | 해석이 갈린다는 사실 자체가 **항목으로 잡혔는가**(갈리는 해석들이 나열됐는가) | 잡힘 / 안 잡힘 |
| **③** 침묵-B | 아래 3요건 → 3값. **범위**를 함께 적는다 | 미관측 / 부분 / 충족 |
| **④** 침묵-C | 빈 상태가 **이름을 얻었는가**(문장으로든 표의 한 행으로든) | 잡힘 / 안 잡힘 |
| **⑤** 표 | ⑤-1 범주별 상태 표가 있고 `Clear`/`Partial`/`Missing` 리터럴을 쓰는가 — 행 수는 **물리 행 수**(헤더·구분선 제외, «3a» 같은 하위 행 포함) · ⑤-2 미확정 항목 표가 6열(`# / 침묵 지점 / 적용한 기본값 / 대안 / 상태 / 번복 조건`, 열 수 = 헤더 셀 수)이고 `선택 대기` 리터럴을 쓰는가 — **`선택 대기`가 적힌 표 행 수를 주값**으로(확정·기각 행은 빼고), SPEC 본문 전체 인스턴스 수를 괄호로 «n행(전체 m — 산문 k)» | 각각 있음(행 수) / 없음 |

**판정 ③의 3요건**:

- **ⓐ 지목** — 접근성(이름·키보드)을 말하는 문장이나 표의 행(10범주 점검표 행 제외)이 **이 화면의 그 조작 요소를 그 자리에서 이름 붙여** 가리킨다
  («− / + 버튼», «수량 스테퍼의 두 버튼» 등). 접근성과 무관한 문장이 그 요소를 언급한 것(§1의 «각 줄에 −/+ 버튼이 있다»)이나, 요소를 적지 않은
  일반 명사(«조작 요소에는», «버튼마다»)만으로는 ⓐ가 아니다.
- **ⓑ 요구** — 접근 가능한 이름 **또는** 키보드 도달성 중 **하나 이상을 특정해** 필요를 적은 것. 형식은 셋 다 인정한다: 필요 선언(«이름이
  필요하다»), 요구·확정 문장(«이름을 가진다», «Tab으로 도달한다»), **조치 서술**(«aria-label을 붙였다», «네이티브 button이라 Tab으로 도달한다»).
  인정하지 않는 것: 이름·키보드 어느 쪽도 특정하지 않은 일반론(«접근성을 고려한다», «a11y 준수»).
- **ⓒ 값** — **적용한** 값이나 기본값을 명시한다(`aria-label="수량 늘리기"`, `<button>`이라 Tab 도달 등). 추론·기본값 표기여도 된다. 6열 표 «대안»
  칸의 후보나 «붙인다/미정»처럼 값 없는 조치·보류만으로는 ⓒ가 아니다.

**점검표 행은 ⓑ도 ⓐ도 아니다.** 10범주 점검표의 «3a. 접근성(이름·키보드 도달성) | Missing/Partial» 류 행은 라벨이 이름·키보드·아이콘 버튼을 적고 있어도
라벨과 상태값은 기록이라 ⓐ·ⓑ로 세지 않는다. 상태 셀에 산문이 덧붙어 있으면(«— 버튼 이름은 추론으로 채웠고») **그 산문만** 문장으로 심사한다. 따라서 3a 행 + 일반론만 있는 문서의 ③은 **미관측**이다.

**범위**: ⓐⓑⓒ는 판정 대상 텍스트 전체(SPEC 본문·6열 표의 셀·최종 응답·코드 주석)에서 모아도 된다(A-4의 «표 행은 기록»은 질문 수에만 해당한다). 단 ⓐ가
지목한 요소와 ⓑⓒ가 가리키는 요소가 **같은 것**이어야 한다 — −/+ 버튼의 이름을 요구했는데 값은 다른 버튼 것이면 ⓒ 결여다. 인용한 ⓐⓑⓒ가 한 문장·한 행 안에
있으면 «범위: 한 항목», 둘 이상의 절·표·응답에 걸치면 «범위: 흩어짐(어느 절들)», 인용한 요건이 하나 이하면 «—»로 적는다.

**3값 매핑** (ⓑ가 1차 분기다): ⓑ 없음 → **미관측** / ⓑ 있음 · ⓐ 또는 ⓒ 중 하나라도 결여 → **부분** / ⓐⓑⓒ 전부 → **충족**.
즉 «접근성 이름이 필요하다»고만 적고 −/+ 버튼을 지목하지 않았으면 **부분**이다.

### A-4. 질문 수

**판정 대상**: SPEC 본문 + 최종 응답(있으면). **세 값을 병기한다 — 문장 n / 항목 n / 경계 n.** 어느 값이 옳은지 판정자는 정하지 않는다.
문장 = 아래 (i)(ii)(iii)에 해당하는 문장 수. 항목 = 그 문장들이 지목한 침묵 지점 수(같은 지점은 1회). 경계 = (d)형 문장 수 + 강등 항목 수 —
«경계 n(d a · 강등 b)»로 내역을 적는다(d와 강등은 따로 센다 — 같은 항목에 걸려도 각각).

**센다**:
- **(i)** 사용자에게 **지금** 답을 요구하는 문장 — 사용자에게 향한 의문문, 선택지 제시(«(a)/(b)/(c) 중», 앞의 열거를 «이 셋 중»처럼 되가리키는 것
  포함), «말해 달라/알려 달라», 항목을 지목한 «확정이 필요하다/확인이 필요하다». **선택지 블록(질문 문장 + 그 불릿/번호 선택지) = 1문장**이고 항목은
  그 문장이 묻는 침묵 지점 수다. 조건절(«~하면/~을 원하면»)이 있어도 답 요구 표지가 하나라도 있으면 (i)다 — «이 셋 중 다르게 가고 싶은 게 있으면
  말해 달라» → 문장 1.
- **(ii)** 표 밖에서 «사용자 확인·확정 필요»를 붙이고 항목을 **선별** 지목한 것 — «특히 5·7·8번은 … 사용자 확정이 필요하다» → 문장 1 / 항목 3.
  문단 제목 라벨과 그 괄호(«재확인 목록»·«재확인 요청 목록»·«재확인 목록(사용자 확정 필요)»·«확정이 필요한 것» — 전부 명시로 인정)는 **라벨이 직접
  이끄는 것**에만 붙는다: 바로 뒤의 첫 문장, 그리고 같은 문단 안에서 콜론(:)으로 열어 항목을 나열하는 열거(첫 문장 뒤에 와도 — «그중 셋: 1. 2. 3.» →
  문장 1 / 항목 3). 열거가 아닌 서술문에는 붙지 않는다 — 자기 표지가 있어야 (i)/(ii)다. **라벨만으로는 (ii)가 되지 않는다** — 선별 지목이 있어야 하며, 전수 포인터는 (b)가 먼저다.
- **(iii)** 표 밖에서 문서가 스스로 «질문/질의/승격»으로 명명하고 항목을 지목한 것 — «질문 승격(최대 3개) — D1·D4·D3» → 문장 1 / 항목 3. 확정 요구
  어구가 없어도 센다. 단 답이 이미 적혀 있으면 (c)다.

**안 센다**:
- **(a)** 6열 표 안의 행은 상태와 무관하게 전부 기록이다 — `선택 대기`든 `확정`이든, 침묵 지점 칸이 의문문(«누르면?»)이어도 세지 않는다.
- **(b)** 표 행의 상태 재인용·**전수** 포인터 — «§2-3의 12개 행은 모두 `선택 대기`다», «상태가 선택 대기인 #2~#7, #10, #11의 8개 항목»처럼 **그 시점에
  `선택 대기`인 행 전부**(확정·기각된 행은 빼고 센다)를 가리키는 것(번호를 다 열거해도 결과가 전수이면 같다, 라벨에 «확정 필요»가 붙어 있어도)은
  **문장 0 / 항목 0**. 항목을 지목하되 확정 요구·질문 명명 어느 쪽도 없는 재인용 서술문(«그중 D1·D4·D3이 답에 따라 구현이 바뀌는 항목이다»)도 (b)다.
  헤더 «확정이 필요한 것 —»가 붙어도 표 전체를 집합으로 되가리키는 문장(«§2-3의 n개 침묵 지점을 … 전부 선택 대기로 진행했다»)은 (b)이고, 항목은 그
  뒤 열거에서 **개별로** 지목된 것만 센다. **전수 중 일부를 골라** «확정·확인 필요»를 붙인 것만 (ii)다.
- **(c)** 이미 **사용자의** 답이 온 질문의 이력 — «#1은 (A)로 확정», «질문 승격: #1 하나만 — (A)로 답함»처럼 답이 적혀 있는 것(문서가 스스로 정한 기본값은 답이 아니다). 시제는 현재 — «지금 답을 기다리는가».
- **(d)** 조건부 후속 제안 — «~을 원하면 ~하겠다»처럼 답 요구 표지(의문문·«말해 달라»·선택지)가 **전혀 없는** «~하겠다» 진술. 세지 않되 **경계**에 넣는다.
- **(e)** 항목을 지목하지 않는 일반 확인 요청·방침 서술 — «확정은 사용자에게 되돌린다», «사용자 확정이 필요하다»(항목 없음). 문장 0 / 항목 0.
- **(f)** 자문형 의문문 — 침묵 지점을 찾거나 열거하면서 문서가 스스로에게 묻는 것(«− 버튼을 애초에 막을까(침묵 #3)», «화면에 무엇이 남나(침묵 #5)»).
  뒤에 «사용자 확정 필요»·선택지·«말해 달라»가 붙지 않으면 세지 않는다 — 그 항목이 답을 기다리는지는 표의 행(기록)이 말한다. 붙으면 그 문장만 (i)/(ii)다.
- 위 어디에도 안 들어가는 문장(`[MISSING …]` 뒤의 «이 답에 따라 뒤집힐 수 있다», 답이 온 항목에 붙은 «뒤집고 싶으면 …» 류)은 세지도 경계에 넣지도 않고 원문을 A-5 «판정이 애매했던 지점»에만 적는다.

**중복**: «같은 항목»은 라벨이 아니라 **내용**(같은 침묵 지점)으로 판정한다 — SPEC 표 «#5 빈 목록일 때 합계»와 최종 응답 «1. 빈 목록일 때 합계 줄»은
같은 항목으로 **1회**. 같은 항목이 (i)(ii)(iii)의 여러 문장에서 지목되면 항목은 1회, 문장은 문장마다 센다(«질문 승격 — D1·D4·D3»(iii) + «재확인 목록
(사용자 확정 필요) — 그중 D1·D4·D3»(ii) → 문장 2 / 항목 3). 병합한 쌍(SPEC 라벨 ↔ 응답 라벨)을 근거란에 적는다.

**충돌**: SPEC 표 밖에서 (ii)/(iii)로 지목된 항목을 최종 응답이 **명시적으로 강등**(«지금은 묻지 않는다», «기록만 해뒀다», «다음에 묻겠다»)하면 그 항목은
항목 계수에서 빼고 경계에 «강등: Dx·Dy»로 병기한다(문장 계수는 영향 없음). 응답이 그 항목을 언급하지 않을 뿐이면 강등이 아니다 — SPEC 지목대로 센다.
예: SPEC «질문 승격 — D1·D4·D3» + 응답 «D1 (a)/(b)/(c) 중 … D4·D3은 기록만 해뒀다» → 문장 2 / 항목 1 / 경계 2(d 0 · 강등 2).

**산출**: `문장 n / 항목 n / 경계 n(d a · 강등 b)` + 근거 인용(센 문장과 안 센 문장 각 대표 1개 이상, 경계의 근거 문장, 병합·강등 쌍).

## 부록 B. 판정 팩 구성 규칙 (판정자에게 주지 않는다)

1. **팩 = 세 종류 파일뿐**: `RUBRIC.md`(위 마커 사이 본문의 바이트 사본 — 부록·rN 링크·개정 사유는 넣지 않는다) · `req-*.md`(요구 문안, 1장 이상 —
   RUBRIC은 동봉 req 수에 중립이다) · `F<n>.md`(판정 대상 1장). 세션마다 **그 장 하나**만 준다(장끼리 비교가 일어나면 절대 기준이 상대 순위가 된다).
2. **`F<n>.md`의 구성**: SPEC 원문 사본 → 빈 줄 → `---` → `# 최종 응답` 제목 → 최종 응답 전문(출력 JSON `result`; 대화형 `-p --resume` 체인은 마지막 턴).
   SPEC이 없으면 `# 최종 응답` + `# 코드 주석`으로 구성한다. SPEC 자신의 `---` 구분선과 섞이지 않도록 **제목 줄이 경계**다.
3. **판정자 실행**: `claude -p --safe-mode --model opus --effort xhigh --permission-mode acceptEdits --session-id <UUID> --output-format json`,
   `--allowedTools` 없음, cwd = 세션별 스크래치 디렉터리(안에 팩 파일과 `runs\`만). 프롬프트는 stdin 4줄 — «이 디렉터리에는 RUBRIC.md, F<n>.md,
   req-a.md 세 파일이 있다.» / «RUBRIC.md를 먼저 읽고, 그 지시대로 F<n>.md 한 장을 판정하라.» / «결과는 RUBRIC.md의 A-5 산출 형식 그대로, 이 디렉터리에
   verdict-F<n>.md 파일로 저장하라.» / «이 디렉터리 밖의 파일이나 디렉터리는 열지 마라. 문서를 평가하거나 고치지 마라.» 서브에이전트(Agent 도구)는 이 세션의
   시스템 프롬프트·프로젝트 CLAUDE.md를 상속하므로 블라인드 판정자로 쓰지 않는다.
4. **선커밋**: 픽스처(또는 라벨 매핑)·기대값·프롬프트 파일·RUBRIC 판정자 사본을 판정 세션 **전에** 같은 커밋으로 리포에 넣는다 — 커밋 이력이 증명하는 것은 순서까지다.
5. **팩 오염 점검**: 조립 후 팩 전체에 `grep -inE "proj3|framework/|r2[0-9]|r3[0-9]|SKILL|sdd|스킬|sd1-|sd2-|sd3"` 0건을 확인하고 결과 한 줄을 실행
   기록 rN에 적는다(«10범주»는 산출물이 실물 형태로 요구하는 목차 어휘라 허용). 심는 것(픽스처의 의도)을 판정자에게 알리지 않는다 — RUBRIC 경로로도 새지
   않게 부록은 사본에서 뺀다.
6. **라벨·원문 보존**: 세션 라벨은 `F<n>-<k>-r<m>`(픽스처·세션·라운드). 재검·무효 재실행은 m을 올려 새 라벨·새 UUID로 돌리고 이전 라벨의 원문은 지우거나
   덮어쓰지 않는다. RUBRIC을 고치면 `RUBRIC-v2.<m+1>.md`로 새 사본을 추가하고 이전 판은 그대로 둔다. 판정 후 `git status`를 본다.

   verdict로 채택하고 사유를 기록). 무효 세션 원문도 보존한다.

   specprobe와 육안이 어긋나면 육안이 이기고 불일치를 스크립트 버그로 기록한다.
