## 1. 1순위 지표 — `mutationScore`

> **`mutationScore` = 동결된 결함 4개 중, 산출물에 남은 자체 테스트가 실패로 잡아낸 개수.**

**"테스트를 남겼는가"는 지표가 아니다.** 시키면 남기기 때문이다 — 기존 12런이 0개인데
"남겨라"라고 쓰면 남긴다. 그건 지시 준수를 재는 것이고 `gateAC`가 세 조건 연속 8/8로
무정보였던 것과 같은 패턴이다. 그리고 껍데기 테스트(`expect(true).toBe(true)`)에 속는다.

**이 지표는 자명하지 않다.** (d)가 테스트를 남겨도 얕으면 결함을 못 잡는다.
`todo-input`이 렌더되는지만 보는 테스트는 저장소를 지워도 통과한다.
**(d)가 1/4을 받으면 그것은 실패 데이터이고 그대로 싣는다**(r7 §4.3).

### 1.1 판정 규칙

각 (산출물 × 결함) 쌍에 대해:

| verdict | 조건 | 집계 |
|---|---|---|
| `killed` | 남은 자체 테스트 중 **하나 이상 실패** (트랜스폼·런타임 에러 포함) | 잡음 (+1) |
| `survived` | 전부 통과 | 놓침 |
| `none` | 돌릴 자체 테스트가 없음 | **놓침으로 집계** |

> 트랜스폼 에러를 `killed`로 세는 것은 mutation testing의 표준 처리다. 다만 우리 결함 4개는
> 전부 export 시그니처를 유지하도록 정의했으므로(§2) 이 경로가 자주 열리지는 않는다.
> 실제로 발생하면 그 회차를 §4.4의 기록에 명시한다.

### 1.2 2순위 — 병기만 하고 결론에 쓰지 않는다 (r7 §4.5)

| 지표 | 주의 |
|---|---|
| 남은 테스트 파일 수 / 단언 수 | **결론에 쓰지 않는다.** 자명하게 (d)가 이긴다 |
| `firstImplOracle` | 실험 1과 같은 방식으로 병기. **이 트랙의 표적이 아니다** |

| 범위 밖 구현 건수 | `CONTRACT-thin.md`의 «범위 밖» 대비. **탐색적 기록일 뿐** |

## 2. 결함 세트 — 동결됨

**결함의 심판은 AC 오라클이다. 실험자가 고르는 게 아니다.**
AC 8/8을 유지하는 변경(변수명·주석)은 리팩터링이지 결함이 아니므로 세트에 못 들어온다.

```
Red-Check   : 구현 0인 시드    → AC 0/8   → "AC가 구현을 재고 있다"    (실험 1 §5)
Fault-Check : 정답 구현 + 결함 → AC 실패  → "이 결함이 요구사항을 건드린다"
```

### 2.1 정의와 Fault-Check 실측

기준 구현 = `exp2/faultbase/` (`exp/todo-a2t` 사본, 처치 없는 쪽). **baseline `gateAC 8/8`·`regression pass`·`acRunOk true` 확인 완료.**

| ID | 결함 (의미 단위 — 위치가 아니라 의미로) | 잡아야 할 AC | **실측 결과** | 판정 |
|---|---|---|---|---|
| `F-07` | 영속성 **쓰기** 경로를 제거한다 (저장소에 상태를 쓰는 호출 삭제) | AC-07 | `7/8` — **AC-07** 실패 | ✅ 유효 |
| `F-08` | 삭제 버튼의 접근성 이름을 제거한다 (`aria-label`/텍스트 콘텐츠 제거) | AC-08 | `7/8` — **AC-08** 실패 | ✅ 유효 |
| `F-03` | 토글이 앱 상태를 갱신하지 않게 한다 (상태 갱신 호출 제거) | AC-03, AC-05 | `4/8` — **AC-03·AC-05**·AC-06·AC-07 실패 | ✅ 유효 |
| `F-06` | 필터 조건을 뒤집는다 (active ↔ completed) | AC-06 | `7/8` — **AC-06** 실패 | ✅ 유효 |

**4/4 유효.** r7 §6-④(2개 이상 무효)에 해당하지 않으므로 세트를 그대로 쓴다. 제외된 결함 없음.

> **`F-03`이 4개 AC를 깨뜨린다는 것은 실행 전에 기록해 둔다.** 토글이 죽으면 필터·영속 시나리오도
> 연쇄로 깨지기 때문이다. 이는 `F-03`이 **다른 셋보다 잡기 쉬운 결함**임을 뜻하고,
> (d)가 `F-03`만 잡고 나머지를 놓치는 결과가 나오면 그 해석을 리포트에 적는다. **결함을 바꾸지 않는다.**

### 2.2 왜 4개인가

표적 2개(AC-07·08) + 기본 동작 2개면 "얕은 테스트 vs 실질 테스트"를 가르기에 충분하고,
3런 × 4 = 12회 주입으로 한 세션에 끝난다. 8개면 24회인데 추가 정보량이 그만큼 되지 않는다(r7 §4.4).

### 2.3 주입 형식 — 파일 전체 사본

결함은 patch가 아니라 **수정된 파일 전체**로 정의된다(`exp2/faults/<ID>/src/…`).
주입 = 덮어쓰기, 복원 = pristine에서 복사. patch 도구 없이 100% 재현되고, 회차마다 해시로 복원을 확인한다.

**컴파일 가능성을 유지한다.** 미사용이 되는 파라미터는 `_` 접두사로 바꿔 `noUnusedParameters`를 통과시킨다.
빌드가 깨지면 "AC가 잡았는지"와 "빌드가 깨졌는지"가 섞이고, 6단계에서도 "테스트가 잡았는지"가 흐려진다.
실측: 4개 결함 전부 `regression: pass`.

diff 전문은 `exp2/faults/F-0N.diff`에 있다.

## 4. 측정 절차 — 계측기와 커맨드

### 4.1 Fault-Check (완료)

```bash
bash exp2/faultcheck.sh            # 4개 전부
bash exp2/faultcheck.sh F-07       # 하나만
```

복원 → 주입 → `diff -u` 저장 → `node exp2/judge.mjs` 순으로 돌고, 회차마다 src 트리 해시로
복원을 확인한다(불일치 시 즉시 중단). 결과는 `exp2/runs/verdict-fault-*.json`.

### 4.2 자체 테스트 실행기

```bash
bash exp2/selftest.sh <app-dir>
# → {"files":N,"total":N,"failed":N,"verdict":"killed|survived|none"}
```

**자체 테스트의 정의 — 파일명이 아니라 내용으로 판정한다** (§0.5에서 교체):

> ① `tests/ac/**` 밖이고 ② `node_modules`·`dist`·`.git`·`coverage` 밖이고
> ③ `expect(`와 `it(`/`test(`를 **모두** 가진 `.[cm]?[jt]sx?` 파일

`selftest.sh`가 이 규칙으로 열거해 JSON으로 만들고, `SELFTEST_INCLUDE` 환경변수로 설정에 주입한다.
설정 파일은 앱 루트에 `.selftest.vitest.config.ts`로 복사해 실행하고 끝나면 지운다(잔여물 0 — 실측 확인).
**`tests/ac/**`를 제외한다** — mutation score는 AC 오라클이 아니라 에이전트가 남긴 테스트로 재는
것이므로, AC가 섞이면 지표가 통째로 무의미해진다.

결과 파일이 없으면(수집 단계에서 죽음) `killed`로 센다 — 테스트가 있는데 못 돌았다는 뜻이다.

**계측기 검증 (교체 후 재확인)**:

| 넣은 것 | 기대 | 실측 |
|---|---|---|
| 테스트 파일 없음 (`faultbase`) | `none` | ✅ `{"files":0,"total":0,"failed":0,"verdict":"none"}` |
| 통과하는 테스트만 | `survived` | ✅ `{"files":1,"total":1,"failed":0,"verdict":"survived"}` |
| 실패 1건 포함 | `killed` | ✅ `{"files":1,"total":2,"failed":1,"verdict":"killed"}` |
| **실제 (d)#1, 결함 없음** | `survived`, 20테스트 | ✅ `{"files":1,"total":20,"failed":0,"verdict":"survived"}` |

### 4.3 mutation score 측정 (6단계)

각 산출물 X에 대해:

```
0. X/src 를 exp2/pristine/<X>-src 로 백업 (측정 시작 전 1회)
1. 각 결함 F ∈ {F-07, F-08, F-03, F-06}:
     a. X/src 를 백업에서 복원 → 트리 해시로 확인
     b. F를 X에 주입 (의미 단위. 위치는 산출물마다 다르다)
     c. diff -u 를 exp2/faults-d/<X>/<F>.diff 에 저장
     d. bash exp2/selftest.sh <X>  → verdict 기록
2. 복원 → 트리 해시로 확인
```

**(a)(b) 6런**: 자체 테스트가 0개이므로 결함 주입 없이 `selftest.sh`를 1회씩 돌려 `none`을 확인한다.
`none` = 놓침이므로 mutationScore 0/4로 확정된다.

### 4.4 주입 기록 의무

**의미 단위 주입에는 사람의 판단이 들어간다.** "영속성 쓰기 경로를 제거한다"를 각 산출물의
어디에 적용할지는 코드마다 다르다(r7 §7). 따라서 **주입 diff를 전부 파일로 남겨** 사후 검증
가능하게 한다. 판단이 갈린 지점은 리포트에 적는다.

## 8. 종료 조건 (등록 시점부터 유효 — 결과를 본 뒤에는 고칠 수 없다)

실험 1에서 §10이 실제로 작동했다 — **1순위 지표가 예상과 반대로 나왔는데도 조건을 고치지 않고

### 8.1 재실행 사유 화이트리스트

| 사유 | 처리 |
|---|---|
| `acRunOk: false` | 그 라운드만 재실행 |
| `permission_denials` ≠ 0 | 그 라운드만 재실행 |
| 계측기 버그 | **재실행 없음.** 전수 재측정 + 사유 기록 |

**그 외 전부 금지.** 특히 이것들은 재실행 사유가 아니다 — mutationScore가 예상과 다름,
결함이 너무 쉬워/어려워 보임, 더 나은 결함이 떠오름, n이 작아 보임. **전부 리포트 한계 절로 간다.**

### 8.2 승패를 정의하지 않는다

n=3에서 유의성을 주장하지 않는다. 세 경우의 문장을 **실행 전에** 등록한다.

| 결과 | 리포트에 쓸 문장 (사전 등록) |
|---|---|
| (d) `mutationScore` > 0 | "(d)는 동결 결함 4개 중 **`M`개**를 남은 자체 테스트로 잡아냈다. (a)(b)는 테스트를 남기지 않아 0개다. 대가는 비용 `N`배다. n=3, 유의성 주장 없음." |
| (d) `mutationScore` = 0 이고 테스트는 남김 | "처치는 테스트를 남기게 했으나 **남은 테스트는 동결 결함을 하나도 잡지 못했다.** '남겼는가'와 '값을 하는가'가 다른 축이라는 관측이며, 회귀 자산 가설에 대한 음성 데이터다." |
| (d) 테스트를 안 남김 | "처치가 도달하지 않았다. 문안이 약했는지 모델이 무시했는지는 이 데이터로 갈리지 않는다." (r7 §6-⑥ — 실행 중 발생하면 멈추고 물어본다) |

**어느 경우에도 실험은 성공이다.** 산출물은 "(d)가 이겼다"가 아니라 **비교 리포트**다.
