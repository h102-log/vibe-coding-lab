# 자산 회수 리포트 — R1에서 남은 테스트는 회수되는가

**작성일**: 2026-08-02 · **실행 완료**: `exp3/FROZEN3.md` §11 기준 유효 3+3
**원자료**: `exp3/runs/*.json` · 세션 로그 `~/.claude/projects/`
**설계·동결·종료 조건**: `exp3/FROZEN3.md` · **선행**: `docs/REPORT.md`(실험 1) · `docs/REPORT2.md`(실험 2)

> 승패를 선언하지 않는다. n=3에서 유의성을 주장할 근거가 없다는 것이 `FROZEN3.md` §7.2에
> 결과를 보기 전에 등록돼 있다.

**이 실험이 메우는 공백**: 실험 2는 **"자산을 만든다"**를 증명했다(`mutationScore` 0 → 3/4).
증명하지 않은 것은 **"자산이 값을 한다"**다 — 그 3/4은 *우리가* 결함을 주입하고 *우리가* 남은
테스트를 돌려서 나온 값이다. **에이전트가 다음 라운드에 그것을 쓰는지는 데이터가 0이었다.**

**조건**: R0 산출물에 변경 요구 1건(`todo-edit`, 인라인 제목 편집)을 **새 세션**으로 투입.
`--resume`이 아닌 이유는 `FROZEN3.md` §1.1 — 같은 세션이면 에이전트가 방금 자기가 쓴 테스트를
**기억한 채** 받으므로 "회수되는가"가 아니라 "기억하는가"를 재게 된다. 새 세션이면 (b)와 (d)의
차이가 대화 내용이 아니라 **디스크에 남은 파일에만** 있다.

## 1. 1순위 지표 — `assetRun`

**정의**: R1 세션에서, **R1 시작 시점에 이미 존재하던** 자체 테스트를 1회 이상 실행했는가 (런당 0/1).
R1 프롬프트는 자체 테스트를 돌리라고 **말하지 않는다.** 완료 조건은 `test:ac`·`build` 둘뿐이라
무시해도 완료된다. **자발적 실행을 잰다.**

| 조건 | 앱 | R1 시작 자산 | 발견 경로 | 실행 커맨드 | `assetRun` |
|---|---|---|---|---|---|
| b | `b2t`·`b2tb`·`b2tc` | 없음 | — | — | **0** ×3 |
| **d** | `d` | `tests/dev/todo.check.tsx` (20) | `SPEC.md` → `vitest.dev.config.ts` → `tests/dev/` | `npm run test:dev` ×3 | **1** |
| **d** | `db` | `tests/dev/todo.spec.tsx` (28) | 〃 | `npm run test:dev` ×1 | **1** |
| **d** | `dc` | `src/todo/todo.invariant.test.tsx` (20) | **`ls -R src`의 파일명** → `SPEC.md` → 설정 | `npx vitest run --config vitest.impl.config.ts` | **1** |

**(b) 0/3 · (d) 3/3.**

`FROZEN3.md` §7.2가 이 경우에 대해 미리 등록한 문장:

> **남은 자산은 새 세션에서도 자발적으로 회수된다. 3/3이 기존 테스트를 실행했다. n=3, 유의성 주장 없음.**

### 1.1 예상이 빗나갔다 — `dc`도 회수됐다

`FROZEN3.md` §5-2는 **2/3**을 예상했다. `dc`만 `package.json`에 실행 스크립트가 없어
발견 난이도를 "높음"으로 등록했기 때문이다. **빗나갔다.**

이유는 세션 로그에 그대로 있다. `dc`의 **첫 두 툴콜**이 이것이다:

```
1  Bash  ls -la "…/exp3/dc"
2  Bash  ls -R "…/exp3/dc/src" …
```

**에이전트는 작업 시작에 디렉터리를 훑는다.** 파일이 거기 있으면 보인다 —
`todo.invariant.test.tsx`라는 이름이 자기 설명적이었고, `vitest.impl.config.ts`도 루트에 있었다.
`package.json` 스크립트는 **편의일 뿐 발견의 필요조건이 아니었다.**

> 이 관측은 처치 §4의 약점으로 지목했던 것("남겨라"만 말하고 "발견 가능하게 하라"는 안 한다)이
> **적어도 이 규모에서는 문제가 아니었다**는 뜻이다. 코드베이스가 커지면 달라질 수 있고,
> 그것은 이 설계로 측정되지 않는다(§4-5).

### 1.2 발견 경로에서 `SPEC.md`가 한 역할

3런 모두 자산에 도달하기 전에 `SPEC.md`를 읽었다. `d`는 `SPEC.md`(툴콜 14) → 설정(15) → 디렉터리(16)
순으로 갔고, `dc`는 파일 목록에서 먼저 본 뒤 `SPEC.md`(11)로 확인했다.

**SDD 산출물이 자산의 인덱스 역할을 했다.** 실험 2 §1.1에서 SPEC이 "문장은 있는데 테스트가 없다"는
약점으로 나타났던 것과 대비된다 — 같은 문서가 여기서는 자산을 잇는 다리였다.
(d)가 SDD 위에 얹힌 구조라 이 효과는 **분리되지 않는다**(§4-2).

## 2. 자산의 운명 — 생존과 성장 (2순위, 결론에 쓰지 않는다)

| 조건 | 앱 | 케이스 R0 → R1 | 단언 R0 → R1 | 어떻게 | 삭제 |
|---|---|---|---|---|---|
| b | `b2t` | — → **0** | — | `todo/__verify.test.tsx` 만들어 15/15 | **삭제** |

| **d** | `dc` | 20 → **41** | 53 → **106** | **같은 파일 확장** | 0 |

두 가지가 관측됐다.

**① (b)는 R1에서도 만들고 지웠다 — 3/3.** R0에서 이 행동의 기저율은 1/6이었는데(`REPORT2.md` §2.1)

`b2tc`는 테스트를 네 번이나 돌리고도(25/25 → 1/1 → 0/1 → 25/25) 전부 지웠다.

**② (d)는 3/3이 새 파일을 만들지 않고 기존 자산을 확장했다.** 케이스가 2배 안팎으로 늘었고
단언은 100건대가 됐다. **자산은 살아남기만 한 게 아니라 자랐다.**

## 3. 회귀와 비용

### 3.1 기존 테스트가 잡은 회귀는 0

`todo-edit`은 기존 동작을 깨뜨리지 않았다. (d) 3런의 기존 케이스(20·28·20)는 전부 통과했고,
`gateAC`는 6런 전부 8/8·`regression pass`다. **`FROZEN3.md` §5-3이 예상한 그대로다**
— 실험 1의 (a)가 변경 4건 연속 회귀 0이었으므로 미리 등록해 뒀다.

**단 하나의 자체 테스트 실패**는 `d`의 `U-68: 필터를 바꾸면 편집이 취소된다`이다:

```
× U-68 …  AssertionError: expected [ '버릴 초안', 'b' ] to deeply equal [ 'a', 'b' ]
  Tests  1 failed | 38 passed (39)     →  수정 후  40 passed (40)
```

**이것은 R1에서 새로 쓴 신규 기능 케이스이지 기존 자산이 아니다. 회귀 검출로 세지 않는다.**
"남은 테스트가 회귀를 잡는다"는 이 실험에서 **관측되지 않았다** — 잡을 회귀가 발생하지 않았기 때문이다.

### 3.2 비용 — 차이가 거의 없다

| | (b) 합계 | (d) 합계 | (d)/(b) |
|---|---|---|---|
| `total_cost_usd` | $8.6051 | $9.2084 | **1.07×** |
| `num_turns` | 120 | 125 | 1.04× |
| 벽시계 | 1,912초 | 1,959초 | 1.02× |

중앙값: cost (b) $2.6202 · (d) $2.8962 / turns 43 · 41 / 벽시계 593초 · 655초

**`FROZEN3.md` §5-4의 예상("(d)가 더 비쌀 것")은 방향만 맞고 크기가 빗나갔다.**

이 7%가 이 리포트에서 가장 중요한 숫자일 수 있다:

> **(b)는 (d)와 거의 같은 비용을 쓰고 자산을 0개 남겼다.**
> 테스트를 쓰고 돌리는 비용은 양쪽이 똑같이 지불했다 — (b)만 그 결과물을 버렸다.
> 처치 §4가 사는 것은 "테스트를 쓰게 하는 것"이 아니라 **"이미 쓴 것을 버리지 않게 하는 것"**이고,
> 그 한계 비용이 7%다.

실험 2의 관측(§3 — (d)/(b) 1.16배)과 방향이 같고 R1에서는 더 작다.

## 4. 한계

### 4.1 설계 단계에서 등록된 한계 (`FROZEN3.md` §6 전문)

1. **n=3, 단일 머신, 순서 효과 미통제.** (b) 3런 → (d) 3런 순차.
2. **변경 요구 1건뿐이다.** `todo-edit`이 기존 테스트를 안 깨뜨려 **"깨졌을 때의 대응"은 관측되지 않았다**(§3.1).
3. **`assetRun`은 "돌렸는가"이지 "값을 했는가"가 아니다.** 3/3이 돌렸지만 그 실행에서 기존 케이스는
   전부 통과했다. **회수는 확인됐고 회수의 효용은 확인되지 않았다.**
4. **(d)의 R0 산출물이 서로 다르다.** 발견 난이도가 앱마다 달랐고(§1.1), 그 차이가 결과를 가르지 않았다.
5. **규모가 작다.** `src/`가 100~300줄대다. `ls -R`로 전부 보이는 코드베이스에서 "발견 가능성"은
   문제가 되지 않는다. 큰 코드베이스에서는 달라질 수 있고 이 설계로는 영원히 측정되지 않는다.
6. **`--safe-mode`라 실사용 환경이 아니다.** 처치는 `--append-system-prompt`다.

### 4.2 실행 중 관측된 것 (조건을 고치지 않고 여기 적는다)

1. **예상 2/3이 3/3으로 빗나갔다**(§1.1). 조건·프롬프트를 바꾸지 않았다.
2. **`judge.mjs`의 `styleTouched` 오탐 1건.** `exp3/`에 `seed/`를 복사하지 않아 기준 파일이 `ABSENT`로
   읽혔다 — App.css 실제 diff는 0줄. 기준 파일 하나만 놓고 재채점해 `false` 확인(§7.1 계측기 예외, 재실행 없음).
3. **계약과 변경 요구가 직접 모순이었다.** `CONTRACT-thin.md`의 «범위 밖»에 "인라인 제목 편집"이 있다.
   실험 1은 `--resume`이라 새 지시가 컨텍스트를 덮어썼지만 새 세션에서는 둘이 동시에 주어진다.
   **계약을 고치지 않고**(동결) 프롬프트에 우선순위 한 줄을 넣어 해소했다(`FROZEN3.md` §3.2). 양쪽 동일.
4. **`exp/`·`exp2/`는 무변경이다.** 자산 38개와 선행 산출물 6개의 트리 해시를 실행 후 대조해 전부 일치.

## 5. 다음 트랙으로 넘기는 입력

### 5.1 세 실험을 한 줄로

| 실험 | 물음 | 답 |
|---|---|---|
| 1 | SDD 38줄이 첫 제출 점수를 올리나 | **아니다.** 중앙값 7 → 6, 비용 4.32× |
| 2 | "쓴 테스트를 남겨라" 4줄이 회귀 자산을 만드나 | **만든다.** `mutationScore` 0 → 3/4, 비용 +16% |
| **3** | **그 자산이 다음 라운드에 회수되나** | **된다.** 새 세션 3/3이 자발적으로 실행, 케이스 2배로 확장, 비용 +7% |

### 5.2 이 실험이 답할 수 없는 것

1. **회수의 효용.** 3/3이 돌렸지만 잡을 회귀가 없었다. **"자산이 실제로 사고를 막는가"는 여전히 데이터 0이다.**
   막으려면 회귀가 나는 변경이 필요한데, 이 과제는 4라운드 연속 회귀 0이었다(`REPORT.md` §3.1).
   **과제가 너무 쉽다는 것이 세 실험 연속으로 천장을 만들고 있다.**
2. **여러 라운드 누적.** R1 하나만 봤다. R2~R4에서 자산이 계속 자라는지, 거추장스러워져 지워지는지.
3. **큰 코드베이스에서의 발견 가능성**(§4-5).
4. **§4 단독 효과.** 여전히 SDD와 분리되지 않는다. §1.2에서 `SPEC.md`가 발견 경로로 쓰인 것이
   그 결합을 더 강하게 만든다.

### 5.3 다음 표적 — 우선순위가 바뀌었다

**세 실험이 같은 벽에 부딪혔다: 이 과제에서는 회귀가 안 난다.**
`gateAC` 8/8이 네 조건 연속, 변경 요구 4건 연속 회귀 0, 그리고 이번에 자체 테스트도 기존 케이스는 전부 통과.

> **회귀 자산의 값을 재려면 회귀가 나는 과제가 필요하다.** Todo 앱 + jsdom + 단일 라운드로는
> 더 짜낼 것이 없다. `REPORT.md` §5.2-2가 "긴 세션·큰 코드베이스가 전부 측정 범위 밖"이라고 한 것이
> 이제 **가장 비싼 공백**이다.

따라서 다음은 실험이 아니라 **실사용**을 권한다 — 42줄(SDD 38 + §4 4)을 켜고 실제 프로젝트를
진행하며 자산이 자라고 회수되는지 관찰하는 것. 측정이 아니라 일화가 되지만,
**네 번째 Todo 앱 실험의 한계 수익은 이제 명백히 낮다.**

실험을 더 한다면 `REPORT2.md` §6.3의 문안 A/B("1·2번 문장을 전부 테스트로 옮겨라")가 남아 있다 —
가장 싸고($8) 측정 장치를 그대로 쓰며, 실험 2의 유일한 음성 관측(`F-08` 3/3 놓침)을 직접 겨눈다.

- **실험이 답할 수 없는 것부터 시작한다.**
