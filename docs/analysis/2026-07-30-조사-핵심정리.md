## 0. 다섯 줄 결론

1. **안 만드는 게 이긴다.** harprame이 Python 533줄로 만든 하네스의 상당 부분을 Claude Code가 이미 네이티브로 준다 — `/goal` 조건, `Stop` 훅, 검증 서브에이전트. 출발점은 "외부 오케스트레이터를 만든다"가 아니라 **"네이티브로 안 되는 게 뭔지 먼저 확인한다"**.
2. **배포 형태가 지침 주입 설계를 규정한다.** 플러그인은 CLAUDE.md·rules를 배포할 수 없다. 이 제약이 다른 모든 선택보다 앞선다.
3. **팀 오케스트레이터는 선행 사례가 만들어서 폐기했다.** MoAI-ADK Mode 3(agent-team) = RETIRED. 코딩 작업 기본값은 순차 서브에이전트.
4. **TDD는 "지침에 적기"가 아니라 "반증 가능하게 만들기"**가 설계의 본체다. RED 실패 출력 원문 제출 의무 + Red-Check.
5. **착수 전 정보의 절반이 아직 공백이다.** 특히 웹 도메인의 결정론적 AC 상한과 효과 측정 방법.

## 2. 두 벤치마크 대조

|  | harprame | MoAI-ADK |
|---|---|---|
| 실체 | 6일 된 개인 설계 실험 | 프로덕션 프레임워크 |
| 규모 | 28 파일 / Python 533줄 | 6,656 파일 / Go 바이너리 |
| **강제 위치** | **Claude 밖** — 결정론적 외부 하네스 | **Claude 안** — 에이전트 팀 + 정책 |
| **판정 주체** | 비-LLM (exit code) | 감사 에이전트의 확률적 채점 |
| 서브에이전트 | 커스텀 정의 **없음** (내장 Explore만) | 11개 카탈로그 (+ 프레임워크 정비용 10개 별도) |
| 확장 자산 | commands 2 + settings.json 훅 | agents 20 · commands 21 · skills 37~38 · hooks 39 · rules 67 |

**harprame의 실행 구조** — Claude Code의 subagent/Task를 쓰지 않고 `claude -p --dangerously-skip-permissions --output-format json <프롬프트>`를 **스텝마다 새 프로세스로** 호출한다(`--resume` 없음, timeout 1800s). 즉 컨텍스트 격리를 서브에이전트가 아니라 **"세션 분할 + 문서 자기완결성"**으로 구현. 상태는 모델 컨텍스트가 아니라 `phases/**/index.json` 파일시스템에 외부화하고, 타임스탬프·status는 하네스가 쓰고 **에이전트는 `summary`만** 채우게 프롬프트로 금지한다.

**MoAI-ADK의 파이프라인** — `/moai plan` → `/moai run SPEC-ID` → `/moai sync SPEC-ID`. 핵심 설계는 **"생성자와 검증자의 분리"**이고 파일 수준에서 강제된다: `sync-auditor`는 Write/Edit 도구가 없고 `permissionMode: plan`. 채점 Functionality 40% / Security 25% / Craft 20% / Consistency 15%, **Functionality·Security 중 하나라도 실패하면 총점 무관 FAIL.**

> ⚠️ **"게이트"라는 같은 단어의 강도 차이.** MoAI의 TRUST 5와 방법론 라우팅은 문서에 **"하드 차단 훅이 아니다"**라고 적혀 있다(정책 + 에이전트 판단 + 수렴 루프). harprame은 exit code로 실제로 프로세스를 멈춘다. **"강제"를 주장하려면 어느 층에서 무엇이 실제로 프로세스를 멈추는지 코드로 확인해야 한다.**

## 3. 훔칠 값어치가 있는 장치

### 3.1 harprame — 개념 5개

- **판정 주체 분리** — step 완료는 하네스가 `verification_cmd`의 exit code로 정한다. 프롬프트에 *"네가 무엇을 써넣든 하네스가 무시하고 검증 결과로 덮어쓴다"*고 못박음.
- **Red-Check** — 코드 작성 *전에* AC를 돌린다. 통과하면(exit 0) `assert True` 류 가짜 AC이므로 **계획을 거부하고 `sys.exit(2)`**. 근거: *"결과를 본 뒤에 기준을 정하면, 기준이 결과에 맞춰 휜다."*
- **Sign-off** — 실행 전 1회 사람이 AC 묶음 y/N 승인. 비용 논거: *"실행 후 코드 리뷰(수백 줄)보다 실행 전 AC 리뷰(몇 줄)가 압도적으로 싸다."*
- **Gate vs Advisory 분리** — 판별 기준 **딱 하나: "같은 입력에 항상 같은 답이 나오는가."** 결정론적 검사만 진행 차단, LLM 정성 심사는 1~5점만 기록하고 **절대 차단하지 않는다.**
- **실패 지문(fingerprint)** — 검증 출력에서 시간 노이즈를 정규식으로 지운 뒤 직전 실패와 같으면 재시도 중단. *"같은 실패 반복 = 주사위를 다시 굴리는 것. 이건 실행 실패가 아니라 계획이 틀렸다는 신호."*

**자기심판이 나쁜 이유 (인용 가치 최상):** 게으름이나 거짓말이 아니다. **코드를 쓴 이해와 그 코드를 검증하는 이해가 같은 이해이기 때문이다.** 이해가 틀렸으면 코드와 판정이 *같은 방향으로* 틀리고, 안에서 보면 모순이 안 보인다. 상관오류이지 부주의가 아니므로 **더 성실한 에이전트를 써도 안 풀린다.** → 해법은 "더 똑똑한 심판"이 아니라 **판정 주체를 실행 주체 밖으로 빼는 것**.
실제로 데인 사건: API 조회 step에서 `WHERE`가 항상 거짓 → 호출은 200, 기록은 "성공", 실제 반환 0건. **기계적 성공(호출됨) ≠ 의미적 성공(원하는 값).**

**반면교사** — harprame의 가드레일 주입은 `docs/*.md` 6개를 **모든 step에 무조건 전량** 싣는다. 페이즈별 선택 로딩이 코드 어디에도 없다. *우리가 피하려는 바로 그 문제를 안고 있다.*

### 3.2 MoAI-ADK — 구조 4개

- **TDD Anti-Cheat 불변식 2개** (가장 훔칠 값어치 큼)
  - **i.** 구현 전에 캡처한 **RED 실패 출력의 원문**이 완료 증거로 필수. 못 내놓으면 RED를 건너뛴 것이므로 clean 보고 불가.
  - **ii.** 실패 테스트보다 먼저 쓰인 구현 코드는 **삭제하고 테스트부터 다시 유도**한다.
  - 이유가 스킬 본문에 적혀 있다 — 이전엔 RED 증거가 없어도 자기검증 매트릭스를 다 통과할 수 있었고, 그러면 **완료 보고서만으로 test-first와 test-after를 구별할 수 없었다.**
- **감사자 편향 방지 5장치** — M1 컨텍스트 격리(작성자의 추론·초안·대화 이력 차단, 최종 산출물만) / M2 적대적 태도 / M3 루브릭 고정 / M4 증거 인용 / M5 must-pass 방화벽. 감사자 파일에 *"이 역할은 병합되어서는 안 된다"*고 명문화.
- **커버리지 기준 방법론 분기** — 신규 또는 커버리지 10% 초과 → TDD(RED→GREEN→REFACTOR), 10% 미만 레거시 → DDD(ANALYZE→PRESERVE→IMPROVE, characterization test). **브라운필드를 TDD로 밀어붙이지 않는다.** 설정은 `quality.yaml`.
- **임계값 외부화** — 커버리지 85% 같은 수치를 하드코딩 않고 설정 파일로. + 제품용/프레임워크 정비용 에이전트를 **디렉터리로 분리**(`agents/moai/` vs `agents/harness/`).

부수 패턴: **`Common Rationalizations` 표**(에이전트가 댈 변명 ↔ 현실. 예: "구현이 돌아가면 테스트를 추가하겠다" → "사후 테스트는 코드가 *하는 일*을 검증할 뿐 *해야 할 일*을 검증하지 않는다"), **`Red Flags`**(테스트와 구현이 같은 커밋 / 새 테스트가 첫 실행에 전부 통과 / 머지 후 "add tests" 커밋 / 신규 기능 커밋에서 커버리지 하락), **DAMP over DRY**, **Beyoncé Rule**.

### 3.3 SDD — 성숙도 3단계 (두 출처 일치)

Böckeler(martinfowler.com) ↔ MoAI `moai-workflow-spec` 스킬이 그대로 구현:

| 단계 | 의미 | 유지보수 |
|---|---|---|
| `spec-first` | 구현 후 스펙 폐기 | 없음 |
| `spec-anchored` | 구현과 함께 유지 | 분기별 리뷰 |
| `spec-as-source` | 스펙이 SSOT, 사람은 스펙만 수정 | 변경 시 구현 재생성 |

전이 규칙까지 있다(production-critical → anchored, 컴플라이언스/재생성 필요 → as-source, **다운그레이드는 명시적 정당화 필요**). 스펙 표류에 "전부 유지한다"는 거짓말 대신 **명시적 3단계 선택**으로 답한 것 — 조사 전체에서 가장 정직한 해법.

**MoAI의 구체 자산:** 3파일 강제 `{spec.md, plan.md, acceptance.md}` · GEARS 표기법(EARS의 `IF/THEN` 폐기, `moai spec lint --strict`가 잔존 시 오류) · 12개 필수 frontmatter 필드 + status enum 8종 · **`[NEEDS CLARIFICATION]` 마커**(spec.md·acceptance.md 금지, 남아 있으면 plan-auditor가 게이트로 잡고 `AskUserQuestion`으로 해소해야 킥오프) · **`.moai/specs/`에 안 들어가는 것을 표로 명시**(*"리포트는 존재하는 것을 분석 → reports/. SPEC은 만들 것을 정의 → specs/."*) · Out of Scope 섹션 강제.

### 3.4 harprame step 설계 원칙 7개 (그대로 채택 가치)

1. **Scope 최소화** — 한 step에 한 레이어/모듈. 여러 모듈이면 쪼갠다.
2. **자기완결성** — *"각 step 파일은 독립된 Claude 세션에서 실행된다. '이전 대화에서 논의한 바와 같이' 같은 외부 참조는 금지한다."* → **페이즈 설계 난이도를 전부 결정하는 제약.**
3. **사전 준비 강제** — 읽을 파일과 선행 산출물 경로를 앞부분에 명시.
4. **시그니처 수준 지시** — 인터페이스만, 내부는 재량. 단 멱등성·보안·데이터 무결성은 명시.
5. **AC는 실행 가능한 커맨드** — "~가 동작해야 한다" 금지, `npm run build && npm test` 형태.
6. **주의는 구체적으로** — "조심해라" 대신 **"X를 하지 마라. 이유: Y"**.
7. **네이밍** — kebab-case slug.

> 이 중 2번은 Claude Code 공식 베스트 프랙티스와 **정확히 같은 말**이다: *"좋은 명세는 자기완결적일 것 — 관련 파일과 인터페이스를 이름으로 지목하고, 범위 밖을 밝히고, 기능이 동작함을 증명하는 종단 검증 단계로 끝난다."* 공식 문서에서 나온다는 게 중요하다.

## 4. 플랫폼 제약 — 여기가 설계를 규정한다

### 4.1 로딩 시점 = 컨텍스트 비용 = 선택 기준

| 메커니즘 | 로드 시점 | 컨텍스트 비용 | 쓸 곳 |
|---|---|---|---|
| **CLAUDE.md** | 세션 시작, 전량 | 매 요청 (가장 비쌈) | 항상 참인 규칙만. **200줄 이하** |
| **`.claude/rules/` + `paths`** | 매칭 파일을 다룰 때 | 해당 시점만 | 파일 종류별 규약 |
| **스킬** | description 상시, 본문은 호출 시 | 낮음 | 페이즈 절차, 긴 참조 자료 |
| **서브에이전트** | 완전 격리, 요약만 반환 | 리드는 0, **총량은 증가** | 탐색·조사·독립 검증 |
| **훅** | 이벤트 발생 시 | **0** (출력 없으면) | 반드시 지켜야 할 불변식 |

**함정 4개**
- **`paths` 없는 rules는 절약이 0이다** — CLAUDE.md와 같은 우선순위로 시작 시 로드. 반대로 path-scoped rules는 `/compact` 후 "매칭 파일을 다시 읽을 때까지 유실"되는 반면 루트 CLAUDE.md는 디스크에서 재주입된다. **오프로드 = 컨텍스트를 아끼는 대신 압축 후 규칙 유실을 감수하는 선택.**
- **스킬 description도 공짜가 아니다** — description+when_to_use 합산 1,536자 컷, 전체 목록에 컨텍스트 1% 예산. 넘치면 가장 적게 쓴 스킬부터 드롭. `/context`로 실측 가능. `disable-model-invocation: true`로 0을 만들 수 있으나 **Claude가 스스로 못 부른다**.
- **서브에이전트의 `skills:` 필드는 전량 프리로드다** — 많이 매달면 격리로 아낀 걸 그대로 되돌려준다.
- **PreToolUse matcher는 툴 이름만 본다** — `Edit|Write`만 걸면 `Bash`로 `sed -i` / `cat > impl.ts` 우회 시 훅이 아예 발화하지 않는다. `Bash`까지 매칭하고 `if` 필드로 인자를 검사해야 한다.

**훅이 유일한 진짜 강제 수단** (공식 문서 표현): *"CLAUDE.md나 스킬에 적은 '절대 .env를 수정하지 마라'는 **요청이지 보장이 아니다.** 규칙이 매번 성립해야 한다면 프롬프트가 아니라 훅으로 만들어라."*

### 4.2 플러그인 배포를 고르면 잃는 것

- **플러그인 루트의 `CLAUDE.md`는 프로젝트 컨텍스트로 로드되지 않는다.** 플러그인 컴포넌트에 memory/instructions/rules가 아예 없고 `.claude/rules/*.md`도 배포 불가.
  → **`.claude` 템플릿 리포로 설계한 워크플로는 플러그인 배포로 그대로 이식되지 않는다.** (MoAI가 rules 67개를 갖고도 Go 인스톨러를 쓰는 이유일 가능성 — 미확인)
  → 스킬은 lazy, CLAUDE.md는 eager. **항상 켜져 있어야 하는 규칙은 스킬로 등가 대체되지 않고 `SessionStart` 훅이 필요하다.**
- 플러그인이 배포하는 subagent frontmatter는 보안상 `hooks`·`mcpServers`·**`permissionMode`를 무시**한다. → MoAI식 "감사자는 쓰기 권한 없음"의 파일 수준 강제가 **플러그인 경로로는 안 된다.**
- `permissions.allow`는 **세션 전체** 적용 → "특정 에이전트만 자동승인" 불가.
- **우회로:** `hooks/hooks.json`은 배포 가능하고 `SubagentStart`/`SubagentStop` 매처가 `^my-plugin:db-agent$` 스코프 식별자를 받는다 → **에이전트별 훅 강제는 사실상 구현 가능.**
- 배포 자체는 가볍다 — `plugin.json`은 **선택**이고 필수 필드는 `name` 하나. 마켓플레이스는 루트에 `.claude-plugin/marketplace.json` 하나 두고 push하면 끝. ⚠️ **`version` 생략 시 커밋 SHA로 대체돼 모든 커밋이 새 버전 취급.**

### 4.3 훅으로 게이트를 만들 때의 함정

- 훅 타입 5종: `command` / `http` / `mcp_tool` / `prompt` / `agent`. **`agent` 훅은 문서에 `experimental and may change` 명시** — 핵심 게이트로 쓰면 위험.
- 차단 가능 이벤트는 plugins-reference 표의 2종이 아니라 hooks 문서 기준 **약 15종**. **TDD 게이트엔 `PreToolUse`보다 `TaskCompleted` 차단이 더 적합할 수 있다.**
- 🔴 **`--dangerously-skip-permissions`(bypass) 하에서 `PreToolUse` 훅이 비동기 실행돼 차단에 실패한다는 버그 보고** — anthropics/claude-code#20946 (관련 #40117, #24327).
  **그리고 이게 harprame 자신의 구성과 정면 충돌한다** — bypass로 에이전트를 호출하면서 PreToolUse 훅으로 `rm -rf`를 막으려 한다. 동작 여부 미검증. **이 패턴을 그대로 베끼면 안 된다.**
- Stop 훅에도 상한이 있다 — **8회 연속 차단되면 Claude Code가 훅을 무시하고 턴을 끝낸다.**
- **TDD 강제는 두 갈래로 나눠야 한다.** ① "테스트 파일 수정 금지" = 경로 기반 정적 판정, 훅의 정석 용례. ② "테스트 없이 구현 금지" = 무엇이 구현이고 대응 실패 테스트가 있는지 판정해야 해서, 훅 스크립트 안에 판단 로직을 직접 넣지 않으면 결정론적 게이트가 안 된다.
- 참고: **Claude Code 공식 문서에 TDD 언급은 아예 없다.** 이 영역은 훅 사양으로부터의 응용이지 검증된 권고가 아니다.

## 5. 확인된 것 vs 논쟁 중인 것

### 5.1 컨텍스트 분할 — 방향은 정당, 크기는 못 믿는다

**정당한 쪽:**
- Chroma LongMemEval — 필요한 부분만 담은 **약 300토큰 프롬프트가 전체를 담은 약 113,000토큰을 모든 모델에서 이겼다.**
- EMNLP 2025 Findings "Context Length Alone Hurts LLM Performance Despite Perfect Retrieval" — **완벽히 검색해내도 입력이 길면 13.9~85% 하락**, 무관 토큰을 공백으로 바꾸거나 어텐션 마스킹해도 저하가 남는다. **길이 자체가 독립 변수.**
- NoLiMa(ICML 2025) 유효 길이(베이스 85% 유지 최대 길이): Claude 3.5 Sonnet 200K→**4K**, GPT-4o 128K→8K, Gemini 1.5 Pro 2M→**2K**.
- MoAI 실무 수치: 토큰 예산 **Plan 30% / Run 60% / Sync 10%**, 핸드오프 임계가 **모델별**(1M 창은 50%, 200K/256K 창은 90% — 큰 창일수록 퍼센트를 **낮게** 잡는 역설), 95% 초과 시 무조건 `/clear`. **Verification Economy**(검증 출력은 디스크로, 컨텍스트엔 exit code + 최대 50줄 tail), **Token Circuit Breaker**(하드 리밋에서 중단 후 붙여넣기 가능한 resume 메시지 발급).

**못 믿는 쪽 / 반대 근거:**
- 🔴 인용 가능한 정량 수치가 **전부 2025년 상반기 이전 모델 기준**. Opus 5·GPT-5·Gemini 3의 유효 길이는 없다. NoLiMa 확장표에서 32K 미달 비율이 11/13 → 약 10/22로 개선 중. **방향성은 믿되 크기를 그대로 투사하지 말 것.**
- 🔴 arXiv:2606.20512 — **LLM 생성 컨텍스트/지침 파일이 SWE-bench Lite resolve rate를 오히려 떨어뜨린다**(에이전트가 지시를 문자 그대로 따르다 역효과). 단 3표 검증 미통과, 검증자의 부수 발견 → **원문 재확인 없이 인용 금지.**
- **progressive disclosure의 정확한 정의는 "문서를 잘게 쪼개 미리 다 읽히는 것"이 아니다.** Anthropic 정의는 "메타데이터/참조만 남기고 에이전트가 탐색으로 발견하게 하는 것". 부정되는 건 **쪼갠 것을 전부 미리 읽히는 것**뿐 — Anthropic 자신도 CLAUDE.md는 통째로 사전 로드한다. 대가도 명시돼 있다: *"런타임 탐색은 사전 계산 조회보다 느리다"*, *"막다른 길을 쫓다 컨텍스트를 낭비할 수 있다."* **페이즈를 너무 잘게 쪼개면 탐색 오버헤드가 절약분을 잠식하는데, 손익분기점 수치는 어디에도 없다.**

### 5.2 멀티에이전트 — 이득은 토큰 절감이 아니다

**서브에이전트의 이득은 토큰 절감이 아니라 리드 에이전트의 윈도우 격리다.** 총비용은 오히려 는다 — Anthropic 자신의 수치로 **에이전트는 채팅 대비 약 4배, 멀티에이전트는 약 15배.**

Anthropic 직접 인용: *"most coding tasks involve fewer truly parallelizable tasks than research, and LLM agents are not yet great at coordinating and delegating to other agents in real time."*

Cognition은 더 세게 반대한다 — "컨텍스트를 공유하라, 개별 메시지가 아니라 전체 트레이스를". 주목할 점: **Anthropic이 "이득"이라 부르는 압축(전체 트레이스 → 1~2K 요약)이 Cognition이 지목하는 1순위 실패 모드 그 자체**다.

**MoAI-ADK는 만들어서 폐기했다** — Mode 3(agent-team) **RETIRED**, `--mode team` 강제 시 `MODE_TEAM_UNAVAILABLE` 센티넬 + 폴백:

| 모드 | 조건 | 동시성 |
|---|---|---|
| 1 `trivial` | 오타·한 줄 | 직접 실행 |
| 2 `background` | 읽기 전용 비동기 분석 | 1 |
| ~~3 `agent-team`~~ | **폐기 (tombstone)** | — |
| 4 `parallel` | **리서치** 성격 AND ≥3 도메인 | 3~5 |
| 5 `sub-agent` | **기본 폴백 — 코딩 작업 전부** | 순차 1 |
| 6 `workflow` | ≥~30파일 AND **단일 균일 변환 규칙** AND 파일 간 의존 없음 | 최대 16 |

안티패턴 목록에 **"코딩 중심 작업에 Mode 4/6 선택"**이 명시. 운영 패턴으로 훔칠 것: 모드 선택 근거를 **grep 가능한 형식**으로 `progress.md`에 기록 / **임계값 ±1 경계에서는 항상 더 단순한 모드로** 떨어뜨림 / Mode 6 에이전트는 사용자에게 직접 묻지 않고 **구조화된 blocker report**를 반환하면 오케스트레이터가 `AskUserQuestion` 후 재위임(비대칭 경계).

**판단 기준:**

| 쓸 것 | 쓰지 말 것 |
|---|---|
| 읽기 전용 탐색·조사 | 같은 파일을 편집하는 병렬 구현 |
| 요약해 넘겨도 손실이 적은 작업 | 결정이 서로 얽혀 전체 맥락이 필요한 작업 |
| 독립 검증·리뷰(신선한 컨텍스트가 이득) | 작업량이 적어 15배 비용이 아까운 작업 |

병렬 편집이 꼭 필요하면 서브에이전트가 아니라 **git worktree로 세션을 물리적으로 분리**하는 쪽이 공식 권고.

⚠️ 독립 리뷰에도 경고가 붙는다 — *"결함을 찾으라고 지시받은 리뷰어는 작업이 멀쩡해도 대개 뭔가를 보고한다. 모든 지적을 쫓으면 과도한 추상화와 방어 코드로 이어진다."* → 리뷰어 범위를 **"정확성이나 명시된 요구사항에 영향을 주는 것만"**으로 좁힐 것.

### 5.3 웹 도메인 — 양쪽 다 비어 있다

- harprame은 웹 타깃이 맞다(Next.js 15 / TS strict / Tailwind 플레이스홀더 템플릿, 기본 AC가 `npm run build && npm test`). **하지만 골격뿐이고 패턴 자산은 없다.**
- MoAI의 `moai-domain-frontend`는 **참조 카드**다 — `allowed-tools: Read, Grep, Glob`으로 **코드를 쓰지 않고 지식만 주입.** 인증·CRUD·결제·SEO의 실행 가능한 스캐폴드가 아니다.
- **→ "웹사이트 전형 패턴"은 어느 쪽도 풀지 않았다.** 차별점이 될 수 있는 동시에 근거가 가장 없는 영역.

**있는 것 두 개는 쓸 만하다:**
- **시각적 검증 루프**(공식 베스트 프랙티스) — *"make the dashboard look better"*(나쁨) → *"[스크린샷] 이 디자인을 구현해라. 결과를 스크린샷 찍어 원본과 비교하고, 차이점을 나열하고 고쳐라."*(좋음). **시각적 목표물을 주고 스스로 비교·수정하게 하는 것**이 핵심.
- **"AI가 만든 티" 안티패턴 금지 목록**(harprame `UI_GUIDE.md`) — glassmorphism `backdrop-filter: blur()`, 그라디언트 텍스트, 네온 글로우, 보라/인디고 브랜딩, 균일한 둥근 모서리, 배경의 흐릿한 그라디언트 오브. + MoAI `moai-ref-ui-polish`의 정밀 규칙(동심원 반경 `outer = inner + padding`, 진입 `ease-out`, 상태 변화는 keyframes 아닌 중단 가능한 `transition`, `tabular-nums`, 히트영역 44×44px, **`transition: all` 금지**). 전제: *"개입 전에 기존 디자인 시스템을 먼저 파악하라. 폴리시 수정을 위해 두 번째 스타일링 시스템을 도입하지 마라."*

## 6. 미해결 5개 (누구도 답을 모름)

1. **훅 기반 하드 게이트는 bypass/자동승인 모드에서 실제로 신뢰 가능한가?** → **최소 재현 테스트를 직접 돌려야 게이트 설계 전체가 확정된다.** (이거 하나가 가장 값싸고 가장 크게 좌우한다)
2. **AC 작성 주체와 코드 작성 주체를 분리하면 실제로 테스트 조작·과적합이 줄어드는가?** harprame 원저자가 미해결로 명시 — *"'분리하면 AC 품질이 오른다'는 가정이 검증되지 않았다. 실험 없이 구현하면 비싼 추측이다."*
3. **웹 도메인에서 결정론적 AC를 어디까지 만들 수 있는가?** 인증·CRUD·폼은 Playwright/vitest exit code로 Gate 가능. **레이아웃·반응형·접근성·SEO 메타·결제 플로는 어디까지 Gate고 어디부터 Advisory인가.**
4. **멀티에이전트 팀이 웹 CRUD류에서 "단일 에이전트 + 페이즈 분할 + 세션 리셋"보다 실제로 이득인가?** 이 답이 **팀 오케스트레이터 채택 여부와 배포 형태 선택을 동시에 결정한다.**
5. **MoAI-ADK가 npm → Go 단일 바이너리로 전환한 이유는?** 릴리스 노트에서 확인 가능하지만 미확인. **배포 형태 선택에 직접적인 교훈.**

**추가 공백** — 현행 모델의 유효 길이 / 페이즈 분할의 최적 입도 손익분기점 / "테스트 없이 구현 금지"를 훅으로 구현한 검증된 레시피 / 에이전트 테스트 조작의 실제 발생률 / **브라우저 MCP의 컨텍스트 비용**(컨텍스트 절약 설계와 정면 충돌 가능 — 실측 필요) / SDD 오버헤드 손익분기점 / 선행 프레임워크 지형(spec-kit·BMAD·Agent-OS·Task Master) / 운영 실무(버전 마이그레이션, 충돌 처리, 온보딩) / **프레임워크 효과 측정 방법**.

## 7. 권고 — 단, 두 문서가 여기서 갈린다

> ⚠️ **원본 간 결론 충돌.** `RESEARCH-2026-07-30.md`는 *"harprame 규모(28파일)에서 시작하라"*로 끝나고, `vibe-coding-framework-research.md`는 한 발 더 나가 *"harprame처럼 외부 러너를 만들지 마라, 네이티브로 안 되는 걸 먼저 확인하라"*고 한다. **후자가 더 강하고, 근거(공식 베스트 프랙티스 문서)도 더 단단하다.** 정리자 판단으로는 후자를 채택하고 전자를 그 안의 규모 기준으로 쓰는 게 맞다.

1. **네이티브 먼저.** `/goal` 조건 하나 + 스킬 두세 개 + 훅 하나로 최소 버전을 세워 실제 웹 프로젝트에 써보고, **아쉬운 지점부터** 채운다. harprame이 커밋 23개 만에 만난 벽들(부분 성공 롤백, 커밋 범위, 실패 아티팩트 보존)이 전부 **돌려봐야 보이는 것들**이었다.
2. **규모는 harprame 쪽.** 28 vs 6,656 파일. MoAI의 rules 67개·hooks 39개는 **축적의 결과이지 시작점이 아니다.** 처음부터 흉내내면 유지보수만 남는다.
3. **팀 오케스트레이터는 마지막에.** 선행 사례가 만들어서 폐기했다. Mode 5(순차) 하나로 시작.

7. **스펙 작성 규율로 harprame `requirements.md` 형식을 채택.** 모든 항목에 `근거(실측 출처) / 없으면 뭐가 깨지나 / 비용(몇 줄)`을 강제하고 4구역으로 나눈다:
   - **A. 이미 검증된 것** — 그대로 가져간다 (비용 0줄)
   - **B. 실측이 요구한 것** — 근거가 실행 기록에 있다
   - **C. 근거가 부족한 것** — **넣기 전에 실험한다.** *"여기 있는 항목을 근거 없이 구현하면 그게 곧 추측성 설계다"*
   - **D. 알고 빼는 것** — *"없다는 걸 알고 뺀 것과 모르고 빠진 것은 다르다"*

   원저자가 규칙까지 적어놨다: **"출처를 못 다는 항목은 요구사항이 아니라 취향이다."**

## 8. 인용 금지 / 주의 목록

**반증된 주장 6건 — 최종 설계 문서에서 사실로 되살리지 말 것.** 대부분 "사실이 틀렸다"가 아니라 **"부재를 과단정했다"**로 떨어졌다.

- ❌ "harprame은 subagent·Skill을 쓰지 않는다(부재 확인)" → `harness.md`가 내장 Explore 병렬 사용을 명시하고 settings.json에 훅이 있다. 정확히는 **"커스텀 서브에이전트 정의 파일과 skills 디렉터리가 없다."**
- ❌ "harprame 루트는 6개 항목뿐" → LICENSE·README 부재는 맞지만 나머지 단정이 과했다.
- ❌ "검증 로직의 비-LLM화가 1차 원칙" → Advisory는 명시적 예외이고, `execute.py`가 정성 리뷰에서 `claude -p`를 직접 호출한다. 정확히는 **"차단성 게이트에는 LLM을 쓰지 않는다."**
- ❌ "AC 동결 = 파일 권한 수준의 결정론적 제약" → 현재는 **프롬프트 지시뿐**, 해시 대조는 미구현·후순위(R2가 우선순위에서 빠졌다).
- ❌ "`harness.md`에 TDD 강제 장치 없음" → Red-Check가 `execute.py`에 있다. **단 RED→GREEN→REFACTOR 강제는 실제로 없다.**

**기타 주의:**
- harprame은 1차 근거는 강하지만 **"검증된 관행"의 근거로는 쓸 수 없다** — `phases/` 하위가 `0-smoke`, `1-fail` 둘뿐, 3자 언급 0건, 리포 내부에 문서 드리프트(`harness.md`↔`execute.py`가 status 기록 주체에서 충돌 = 원저자가 R8로 인지).
- MoAI-ADK는 버전마다 에이전트 개수가 **11/24/28로 급변**(제품용 10 + 내장 Explore = "11", 프레임워크 정비용 10을 더하면 "24" 계열). **수치 인용 시 SHA 고정 필수.**
- arXiv:2606.27045(Spec Growth Engine — Intent/Evidence Graph, Spine) — **미심사 단독저자 프리프린트, 경험적 평가 전무, 자사 홍보 Related Work.** 아이디어로만. 이 논문의 **Kiro "스펙 폐기" 분류는 공식 문서와 상충 → 사실로 인용 금지.**
- arXiv:2606.20512(컨텍스트 축소가 성능을 떨어뜨림) — 3표 검증 미통과 부수 발견. **원문 재확인 없이 인용 금지.**
- arXiv:2307.03172(Lost in the Middle)의 **U자 곡선 주장은 이번 검증에서 기각** — 인용 비권장.
- 원본에서 **검증 기각된 목록**(직접 확인 필요): MoAI의 3단계+15명령, spec-kit의 5+4 커맨드, OpenSpec 디렉터리 구조, Kiro 3파일 구조.
