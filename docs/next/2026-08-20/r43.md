# r43 — KF1 라운드 3: 게이트 델타 분기 (델타 루프가 자동으로 돈다)

계획서 `plankf1gate.md` 집행. `plankf1delta.md` §5 WBS의 **마지막 라운드**다. R1(r39)이 검사기를,
R2(r42)가 병합기를 냈지만 `merge`는 사람이 쳤고, 그러면 델타 루프의 값(«커맨드 1회 외에 중단이
없다» — 계획서 §7 ②)이 성립하지 않는다. 이 라운드로 **KF1이 끝났다**.

## 2. 설계에서 값을 한 것 3가지

- **재진입 가드를 «차단 전용»으로 내렸다.** 기존 `stop`은 첫 줄이 `if (stop_hook_active) return`
  이었다. 그대로 두면 «위반으로 1회 차단 → 대조 채움 → 재정지»라는 **정상 흐름에서 병합이 영영
  안 일어난다**. 병합은 차단이 아니므로 재진입에서도 수행하고, 반복 차단형 무한 루프는 그대로
  막힌다. G20(재진입+위반 → 병합 안 됨)과 G21(재진입+정상 → 병합됨)이 이 한 쌍을 고정한다.
- **`decide()` 반환을 객체로 바꿨다**(단계 1, 독립 커밋). «메시지는 내되 exit 0»(병합 실패
  재진입)과 «차단이 아닌 로그»(병합 성공)를 문자열 반환으로는 표현할 수 없다. 기존 경로 전체를
  건드리는 유일한 변경이라 델타 로직과 섞지 않고 따로 커밋했다 — 10건이 깨졌을 때 원인이 둘로
  갈리지 않게.
- **SRC 필터가 델타 검사보다 먼저다.** 순서가 반대면 델타 자신을 쓰는 Write(`.md`)가 자기
  검사에 막힌다. G15가 이것만 본다.

## 3. 계획서에서 바꾼 것 1건 (착수 전 사용자 확정)

**G22·G23의 병합 실패 재료를 «SPEC.md 자리를 디렉터리로 점유»에서 «대조 절 이름이 다른 델타»로
바꿨다.** 계획서 §8-4 자신이 «Windows에서 기대대로 실패하는지 미확인»이라 적어둔 자리다.

바꾼 재료는 §4가 실측해둔 경로다 — `## 대조`를 `## 검증`으로만 바꾸면 D4는 절 이름을 보지
않으므로 `verify`가 통과하고, `mergeDelta`는 `## 대조`에서만 행을 읽으므로 대조 행이 0이 되어
결과가 C4 0→1이 되고 병합이 스스로 거부된다. OS·권한에 무관하게 결정론적이고, M10과 재료를
공유한다. **대가**: 파일시스템 쓰기 실패(EPERM·EISDIR) 경로는 selftest가 안 덮는다. 두 케이스가
재려던 것은 «초회 exit 2 / 재진입 exit 0» 분기지 실패의 **종류**가 아니므로 손실은 없다.

부수로 계획서 §3-5가 말하지 않은 것 하나를 정했다: **`mergeDelta`의 경고는 성공 로그에만 싣고
stderr로 내지 않는다**(§9 선택 대기 2번의 기본값을 이 라운드에서 뒤집지 않는다).

## 4. R2에서 넘어온 미비 1건을 닫았다

«대조 절 이름이 다르면 verify는 통과하고 merge가 실패한다» — 안전망은 제대로 걸리지만 **메시지가
원인을 짚지 못했다**. `mergeDelta`가 «ADDED·MODIFIED가 있는데 대조 행이 0»일 때 경고 1줄을
내게 했고, 그 경고를 **throw 메시지에도 꼬리로 붙였다**. 안 붙이면 throw 경로에서 `W`가 통째로
사라져 진단이 남지 않는다. rows 0이 정상인 델타(REMOVED만 있는 것)가 있으므로 조건에
`added.length || modified.length`를 넣었다 — 위양성 방지.

## 5. 손검증 (실물 훅 이벤트 1회)

스크래치에 SPEC.md(S1·S2·I3·U1) + 델타(ADDED S4·I5·U6행 / MODIFIED S2 / REMOVED U1)를 두고
`pre`와 `stop`에 실제 훅 JSON을 stdin으로 먹였다. pre exit 0 → stop exit 0 → 델타 삭제 →
로그 `{"mode":"merge","added":3,"modified":1,"removed":1,"coldstart":false}`.

병합된 SPEC.md를 눈으로 읽어 확인한 것: S2가 §1 제자리에서 교체(옛 문장 부재) · S4가 §1 끝에 ·
I5가 **§2.2에**(I 접두어 앵커) · U1 행과 재확인 줄이 함께 소멸 · U6이 미확정표와 §3.2 양쪽에 ·
대조표의 S2 위치가 20→31로 갱신 · 파일 끝 개행 유지. 병합 후 `spec-verify`는 C2 1건인데
**그건 병합 전에도 있던 것**이다(원본에 점검표가 없었다) — «위반 수 증가 없음» 조건이 의도대로 읽혔다.

**환경 함정 1건 재확인**: 훅 이벤트의 `cwd`에 Git Bash 스타일 POSIX 경로(`/c/Users/…`)를 주면
Node(Windows)가 못 읽어 «SPEC.md가 없다»로 조용히 갈라진다. 손검증은 `cygpath -w`로 변환한
경로로 해야 한다. r42 §5의 백슬래시 소비 함정도 그대로였다(sed 표현이 깨졌다).

## 6. 남은 것

- **KF1은 끝났다.** `/spec delta` → 델타 1장 → pre D1·D2 → 구현 → 대조 → Stop D1~D5 → 자동
  병합이 한 바퀴 돈다. 사람이 치는 `merge`는 복구 경로로만 남았다.
- **이 라운드가 만든 침묵 3건** (계획서 §9 그대로 살아 있다):
  ① `decide()`의 부수효과 — 병합을 `decide` 안에서 한다. 번복 조건은 «decide를 다른 곳에서
  부르고 싶어지는 사건 1건». ② 병합 성공 알림은 로그 1줄만. ③ pre에서의 D5는 여전히 stop 몫.
  ②·③은 README 선택 대기 표에도 올렸다(#5·#6).
