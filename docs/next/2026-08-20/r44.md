# r44 — KF2 라운드 2: 침묵 인터뷰 배선 (기록기가 소비처를 얻었다)

계획서 `plankf2interview.md` §5 WBS의 **R2**. R1(r40)이 `spec-interview.mjs`를 냈지만 부르는
곳이 없어 `stats`가 항상 빈 집계였고, 그러면 계획서 §2 목표 1(«`/spec`마다 빠짐없이 발동»)이
성립하지 않는다. 이 라운드로 **KF2가 끝났다**.

사용자 결정 2건이 앞에 있었다 — **범위 = 문안 + 비대화 프록시 런**(대화형 스모크는 하지 않는다.
r40 §4가 R2를 «G3 + jp-trip 이후»로 미룬 것은 설치형 스모크가 실사용에 걸려서였고, 프록시로
바꿔 그 의존을 끊었다), **질문 제시 = 한 번에 하나씩**(계획서 §4-2·SKILL.md:58 그대로).

## 2. 프록시 런 1회 — 문안이 실제로 돈다

리포 밖 스크래치(`scratchpad/kf2-proxy/cart`)에 요구 한 줄 + 자동 응답 규약만 둔 `CLAUDE.md`를
놓고 `/specgate:spec` 1런. **시드에 «인터뷰를 하라»를 넣지 않았다** — 발동 여부 자체가 관측
대상이라 그 지시는 문안이 해야 한다. 19턴 · $1.04.

**`위임` 리터럴은 검사기와 충돌하지 않았다**(계획서 §10-3의 첫 실물 확인). 생성된 SPEC에
`spec-verify`를 걸면 **위반 0 · 경고 1**(C4 «파일:줄» 없음 — 구현 전이라 정상), C3 6열 통과,
C5 15/15. 예측대로 **U2(위임)만 재확인 목록에서 빠졌다** — 즉 Enter로 수락한 기본값은 다시
사용자에게 돌아오지 않는다. 계획서 §4-3의 의도이지만 r35 판정 IV(기본값이 굳는 오염)와는
방향이 반대이므로, 번복 조건은 «실사용에서 위임 행이 되돌아왔어야 했던 순간»으로 남긴다.

## 3. 계획 밖 관측 2건 (둘 다 배선이 아니라 배포 형태 몫)

**① `--plugin-dir`이 대화형 설치를 대체한다.** r38 §A가 «`/plugin marketplace add`·`/plugin
install`은 대화형이라 에이전트가 못 친다»로 사용자 개입을 전제했는데, `claude --plugin-dir <path>`가
세션 한정으로 같은 플러그인을 띄운다. 이번 런이 그것으로 돌았고 훅·스킬·커맨드가 전부 붙었다.
전역 설치가 아니므로 uninstall도 필요 없다 — 시험 설치의 오염 문제(CLAUDE.md 하네스 절)가 준다.

**② `commands/`가 스킬 슬롯으로 흡수돼 있다.** `claude --plugin-dir … plugin details specgate`의
인벤토리에 Commands 항목이 없고 `Skills (3) sdd, spec, tdd`로 나온다(`framework/skills/`에는
`sdd`·`tdd`뿐이다 — `spec`은 `commands/spec.md`다). 실제로 **`/spec`은 `Unknown command`로 즉시
실패**(23ms·$0)했고 `/specgate:spec`이 인식됐다. 이 리포의 문서·FIELD-GUIDE가 안내하는 호출
형태가 `/spec`이므로 어긋난다. 다만 `--plugin-dir` 로드와 `/plugin install` 설치가 같은 경로인지
확인하지 않았으므로 **문서를 아직 고치지 않았다** — 가르는 것이 먼저다.

## 4. 한계 (병기 의무)

1. **프록시는 대화가 아니다.** 질문 3개가 한 턴 안에서 연속으로 나왔다(자동 응답 규약 때문).
   실제 사용자 응답 대기와 그때의 중단 체감은 이 런이 재지 못한다. 계획서 §7 ②의 «중단 +1회»는
   «인터뷰 블록 1회»라는 회계 표현이고, 하나씩 물으면 **실제 중단은 3회**다.
2. **n=1이고 대조군이 없다.** 배선 확인이라 스모크 설계 규칙 조건 5를 적용하지 않았다. KF2 효과를
   언젠가 보고할 때 **«모델 기본 행동일 수 있다»(r31 §1-4) 병기는 그대로 의무**다.
3. **런 설정 흠 1건** — `permission_denials` 3건이 났다. 전부 `PowerShell` 도구이고 원인은
   `--allowedTools`에 PowerShell을 안 넣은 것(CLAUDE.md 런 예시는 `Bash PowerShell`이다). 그중
   하나가 `spec-interview.mjs stats` 시도였고 에이전트가 Bash로 재시도해 성공했다. 인터뷰·게이트
   기인 차단이 아니므로 판정에 영향은 없지만, 실험 트랙이었다면 무효 조건이다.
4. **기록의 정직성**(계획서 §9-8) — `log` 호출은 문안 지시라 에이전트가 빠뜨리면 조용히 빈다.
   이번 런은 3/3 불렀지만 그것이 보장은 아니다.

## 5. 남은 것

- **KF2는 끝났다.** mute 설정 저장(`.specgate.json`)은 KF4 몫이고, KF2는 제안만으로 완결이다(계획서 §8-3).
- 관측 ②의 가름 — `/plugin install` 형태에서도 `/spec`이 `/specgate:spec`인지. 사용자 개입이
  필요하고(대화형), 결과에 따라 `README.md`·`FIELD-GUIDE.md`의 호출 형태를 고친다.
- `framework/README.md`에 `spec-anchor.mjs`(KF3 R1)가 아직 없다 — 이 라운드 몫이 아니라 기록만 한다.
