# r41 — KF3 라운드 1: 지목 실증기 record + 드리프트 감시 drift

계획서 `plankf3anchor.md` §5 WBS의 **R-A1 + R-A2**를 한 세션에 묶어 실행했다(사용자 결정).
묶은 이유는 둘이 한 파일이고, record만 만들면 r40과 같은 «기록만 있고 소비가 없다» 상태가
되기 때문이다. **R-A3(drift의 `modified` 범주)는 제외** — §4-6이 전제한 KF1 export가 실물에
없다(아래 §3-1).

## 1. 만든 것

| 파일 | 줄 | 내용 |

| `framework/spec-anchor.mjs` | 326 | `record`/`drift` CLI + `--selftest` r1~r7·d1~d6. A1~A3 · missing/stale |

`spec-verify.mjs` diff는 상수 1개와 C4 블록 말미의 11줄이 전부고, **판정 로직은 무접촉**이다.
`POS`는 `POS_FILE.source`를 첫 대안으로 조합해 한 소스를 공유한다 — 갈라지면 «경고는 없는데
앵커는 못 하는» 지목이 생긴다. `POS`는 `test()` 전용이라 캡처 그룹이 늘어도 판정이 같다.

**검증** — selftest 13건 전건 + 회귀 3종 무변경: `spec-verify --selftest` 6장,

## 2. 실물 1회 — 유령 지목은 0건이었다

`framework/smoke/i1-cart-r1`을 스크래치에 복사해 거기서 record 1회(원본 무접촉).

```
  앵커 28건(스팬 31) · 무위치 1건
    [경고 A3] S11 — 파일:줄 없음, 드리프트 감시 밖
  → SPEC.anchors.json 기록 (28 anchors · 31 spans)   exit 0
```

**A1·A2 위반 0건이다.** 이 SPEC은 `spec-gate` selftest가 «위반 0» 양성 픽스처로 쓰는 것이라
예상된 결과지만, 뒤집으면 **이 라운드에서 실증기가 잡아낸 유령 지목은 하나도 없다**는 뜻이다.
계획서 §10 #1의 번복 조건(«유령 지목이 실측되면 record를 훅에 배선»)은 여전히 안 열렸다.

drift는 무변경에서 exit 0, 사본에서 `src/CartList.css` 삭제 + `src/App.tsx` 첫 줄 삽입 후
missing 1(S4) · stale 1(S1) · exit 1. **줄 삽입이 stale을 낸 것은 의도된 보수적 동작**이고
selftest d4가 그 동작을 고정한다.

## 3. 계획에서 벗어난 것 3개

**① `modified`를 안 만들었다.** 계획서 §4-6은 «KF1 `spec-delta.mjs`의 `inspect()` 계열 export를
import»한다고 썼는데, 실물 `inspectDelta()`는 `counts.modified`(개수)만 반환하고 **MODIFIED가
지목한 문장 ID 목록을 안 준다.** R-A3 착수 시 `modifiedIds` 필드를 additive로 더하는 것이 선행
작업이다. 그 전까지 drift는 2범주 퇴화 모드로 돌고, 출력에 «활성 델타 없음»으로 명시된다.

**② `unanchored`를 따로 계산하지 않는다.** `c4.positions`의 **빈 배열 키**가 곧 그것이다.
JSON 필드로는 계획서 §4-3 그대로 나가되 계산이 파생일 뿐이다.

**③ positions 계산 방향을 뒤집었다.** §4-2 문면은 «ID마다 정의 줄 이후를 훑기»인데, 위치 표기가
있는 줄에서만 `mentions()`를 1회 부르는 쪽으로 뒤집었다. 결과는 같고 호출 수가 ID×줄 → 줄 수다.

부수: 앵커 키 순서는 사전순이 아니라 **SPEC의 문장 정의 순서**다(S1 다음이 S10이 아니라 S2).
같은 입력에 같은 순서라 결정론은 동일하고 읽기는 낫다. `--json`의 drift 쪽은 `anchors` 대신
`checked`(대조한 스팬 수)를 낸다 — record의 `anchors`(객체)와 타입이 갈리는 것을 피했다.

## 4. 선례를 따른 것 / 벗어난 것

- 인자 파싱은 `spec-delta.mjs`에서 **베끼지 않았다**(r39 §2의 «`--base` 없으면 첫 인자를 삼킨다»).
  값 있는 플래그가 없어 `args.find(a => !a.startsWith('--'))` 한 줄이면 된다.
- selftest는 실프로세스이되 `execFileSync`가 아니라 **`spawnSync`**(r40 §2-② 선례) — exit 1·2에서도
  `--json` stdout을 그대로 읽어야 한다.
- **사람용 출력(`reportRecord`·`reportDrift`)은 selftest가 안 덮는다** — 전 케이스가 `--json`
  경로다. §2의 실물 1회가 그 층의 유일한 검증이었고, 실제로 거기서 `reportRecord`의 미완성 줄
  하나를 잡았다. r39 §2가 말한 구멍이 형태만 바꿔 남아 있는 셈이다.
- 훅은 이번에도 안 막았다(`specgate@proj3` uninstall 상태 — r40 §3과 같다). 우회는 하지 않았다.

## 5. 남은 것

- **R-A3**(modified) — KF1 merge + `modifiedIds` export 이후.
- README·`commands/spec.md`·CLAUDE.md 커맨드 절은 **안 건드렸다**(r39·r40 선례 — KF1 R3와 공유
  파일이 충돌한다). KF3 검사표 등재는 KF4 SG 번호 부여(SG1021~1026)와 같이 가는 것이 싸다.
- **안 돌리면 아무것도 실증되지 않는다.** record는 어떤 훅에도 안 걸려 있어(3예산 ② 중단 0) 이 층
  자체가 fail-open이다. 빈손 완료를 하는 에이전트는 record도 안 돌린다 — «실증기만으로 조사 F3층이
  제거된다»고는 주장하지 않는다.
- 효과 실측은 여전히 0이다(조사 Q1). drift exit 0은 «문장이 아직 참»이 아니라 «앵커 스팬이
  그대로»다 — 스팬 밖 변경으로 문장이 거짓이 돼도 이 도구는 침묵한다.
