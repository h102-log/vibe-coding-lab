# r40 — KF2 라운드 1: 침묵 인터뷰 기록·집계기

계획서 `plankf2interview.md` §5 WBS **라운드 1만** 실행했다. 사용자 결정 3건이 앞에 있었다 —
**범위 = R1만**(R2는 설치형 스모크라 공통 전제 G3·실사용 투입에 걸린다. R1은 독립 CLI라 안 걸리고,
`commands/spec.md`를 안 건드려 KF1 R3와 공유 파일 충돌도 없다 — r39의 «A-3 유예 + 라운드 1만»과 같은 논리),
**선택 대기 #1 = 창 10 / `skip` ≥ 9 고정**(stats 인자로 노출하지 않는다 — 설정 파일은 KF4 몫),
**선택 대기 #4 = 문안은 `commands/spec.md`만**(`SKILL.md` 무변경 — 줄 번호가 검사기 주석에 박혀 있다).

## 1. 만든 것

| 파일 | 줄 | 내용 |
|---|---|---|
| `framework/spec-interview.mjs` | 223 | `readRows`/`stats` export + `log`·`stats` CLI + `--selftest` T1~T12 |

다른 파일 무변경. 플러그인 매니페스트도 안 고쳤다 — 선언 필드는 hooks/commands/skills 셋뿐이고
`.mjs`는 플러그인 루트(`framework/`) 직하에 두면 `${CLAUDE_PLUGIN_ROOT}/…`로 잡힌다.

**계획 추정(100~150줄)을 초과했다** — selftest 12건이 각자 다른 축을 재느라(exit / 줄 수 / 필수 필드 /
`muteSuggest` / `malformed` / stderr) 케이스마다 검사 함수를 갖는다. 공통 스키마로 접으면 오히려
케이스가 무엇을 재는지 안 보인다. 본체는 90줄이고 나머지가 selftest다.

**검증** — selftest T1~T12 전건 + 회귀 3종 무변경: `spec-verify --selftest` 6장, `spec-gate --selftest`
10건, `git status`에 새 파일 1개뿐(`verify-tdd`·`smoke/`·`verify-eval/` 무접촉, 리포 루트에
`.specgate-interview.jsonl` 미생성 = selftest가 mkdtemp 밖에 쓰지 않았다).
손검증 1회(임시 디렉터리에서 `log` 3번 + `stats` 사람용·`--json`) — 출력이 계획서 §4-4·§4-5 형태와 일치.

## 2. 선례에서 벗어난 것 2개 (둘 다 r39가 이유다)

**① 인자 파싱을 `spec-delta.mjs`에서 베끼지 않았다.** `indexOf('--base')` + `skip` 트릭이 r39 §2에서
«`--base`가 없으면 첫 인자를 삼킨다» 버그를 냈는데, 여기는 값 있는 플래그가 5종(`--cat`·`--resp`·
`--q`·`--u`·`--dir`)이라 그 트릭을 5번 반복하면 같은 버그가 5개 생긴다. 대신 한 줄로 `--key value`를
객체로 접었다. 알려진 한계는 코드에 `ponytail:` 주석으로 박아뒀다 — `--q "--로 시작하는 질문"`은 깨진다.

**② selftest를 `execFileSync`가 아니라 `spawnSync`로 돌린다.** T12(기록 실패 무해)가 «exit 0인데
stderr가 있는» 케이스라, throw 여부로 결과가 갈리는 `execFileSync`(`spec-gate.mjs` 선례)로는
stderr를 못 잡는다. 같은 `node:child_process` 내장이고 `{status, stdout, stderr}`를 그냥 준다.

실프로세스라는 선택 자체는 선례를 따랐다 — r39 §2가 «인라인 픽스처만 부르는 selftest는 CLI 파싱
버그를 9건 전건 통과시킨다»를 실측했으므로, 인자 파싱과 exit code를 selftest가 반드시 통과해야 한다.

## 3. 계획 밖 관측 1건 — 훅이 안 막았다

r39에서 `spec-delta.mjs` 첫 Write를 specgate 자신의 훅이 막았고, 그때 «uninstall이 실행 중 세션의
훅을 못 끈다»가 관측됐다. **이번 세션에서는 같은 자리의 Write가 통과했다** — uninstall이 *새* 세션에는
반영된다는 뜻이다. r39 §3-2의 뒤집힌 면이고, 배포 관점의 값은 그대로다: 끄는 것은 세션 경계에서만 듣는다.

우회는 여전히 하지 않았다(하네스가 Bash 우선을 지시했지만 heredoc으로 파일을 만드는 것이 곧 게이트
우회라 Write로 갔다). 막혔으면 r39와 같이 사용자에게 물었을 것이다.

## 4. 남은 것

- **R2**(`commands/spec.md` 문안 확장 + 설치형 스모크 1런 $0.5~1.5)는 **G3(실사용 실수요) + jp-trip
  투입 이후**다. 그때 선택 대기 #3(Enter 수락 행의 `위임` 리터럴)이 실물 SPEC에서 C3·C5 집계와
  충돌하는지 처음 확인된다.
- 기록만 있고 소비가 없다 — R2 문안이 붙기 전까지 `log`를 부르는 곳이 없으므로 `stats`는 항상 빈
  집계다. 이 라운드의 산출물은 «돌아가는 코드»이지 «작동하는 인터뷰»가 아니다.
- KF2 효과를 언젠가 보고할 때는 **«모델 기본 행동일 수 있다»(r31 §1-4) 병기가 의무**다 —
  대조군 1런에서도 판정 ③이 «충족»이었다.
