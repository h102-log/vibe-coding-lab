# r45 — KF3 라운드 2(R-A3): `drift`의 `modified` 범주 (KF3 종료)

계획서 `plankf3anchor.md` §5 WBS의 **R-A3**. r41이 R-A1·R-A2를 내면서 «§4-6이 전제한 KF1 export가
실물에 없다»는 이유로 미룬 자리다. KF1 R2·R3로 `spec-delta.mjs`의 `inspectDelta` → `ids.modified`가
실재하게 됐고, `spec-anchor.mjs`가 «KF1 병합 도입 후 R-A3에서 산다»로 비워 둔 두 자리를 채웠다.
**이 라운드로 KF3가 끝났다.**

## 1. 만든 것

| 파일 | 변경 | 내용 |
|---|---|---|
| `framework/spec-anchor.mjs` | +66/-9 | `inspectDelta` import · `readSpec`에 원문 · `declared` 판독 · 해시 불일치 분기 · `delta` 필드 · 출력 2줄 · selftest d7·d8 |
| `framework/README.md` | +6 | 「직접 돌리기」 3행 + 미배선·exit 0의 의미 2줄(r44 §5가 남긴 몫) |

판정 순서는 §4-6 그대로 두고 **3단계만 갈랐다** — 해시 불일치일 때 그 문장 ID가 활성 델타의
MODIFIED 절에 선언돼 있으면 `modified`(조치: record 재실행), 아니면 기존 `stale`(조치: 문장 재검토).
1단계 missing·2단계 범위 소멸은 선언 여부와 무관하게 그대로다. **델타의 위반 여부는 보지 않는다** —
차단은 게이트 몫이고 drift가 재는 것은 «선언이 있었는가»뿐이다.

같은 파일시스템 상태에서 델타 한 장이 붙으면 범주가 옮겨간다(스크래치 실측):

```
  stale     2  S1 → src/a.ts:2-4 (해시 불일치) · I1 → src/b.ts:1 (해시 불일치)
  modified  0  (활성 델타 없음 — SPEC.delta.md가 있을 때만 사는 범주다)
--- S1을 MODIFIED로 선언한 델타를 놓고 다시 ---
  stale     1  I1 → src/b.ts:1 (해시 불일치)
  modified  1  S1 → src/a.ts:2-4 (선언된 수정, 앵커 미갱신)
  → 갈라진 문장 2 · 앵커 그대로인 문장 0 · 선언된 수정 1건은 record 재실행으로 갱신하라
```

**검증** — `spec-anchor --selftest` 15건 전건(d7 선언+미선언 동시 변경 → modified 1·stale 1 /
d8 재기록 후 exit 0). 회귀 3종 무변경: `spec-verify` 6장 · `spec-delta` 19건 · `spec-gate` 23건.
d7이 미선언 쪽(I1)을 같이 바꾸는 것이 핵심이다 — 그것이 없으면 «전부 modified가 됐다»와 구별되지 않는다.

## 2. 계획서와 달라진 전제 1건 (사용자 결정)

계획서 §4-6은 «재방문 시 drift → 활성 델타의 MODIFIED 조회»를 그렸는데, 그 뒤 **KF1 R3의 게이트가
Stop에서 델타를 병합하고 삭제한다**(`spec-gate.mjs:51`). 그래서 활성 `SPEC.delta.md`가 존재하는 창은
**수정 세션 진행 중**뿐이고, 6개월 뒤 재방문 시점에는 델타가 없어 modified가 항상 0이다.

선택지는 ⓐ 활성 델타만(계획서대로) ⓑ 게이트 merge 로그에 `ids`를 얹어 창을 넓힘 ⓒ R-A3 포기였고,
**사용자가 ⓐ를 선택**했다. 남은 값어치는 수정 작업 중 «선언된 갈라짐»과 «설명 없는 갈라짐»을 가르는
것이고, 창이 좁다는 사실은 아래 한계로 병기한다.

## 3. 한계 (병기 의무)

1. **modified의 창은 수정 세션 중뿐이다.** 병합이 끝나면 판독 소스 자체가 사라진다 — 재방문 시점의
   drift는 사실상 2범주(missing/stale)다. 계획서 §9-7(«범주 경계가 델타 기록 품질에 종속된다»)에
   더해, 경계는 **델타의 생존 시간**에도 종속된다.
2. 계획서 §9의 나머지 8항은 그대로 유효하다 — 특히 **§9-5(안 돌리면 아무것도 실증되지 않는다)**와
   **§9-1(실재 확인 ≠ 의미 일치)**. `modified`가 생겼다고 «수정이 반영됐다»가 검증된 것이 아니다.
3. **효과 실측 0**(§9-6). 이 라운드도 selftest와 스크래치 1회뿐이고 실사용 관측은 없다.
