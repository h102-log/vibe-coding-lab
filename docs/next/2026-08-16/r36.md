# r36 — `framework/spec-verify.mjs` 작성 (도구 트랙 첫 라운드)

**번호**: r35까지 사용, r21 결번 → r36. 날짜 폴더는 지시서를 쓴 세션 날짜(2026-08-16).
**성격**: **CLAUDE.md 「프레임워크 개발 규칙」의 첫 적용 라운드다.** 사전등록·동결해시·전후비교를 하지 않는다.
이 라운드가 판정 문서 한 장으로 끝나면 규칙 1 위반이다 — **산출물은 돌아가는 `.mjs` 하나**다.

---

## 0. 왜 이걸 먼저 하나

`sdd/SKILL.md`는 SPEC.md에 **기계가 셀 수 있는 것**을 이미 여러 개 요구한다(`[추론]` 표기 · 점검표 10범주 ·
`선택 대기` 리터럴 · 완료 전 대조의 문장별 지목). 그런데 지금 그 준수 여부는 **전부 육안 판정**이고,
`specprobe.mjs`는 리터럴을 세기만 할 뿐 위반을 판정하지 않는다.

여기가 조사 §155가 «아무도 안 했다»고 적은 자리다 — *«10범주를 전부 Clear/Partial/Missing으로 찍지 않으면
exit 1»을 구현한 곳이 없다. 구현 난도는 낮다.* spec-kit도 택소노미를 **목록으로만** 준다.

## 1. 목표

`SPEC.md` 한 장을 받아 **sdd/SKILL.md가 명시적으로 요구하는 것**의 위반을 찾아 exit code로 뱉는다.

**A층(골격 독립)만 한다.** 헤딩 번호·절 순서 같은 골격 의존 검사(B층)는 이 라운드 범위 밖이다 —
골격은 프로젝트마다 사용자가 확정하는 것이지 도구가 정하는 것이 아니다(`framework/spec-template.md`는
«위임 시 쓰는 기본값»이지 규격이 아니다).

## 2. 검사 항목 — 전부 `sdd/SKILL.md`에 근거가 있다

| # | 검사 | 위반의 뜻 | 근거 |
|---|---|---|---|
| **C1** | 추론 문장에 `[추론]` 표기가 붙었는가 | 근거 없는 문장이 확정된 문장으로 섞였다 | SKILL.md:34 |
| **C2** | 점검표에 10범주가 **전부** 있고, 상태가 `Clear`/`Partial`/`Missing` 리터럴인가 | 훑지 않은 범주가 있다 | SKILL.md:40-53 |
| **C3** | 미확정표가 6열이고 상태에 `선택 대기` 리터럴을 쓰는가 | 확정 절차를 안 거쳤다 | SKILL.md:64-68 |
| **C4** | **완료 전 대조에 §1·§2의 문장이 전건 지목됐는가** | **지목 안 된 문장 = 구현되지 않은 문장** | SKILL.md:74-78 |
| **C5** | **`선택 대기` 항목이 재확인 목록에 전건 나오는가** | 사용자가 정할 몫이 조용히 사라졌다 | SKILL.md:79 |

**C4·C5가 이 도구의 값어치다.** 나머지는 세는 것이고, 이 둘은 **집합 차집합**이라 육안이 놓치기 쉽다.

문장 ID는 `framework/spec-template.md`가 규약으로 올린 3종 접두어(`S`/`I`/`U`)로 잡는다. 실물 5장이
이미 이 접두어를 쓰고 있으니 새 규약이 아니라 **관찰된 규약의 성문화**다. 접두어가 없는 SPEC은
C4·C5를 «판정 불가»로 내고 exit 1이 아니라 **경고**로 남긴다(골격 이전 문서일 수 있다).

## 3. 인터페이스 — `verify-tdd.mjs`와 맞춘다

```bash
node framework/spec-verify.mjs <SPEC.md 경로>            # 사람이 읽는 출력 + exit code
node framework/spec-verify.mjs <SPEC.md 경로> --json     # 기계용
node framework/spec-verify.mjs --selftest                # 픽스처 대조
```

**exit code**: `0` 위반 없음 / `1` 위반 있음 / `2` 파일 없음·파싱 실패.
`1`과 `2`를 반드시 가른다 — 훅이 «위반»과 «도구 고장»을 구분해야 하고, 고장을 차단으로 읽으면 작업이 멈춘다.

## 4. 자기검사 (규칙 4)

**먼저 있는 걸 본다** — `framework/smoke/runs/r32-fixture-F1..F6.md`(r33이 만든 합성 픽스처 6장)가
이미 결함을 심은 SPEC들이다. 이게 C1~C5 중 무엇을 덮는지 **먼저 대조하고**, 덮이지 않는 항목만 최소로 추가한다.
픽스처 디렉터리를 새로 만들지 않는다.

`--selftest`는 픽스처마다 «기대 위반 목록»과 실제 출력을 대조하고, 하나라도 어긋나면 exit 1.

## 5. 실물 5장 대조 — 이게 첫 실전 검증이다

작성 후 기존 SPEC 5장에 돌린다(**읽기만 한다. 절대 규칙 6 — 실측 원문이다**).

```
framework/smoke/{i1-cart-r1,sd1-cart-r1,sd2-cart-full,sd3-cart-ask,sd3b-cart-ask}/SPEC.md
```

**사전 예측(빗나가도 그대로 기록한다)**: 헤딩 구조상 **재확인 목록이 있는 것은 `i1`·`sd3b` 둘뿐이고
`sd1`·`sd2`·`sd3`에는 없다.** SKILL.md:79가 요구하는 항목이므로 **C5가 3장에서 걸릴 것으로 본다.**
걸리면 그게 **육안 판정 3회(r25·r31·r35)가 놓친 것을 기계가 잡은 첫 사례**다.
안 걸리면 검사가 느슨한 것이니 왜 안 걸렸는지 적는다.

## 6. 하지 않는 것

- **B층(골격 대조)** — 다음 라운드. 골격은 사용자가 확정하는 것이라 도구가 규격을 정하면 안 된다
- **훅 배선** — `guard.mjs`는 별도 라운드. 이 라운드는 exit code까지만
- **LLM 판단** — 차단성 게이트에 LLM을 쓰지 않는다(규칙 5). 셋 수 없는 것은 검사 항목에 넣지 않는다
- **`sdd/SKILL.md` 개정** — 대기 중인 2건(골격 확정 절차 · `선택 대기` 인용 금지)은 **사용자 결정 대기**다.
  이 라운드에서 문안을 건드리지 않는다
- **기존 SPEC 5장 수정** — 위반이 나와도 고치지 않는다. 실측 원문이다

## 7. 성공 기준

```
1. node framework/spec-verify.mjs --selftest        → 종료 코드 0
2. 실물 5장 전부에 실행                              → 크래시 0, 결과가 §5 예측과 대조됨
3. exit code 0/1/2가 규격대로 갈림                   → 위반 있는 파일과 없는 파일로 각 1회 확인
4. 코드 200줄 이하 · 새 의존성 0                      → 넘으면 검사 항목을 줄인다
```

4번이 상한이다. 넘으면 **기능을 빼지 코드를 늘리지 않는다.**

## 9. 결과 (2026-08-16 집행)

`framework/spec-verify.mjs` 215줄·의존성 0. `--selftest` 6장 전건 일치 · exit 0/1/2 각 확인 · 실물 5장 크래시 0.
기대값은 코드를 쓰기 전에 손으로 냈고, 첫 실행에서 어긋난 5장은 기대값이 아니라 **코드를 고쳐** 맞췄다(버그 2건).

| SPEC | C4 문장 지목 | C5 `선택 대기` 재확인 | exit |
|---|---|---|---|
| `i1-cart-r1` | 29/29 | **10/10** | 0 |
| `sd1-cart-r1` | 27/27 | **3/12 — 위반 9**(D2·D5~D12) | 1 |
| `sd2-cart-full` | 32/32 | 판정 불가(번호 ID) | 0 |
| `sd3-cart-ask` | 25/26 — **위양성 1**(질문 라벨 `Q1`) | 판정 불가(번호 ID) | 1 |
| `sd3b-cart-ask` | 판정 불가(문장 ID 없음) | 판정 불가(번호 ID) | 0 |

**§5 예측은 절반만 맞았다** — C5에 걸린 건 3장이 아니라 `sd1` 한 장이다. ① 재확인 목록은 `sd2`·`sd3`에도 **있다**(§3 말미 문장). ② §2의 «실물 5장이 이미 S/I/U 접두어를 쓴다»가 틀렸다 — 미확정표에 `U`를 쓴 건 `i1`뿐이고 `sd1`은 `D`, 나머지 3장은 순수 번호다. 그래서 접두어 하드코딩을 버리고 **6열 표의 첫 열**에서 ID를 뽑는다(지시서와 다른 설계 — 골격 독립은 유지된다). 번호 ID 3장은 문서 안 재등장을 셀 수 없어 «판정 불가»로 빠졌다.
**얻은 것** — `sd1`의 9건은 육안 판정 3회(r25·r31·r35)가 놓친 것이다. §3 말미가 «12개 행이 모두 `선택 대기`다. 그중 D1·D4·D3»으로만 적어 나머지 9개가 이름 없이 사라졌다.
**놀란 것** — `i1`이 통과한 건 재확인 목록을 더 성실히 써서가 아니라 §3에 `U1~U10` **범위 표기**를 남겼기 때문이다(전개해 전건으로 인정). 이 검사가 실제로 가르는 것은 «성실함»이 아니라 **«ID를 다시 적었는가»**다.
### 9-2. 적대 검증과 반영 (같은 세션, 서브에이전트 33)

3렌즈(위음성·위양성·근거 대조) × 발견마다 반증 1회. **발견 30건 중 17건 확인.** 그중 high 4건을 반영했다.

| 결함 | 무엇이 뒤집혔나 | 수정 |
|---|---|---|
| GFM 이스케이프 `\|` | 셀 하나가 밀려 `선택 대기` 행이 빠지고 **exit 1이 exit 0으로** 뒤집혔다(1글자 대조군으로 확인) | `cellsOf`가 `\|`를 구분자로 안 센다 |
| 상태 열 오집 | 헤더에 «상태»가 둘이면 C5가 **경고 한 줄 없이** 통째로 꺼졌다 | 뒤쪽 열 우선 + pending 0인데 본문에 리터럴이 있으면 경고 |
| 미확정표 복수 | 침묵 지점을 두 표로 쪼개면 둘째 표가 C5 밖 | 헤더로 잡히는 표 전부 검사 |
| C4 카스케이드 | 문장 ID처럼 생긴 토큰 하나가 뒤에 있으면 `cut`이 밀려 **전 문장이 한꺼번에 위양성** | 대조 영역을 ID별 정의 줄 이후로 자른다 |

여기에 코드펜스 안의 예시 표·리터럴을 실물로 세던 것을 고치고, **«파일:줄 없는 지목»을 경고로 신설**했다
(SKILL.md:77 — 빈 셀·«있을 것이다»·«구현 안 함»도 ID만 다시 적으면 통과한다는 발견 ①. **게이트로 올리지는 않았다** —
«실행 확인»·«부재로 충족»처럼 위치가 없어도 정당한 지목이 실물에 있어 위양성이 난다).

**판정 축은 한 건도 안 바뀌었다** — 실물 5장·픽스처 6장의 위반 수와 C5 미제시 목록이 수정 전후 동일하고, 늘어난 건
경고뿐이다(6장 전부 `S9` = 빌드 종료 코드 문장 하나). 수정 도중 회귀 1건을 자체 검출했다: 미확정표를 복수로 잡으며
`선택 대기`를 **인용**하는 §3 대조표까지 삼켜 `i1`이 «문장 ID 없음»으로 뒤집혔다 → 헤더 매칭 우선으로 해소.

**반영하지 않은 것(확인 13건, 알려진 한계)**: C1은 `[추론]` 1건만 있으면 통과 · C2가 SKILL.md에 없는 «N.» 번호 서식을
사실상 강제 · SKILL.md 프론트매터의 «완전한 스펙이 이미 있는» 경로에서 C1·C2·C3가 한꺼번에 위반 · §2 상호참조가
«대조 지목»으로 계수됨(절 인식이 없어 B층 없이는 못 가른다) · ID 없는 문장은 분모에서 빠짐.

`선택 대기` — §7-4 상한 해석: 파일 **249줄** / 주석·빈 줄 제외 **190줄**(검증 반영 전 215 / 171). 전체 줄 기준이면
초과다. 맞추려면 C1(11장 전부 통과 — 검출 0건)을 빼거나 주석을 지워야 한다. **기본값은 «둘 다 하지 않음»**으로
진행했다 — 늘어난 34줄은 기능 추가가 아니라 위 4건의 결함 수정이고, 주석은 «왜 이렇게 짰나»를 담고 있다.
