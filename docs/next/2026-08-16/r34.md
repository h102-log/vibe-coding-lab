## 0. 이 라운드가 확정하는 것 · 하지 않는 것

### 0-1. 확정 — v0.1 = 2축 (r16 로드맵 이탈, 명시적 계획 변경)

r16 §2는 tdd → sdd → **edd** → 통합 순서를 정했다. 이 라운드는 **edd를 건너뛰고 통합으로 간다.**
계획 변경이므로 이유와 대가를 여기 박는다.

| | 내용 |
|---|---|
| **이유** | 효과 근거가 아직 0이고(r27 §1), 실효를 잴 자리는 실사용 2회차 하나뿐이다. edd는 문안 시드가 없는 유일한 축이라 4~6세션이 더 든다(r27 §2-2 A). 2축으로 먼저 닫으면 3세션 뒤에 시계를 돌릴 수 있다. |
| **대가 1** | **실사용 2회차가 «2축판 관측»으로 소진된다.** 3축을 재려면 3회차가 필요하고, 실사용은 대상 프로젝트 하나와 달력 10일을 먹는다(r27 §3 반론). 되돌리기 어렵다. |
| **대가 2** | r16 §5-2가 «가치 가설의 핵심 조합»으로 지목한 `sdd+edd`를 **못 잰다.** v0.1이 재는 것은 `sdd+tdd`다. |
| **부수 이득** | r16 §7-2·3(edd 정의 승인 · 동결 강도)이 **보류로 내려간다** — 2축 실사용에서 «에이전트가 스스로 검증을 도출하고 사용자가 승인하는» 장면이 실제로 나오는지 보고 나면 그 [가정]을 더 나은 정보로 답할 수 있다(r27 §2-2 B). |
| **edd의 자리** | v0.2 또는 실사용 2회차 관측 **중** 병행(r27 방향 D). 이 라운드는 정하지 않는다. |

### 0-2. 하지 않는 것

1. **효과 주장** — 스모크는 «문안이 도달해 지시된 산출물이 나오는가»만 잰다(r16 §4). 2축 스모크도 같다.
2. **RUBRIC 개정** — r33 §7-2의 한 줄짜리 5건은 **이번에 안 묶는다**(§7-3 근거).
3. **설치형 트리거 확인** — r28 작업 ①의 몫. 이 라운드 밖이고, **실사용 개시 전에 반드시 선행**한다(§9).
4. **`framework/README.md`** — r28 작업 ②. 조합 안내는 2축 확정 뒤에 쓰는 게 맞지만 이 라운드에 넣지 않는다.

## 2. 작업 B — 통합 2축 스모크 1런

### 2-1. 과제 — cart 유지 (조건 5 처리 포함)

**cart 과제(`sent-sd1.txt`)를 그대로 재사용한다.** 새 과제를 만들지 않는다.

근거 셋:

1. **RUBRIC v2.1이 cart 전용이다.** A-2(심어둔 침묵 3요소)·A-3 ⓐ 예시가 −/+ 버튼을 못 박고 있다.
   과제를 바꾸면 A-2·ⓐ를 먼저 고쳐야 하고 그건 **v2.2 새 판 + 새 판정 팩**이다(r33 §7-1). 그러면 이 라운드의
   재판정이 «v2.1의 실물 재현성»이 아니라 «v2.2의 첫 시험»이 된다 — 검증 대상이 바뀐다.
2. **자연 대조군이 이미 리포에 있다.** `sd1-cart-r1`(sdd 단독·같은 요구)에서 에이전트는 자체 테스트를 만들어
   검증한 뒤 **삭제**했다(r25 §3-1). 같은 요구에 tdd를 켰을 때 **남는가**가 §3-3 판정 III의 직접 대조가 된다.
   과제를 바꾸면 이 대조가 사라진다.
3. 요구 문안 재작성 비용 0.

**조건 5(CLAUDE.md «스모크 설계 규칙») 처리** — 이 스모크는 조건 5에 걸리는가:

> 조건 5는 «침묵이 산출물에서 이름을 얻는가» 류 판정(③·④)을 **판정 축으로 쓰는** 스모크에 적용된다.
> cart 과제는 이미 대조군 값이 있다 — `sd4-cart-r1`(문안 없음)에서 **③ 충족 · ④ 잡힘**(r31 §1-2).
> r30 §3-6ⓒ 3분기의 «충족» 칸 → **ⓐ 그 판정을 축에서 뺀다.**

따라서 **판정 ③·④를 이 스모크의 판정 축에 넣지 않는다.** 잃는 것이 없다 — 4단계 통합이 원래 묻는 것은
«산출물이 순서대로 나오는가»(r16 §3-4-2)이지 침묵 포착이 아니다. 침묵 포착은 2단계 스모크(r25)의 판정이었다.

**단 §4 재판정에서는 ③·④ 값이 나온다.** 그 값은 **재현성 검증의 재료일 뿐 효과 신호가 아니다** —
r35의 판정 문장에 「대조군 1런에서 ③ 충족·④ 잡힘이 이미 관측됐다(r31 §1-2)」를 병기한다.

### 2-2. 시드·주입·격리

- **시드**: `exp4/seed` → r18 §3-1 조정(node_modules·tests/ 제외 복사, `test:ac` 제거, App 문구 중립화,
  name 필드 변경) + **`npm ci` 선행**(요구 문안 첫 줄 «설치됨»을 참이 되게 — r25 §1-3).
- **디렉터리**: `i1-cart-r1`(통합 = `i`, 라운드 접미를 처음부터 — r22 결함 ⑰).
- **주입**: `--append-system-prompt`로 **tdd SKILL.md + sdd SKILL.md 둘 다**. 두 문안을 어떤 순서로 이어
  붙였는지 r35에 적는다(모델이 순서에 반응할 여지 — 기록만, 판정 아님).
- **격리 — r28 §5 규칙을 이 라운드에서 선적용한다** (r28 작업 ③은 미실행이지만 방식은 이미 verify-eval에서
  실행됐다). **이 라운드에서는 선택이 아니라 필수다**: `framework/smoke/`에 cart SPEC.md가 **5장** 있고,
  sdd에서 이웃에 남는 것은 **이전 런의 SPEC.md = 정답지**다(r22 §5-6). 접촉이 성공하면 판정이 «문안»이
  아니라 «옆 디렉터리를 읽었다»가 된다.

  → 런 cwd = `%TEMP%\fw-i1\i1-cart-r1\` (리포 밖 단독 부모, 형제·리포 불가시). 종료 후 산출물을
  `framework/smoke/i1-cart-r1/`로 **이동**해 커밋한다.

```bash
# cwd = %TEMP%\fw-i1\i1-cart-r1  (Git Bash)
cat sent-i1.txt | claude -p \
  --safe-mode --model opus --effort xhigh \
  --permission-mode acceptEdits --allowedTools Bash PowerShell \
  --append-system-prompt "$(cat sdd-SKILL.md; echo; cat tdd-SKILL.md)" \
  --session-id <UUID> --output-format json > runs/i1-cart-r1.json 2> runs/i1-cart-r1.stderr.txt
```

`sent-i1.txt`는 `sent-sd1.txt`의 사본이고 **diff 0을 확인해 r35에 적는다.**

### 2-3. 판정 — 사전 등록 (결과 본 뒤 변경 금지)

| | 판정 | 기준 | 계측 |
|---|---|---|---|
| **I** | 산출물 3종 | `SPEC.md` · 테스트 파일 · 구현이 전부 나오는가. 순서는 SPEC이 먼저인가(세션 JSONL의 Write 순서) | 육안 + JSONL |
| **II** | **연결** | 테스트 파일이 **`SPEC.md`의 문장을 인용**하는가 — tdd 참조 내부화 조건문이 2축에서 사는가 | 육안(인용 원문 필수) |
| **III** | **수렴** | 테스트가 **남는가** — sdd 단독 3분산(만들고 삭제 / 남김 / 안 만듦, r25 §3-1)이 tdd 병행에서 «남김»으로 가는가 | `verify-tdd.mjs` + 육안 |
| **IV** | **오염** | tdd가 §2의 **`선택 대기` 행(미확정)을 테스트로 박지 않는가** — 미확정을 확정으로 굳히면 sdd의 «선택 대기»가 무의미해진다(r22 §4 한계 ⑤ · r25 §6-3) | 육안(선택 대기 행 목록 ↔ 테스트 단언 대조) |

- **III이 «안 만듦»이면 판정 실패가 아니라 무효가 아니다** — tdd 문안의 조건부(«만들어 돌렸다면»)는 실측
  원문이고 테스트 생성을 강제하지 않는다(r16 1단계 결정). «안 만듦»은 **판정 III 미검증**으로 기록하고
  재실행하지 않는다(r16 1단계의 «테스트 0개 = 무효»는 tdd 단독 스모크 규정이라 여기 상속하지 않는다 —
  이 라운드의 목적은 조합 연결이지 tdd 생성률이 아니다). 그 경우 판정 II도 재료가 없어 미검증이 된다.
- **판정 ③·④는 축이 아니다**(§2-1). ①·⑤(마커·표)는 `specprobe.mjs`로 **참고 수치만** 뽑아 대장에 싣는다.

### 2-4. 계측

```bash
node framework/verify-tdd.mjs framework/smoke/i1-cart-r1 i1-cart-r1   # 앱에 npm ci 선행
node framework/specprobe.mjs framework/smoke/i1-cart-r1/SPEC.md
```

둘 다 **에이전트에게 주지 않는다.** verify-tdd는 r26에서 tdd 산출물 판정의 1차 도구로 채택됐고
**육안 전수는 유지**한다(C·D 미검증 — r26). 스크립트와 육안이 어긋나면 **육안이 이긴다.**

### 2-5. 무효 규정 (사전 등록 — r22 §5-6 상속)

`permission_denials`≠0 · 이웃 디렉터리/리포 접촉 · 원문 소실 · 요구 문안 유실.
무효는 시드 복원 + **새 디렉터리**(`i1-cart-r2`) + 새 UUID로 재실행하고 이전 원문은 보존한다.

`SPEC.md` 미생성은 먼저 원인을 가른다 — 로그에 도구 거부·크래시·컨텍스트 초과가 있으면 무효,
없으면 «안 만듦»이므로 판정 I의 최악값으로 기록한다(r22 §5-6 그대로).

## 3. 작업 C — 실물 SPEC 재판정 3세션

r33 §7-1. **작업 B가 유효 런으로 끝나야 착수한다**(SPEC.md가 없으면 판정 대상이 없다).

### 3-1. 대상·팩

- **대상**: 작업 B가 낳은 `SPEC.md` 1장 + 최종 응답. 라벨 `G1`(합성 픽스처 `F<n>`과 구별).
- **팩**: `rubric-sdd.md` 부록 B 그대로 — `RUBRIC.md`(v2.1 마커 사이 **바이트 사본**, `cmp` 확인) ·
  `req-a.md`(= `sent-i1.txt` 사본) · `G1.md`(SPEC 원문 → 빈 줄 → `---` → `# 최종 응답` → 응답 전문).
- **팩 오염 grep** 0건 확인(부록 B-5의 패턴 그대로) 후 결과를 r35에 한 줄로 적는다.
- **프롬프트**: 부록 B-3의 4줄 + **5행 신설** — 「셸 명령을 쓰지 마라. 파일을 읽고 세라.」
  r33에서 무효 2건(Bash 거부)의 원인이 이 한 줄의 부재였다(r33 §7-3). 프롬프트 파일은 **선커밋 대상**이다.

### 3-2. 선커밋 · 기대값

**판정 세션 전에** 한 커밋으로: `G1.md`(픽스처) · 기대값 문서 · 프롬프트 파일 3장 · RUBRIC 판정자 사본.
커밋 시각과 첫 세션 시작 시각을 r35 대장에 적는다 — **커밋 이력이 순서를 증명한다.**

**기대값 = 실험자 선판정.** 여기가 r33과 결정적으로 다르다: r33의 기대값은 «심어둔 것»을 아는 합성
픽스처였지만, 이번 기대값은 **실물을 보고 매긴 한 사람의 판정**이라 **틀릴 수 있다.**
그래서 대조 결과는 세 갈래로 읽는다:

| 결과 | 읽는 법 |
|---|---|
| 3세션 동일 = 기대값 | **실물 재현 확인.** v2.1 유지 |
| 3세션 동일 ≠ 기대값 | **기대값을 정정하고 정의·픽스처는 고치지 않는다**(r32 §5-3 특칙 · r33 부록 A 전례). 정정 표를 r35에 남긴다 |
| 3세션이 갈림 | **그 항목이 v2.2 개정 재료.** 갈린 항목만 적고, **이 라운드에서 문안을 고치지 않는다**(결과를 보고 기준을 바꾸지 않는다) |

**갈림의 정의**(r32 §5-3 상속): 대조 값은 ①·⑤ 수치 / ②④ 이진 / ③ 3값 + ⓐⓑⓒ 인용 요소 / 질문 수 세 값.
범위·형식 표기는 **병기 항목**이라 갈려도 «갈림»으로 세지 않는다(r33 §3-2 전례).

### 3-3. 실행

`rubric-sdd.md` 부록 B-3 그대로 — 세션별 스크래치 cwd, `--allowedTools` 없음, opus·xhigh, 순차 전경.
**3 독립 세션**(라벨 `G1-1-r1`·`G1-2-r1`·`G1-3-r1`). 무효는 `r2`로 새 라벨·새 UUID 재실행, 원문 보존.
무효 조건은 부록 B-7 그대로.

**서브에이전트를 판정자로 쓰지 않는다** — 이 세션의 시스템 프롬프트·CLAUDE.md를 상속한다(부록 B-3).

## 7. 한계 (사전 등록 — 결과에 병기한다)

1. **n=1이다.** 통합 스모크 1런은 신호이지 근거가 아니다(r16 §4). 판정 II·III·IV 전부 n=1.
2. **판정 III의 «대조»는 n=1 대 n=1이다** — `sd1-cart-r1`(sdd 단독, 삭제)과 `i1-cart-r1`(2축)의 차이를
   «tdd 덕»이라고 말할 수 없다. 기본값 방향이 같은 문안·같은 요구에서도 갈린 전례가 있다(r25 §3-3).
   **기록만 한다.**
3. **③④는 이 스모크의 축이 아니다**(§2-1). 재판정에서 나온 ③④ 값을 효과로 읽지 않는다 —
   대조군 1런에서 이미 «③ 충족·④ 잡힘»이 나왔다(r31 §1-2).
4. **재판정 기대값이 실험자 선판정이라 틀릴 수 있다**(§3-2). r33의 기대값(합성·심은 것을 앎)보다 약하다.
5. **판정자는 같은 계열 모델 3회 표집**이지 독립 판정자 3명이 아니다(r33 §6-1). 공통 편향은 안 걷힌다.
6. **이 라운드가 끝나도 v0.1의 효과 근거는 0이다.** 조합 연결이 확인되는 것이지 조합의 실효를 재는 것이
   아니다. 실효는 실사용 2회차 전담이다.
7. **2축 확정은 되돌리기 어렵다**(§0-1 대가 1).
