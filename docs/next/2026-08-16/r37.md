# r37 — 게이트 배선: 문안이 처음으로 «막았다»

**전제.** 사용자 지적 — 2주 68커밋에 배포 가능한 형태가 0. spec-kit·MoAI-ADK 같은 물건을
만들려던 것인데 남은 게 문안 95줄 + 계측기다. r36까지의 `spec-verify.mjs`는 판정을 exit code에
실었지만 **아무도 그 exit code를 읽지 않았다.**

## 1. 한 일 — 코드

| 파일 | 줄 | 새 로직인가 |
|---|---|---|
| `framework/hooks/spec-gate.mjs` | 100 | **그렇다** — 유일한 신규 로직 |
| `framework/hooks/hooks.json` | 20 | 설정 |
| `framework/.claude-plugin/plugin.json` | 9 | 설정 |
| `framework/commands/spec.md` | 22 | 프롬프트 |
| `framework/README.md` | 70 | 문서 (r28 작업 ②) |
| `.claude-plugin/marketplace.json` | 11 | 설정 |
| `framework/spec-verify.mjs` | +3 | import 가드 |

게이트는 판정하지 않는다. `inspect()`를 그대로 부르고 **시점만 가른다** —
`pre`는 C1~C3(구현 시작 시점에 참일 수 있는 것), `stop`은 C1~C5 전부.
C4·C5를 `pre`에 걸면 첫 줄부터 영원히 막히므로 이 분리가 게이트의 전부다.

`spec-verify.mjs`의 import 가드가 없으면 훅의 인자(`pre`)를 SPEC 경로로 읽고 exit 2를 내며
**매 Write를 오차단**한다. 3줄이지만 이게 없으면 전체가 고장이다.

## 2. 검증

- `spec-gate.mjs --selftest` — 10건 전건 일치. **실제 프로세스로 돈다**(execFileSync + stdin).
  `decide()`만 직접 부르면 stdin 파싱 2줄이 깨져도 통과하고, 훅은 «파싱 실패 → 빈 이벤트 → 통과»로
  조용히 fail-open한다. 그 실패 모드를 selftest가 덮어야 한다.
- `spec-verify.mjs --selftest` — 6장 전건 일치(회귀 무변경, import 가드가 아무것도 안 깼다).

## 3. 라이브 실측 (2026-08-16, sonnet · `acceptEdits` · $0.36 · 9턴)

스크래치 빈 프로젝트 + `.claude/settings.json`에 훅 직접 등록 → «인사 함수 하나» 요청.

| | 결과 |
|---|---|
| `src/greet.ts` | **미생성** |
| `permission_denials` | Write 1건 (+ proj3 밖 Glob 2건 — cwd 밖 접근이라 무관) |
| 에이전트 행동 | 우회 시도 0. `.claude/settings.json` → 훅 스크립트를 읽어 C1~C5를 스스로 재구성한 뒤 사용자에게 되물음 |

> 이건 스펙 기반 개발(SDD)을 강제하는 프로젝트 차원의 하드 게이트라서 **제가 우회할 수 없고**,
> "이름 받아서 인사말 반환하는 함수 하나"라는 요청 규모에 비하면 **문서 작업이 배는 더 큽니다.**
> — 차단당한 에이전트의 응답 원문

**앞 문장이 이 라운드의 성과고, 뒤 문장이 이 라운드의 발견이다.**

## 4. 발견 → 결정

에이전트의 «문서 작업이 배는 더 크다»는 정당한 지적이다. 확장자만 보고 거는 게이트는 한 줄짜리
유틸에도 10범주 점검표를 요구한다. 이대로 실사용에 넣으면 첫날에 꺼진다.

**사용자 결정 2건 (선택지 제시 후 채택):**

1. **게이트 대상 = `Write`만, `Edit` 제외.** SPEC이 필요한 시점은 «새 기능을 시작할 때»다.
   대가: 빈 파일을 만들고 `Edit`으로 채우는 우회가 열린다. 기각한 대안 — 규모 임계값(작은 파일
   여러 개로 우회됨) · 경로 선언(선언 안 하면 fail-open).
2. **이름 = `specgate` 확정.**

## 5. 부수 효과 — r28 작업 ①의 성격이 바뀌었다

기존 계획은 «설치형 스킬이 자동 트리거되는지 확인»이었다. **훅은 트리거 판단 없이 무조건 돈다** —
스킬이 로드되든 말든 SPEC.md 없으면 Write가 막힌다. 실사용 개시의 필수 관문이었던 것이 보조로
내려갔다. 스킬 트리거는 이제 «SPEC을 잘 쓰게 돕는» 역할이지 «게이트가 작동하는 조건»이 아니다.
