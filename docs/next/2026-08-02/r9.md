### 2.1 43줄 주입 — **파일 전체를 넣는다**

```bash
cat /c/Users/bhy99/proj/proj3/exp2/fw/skills/spec/SKILL.md >> CLAUDE.md
sha256sum /c/Users/bhy99/proj/proj3/exp2/fw/skills/spec/SKILL.md
# 00f70d94b2f0c1e51e2591bdea0d051e8b7fafc89dc165b83ecc7320bb98a7c1 이어야 한다
```

**YAML 프론트매터(`---` / `name:` / `description:` / `---`)를 떼지 않는다.**
세 실험은 `--append-system-prompt "$(cat SKILL.md)"`로 **파일 전체**를 주입했다.
프론트매터가 CLAUDE.md 문맥에서 무의미해 보여도, 떼는 순간 **기준선과 다른 물건**이 되고
이 트랙이 세 실험에 붙는 유일한 끈이 끊어진다. 고치고 싶으면 r8 §7-④다.

## 3. 스택 — **Vite + React 확정** (2026-08-02 실측)

사용자 초안은 Next.js였다. **이 머신에서 도는지가 먼저**다 —
Smart App Control Enforced라 Next.js가 의존하는 `@next/swc-win32-x64-msvc`가 막히면
`next dev`가 아예 안 뜬다. 세 실험이 Vite였던 것은 그쪽이 통과한다는 게 **실측으로 확인됐기 때문**이고,
SAC는 서명·평판 기반이라 전부 막히는 것이 아니다(esbuild ○ / chromium ×).

### 3.1 판정 절차

```bash
# 스크래치패드에서. 대상 리포를 더럽히지 않는다
cd "$TMP/scratchpad" && npx create-next-app@latest sac-probe --ts --no-git --yes
cd sac-probe && npx next build      # 여기서 죽으면 SAC 차단이다
```

| 결과 | 결정 |
|---|---|
| `next build` 성공 | 스택 자유 선택. Next.js로 가도 된다 |
| 네이티브 바이너리에서 차단 | **Vite + React** (`npm create vite@latest`). 실험 3트랙에서 검증된 경로다 |

### 3.1a 실측 결과 — 위 표에 없는 제3의 값이 나왔다

`create-next-app@latest` (Next.js 16.2.12) 스캐폴드 후, 스크래치패드에서 측정:

| 명령 | 결과 |
|---|---|
| `next build` (Turbopack 기본) | **✗** `@next/swc-win32-x64-msvc` → `An Application Control policy has blocked this file` → WASM 폴백은 되지만 **Turbopack이 WASM 바인딩을 거부** |
| `next build --webpack` | **○** 컴파일 6.1s · `tsc` 5.2s · 정적 4/4 생성 통과 |
| `next dev --webpack -p 3999` | **○** `Ready in 394ms` |

**SAC 차단은 실재하지만 치명적이지 않다** — Next.js는 `--webpack`으로 우회된다.
즉 판정표의 「성공」도 「차단」도 아니어서 자동 판정이 성립하지 않았고, r8 §7-⑦로 사용자에게 물었다.

**결정: Vite + React** (2026-08-02, 사용자 확정). 근거 셋:

1. 이 앱은 SSR·라우팅·API 라우트를 **하나도 안 쓴다** — §3.2가 미리 짚은 그대로다
2. `--webpack`을 매번 붙여야 한다. 빠뜨렸을 때 터지는 빌드 실패는 §4.3 기준으로 **F가 아닌 환경 잡음**이고, 그 잡음이 기록에 섞이는 것이 이 트랙에는 순손실이다
3. 세 실험이 전부 Vite였다. 같은 경로를 쓰면 이 트랙이 기준선에 붙는다

§3.2(Next.js를 고른 이유를 적어두는 절)는 **해당 없음**으로 닫는다.

### 3.2 Next.js를 고른다면 그 이유를 적어둔다

설명된 앱(localStorage 단일 페이지)은 SSR·라우팅·API 라우트를 **하나도 안 쓴다.**
그래도 고른다면 «Next.js를 익히는 것 자체가 목적»처럼 **이유가 프로젝트 밖에 있다**는 뜻이고,
그건 정당하지만 **r8 §4.4**의 «형식 노동» 신호와 섞이지 않게 미리 적어둔다.

## 4. 초기 요구 — 넣을 것과 **비울 것**

### 4.1 첫 세션에 만드는 것

> 프롬프트 **제목**과 **마크다운 본문**을 입력받아 리스트로 띄우고,
> 버튼을 누르면 **클립보드로 복사**되는 단일 페이지 웹 앱.

이게 전부다. 저장은 localStorage로 충분하다.

### 4.2 비우는 것 — **채우지 않는 것이 설계다**

검색 · 태그 필터링 · DB 연동 · 수정/삭제 UX · 파라미터 입력창 · 정렬 · 내보내기

**여기를 미리 정해주면 이 트랙이 무효가 된다.** 계약이 완전해지면 §2가 빈손이 되고,
그건 실험 1이 걸린 삼각 모순을 비싸게 반복하는 것이다(r8 §1).
쓰다가 필요해지는 순간이 **R·Q·F 사건**이고, 그게 이 트랙이 재려는 전부다.

### 4.3 F로 세는 것과 안 세는 것 (r8 §4.1 정정본)

| 사례 | F인가 |
|---|---|
| 복사 실패 시 무엇을 보여줄지 안 정해져 있었다 | **○** — 계약의 침묵 |
| 긴 본문을 리스트에서 어디까지 보여줄지 안 정해져 있었다 | **○** |
| `react-markdown`이 줄바꿈을 안 살린다 | **×** — 라이브러리 기본 동작. 기록만 |
| 하이라이팅이 특정 언어를 못 잡는다 | **×** — 같음 |
| 빌드가 SAC에 막힌다 | **×** — 환경 |

기준: **의도가 명확했는데 도구가 안 따라준 것은 F가 아니다.**

## 6. 기록

**관측 기록은 `proj3`에, 산출물은 대상 리포에.** 섞지 않는다.

```
proj3/docs/usage/YYYY-MM-DD.md      ← 주 1회 또는 마일스톤마다, 5줄 이내
ai-prompt-vault/SPEC.md             ← 대상 리포. 세션마다 커밋
```

`docs/usage/` 형식은 r8 §10이 «첫 기록에서 굳힌다»고 열어둔 것이다. 초안:

```markdown
# YYYY-MM-DD
- R/Q/F: <사건 한 줄> → §2 적중 | 누락 | (F 아님: 라이브러리)
- §2 누적: N개
- §4.4 신호: 없음 | <있으면 한 줄>
```

애매하면 **누락으로 센다**(r8 §10). 관찰자가 결과를 바라는 방향의 반대로 기울이는 것이 유일한 방어다.
