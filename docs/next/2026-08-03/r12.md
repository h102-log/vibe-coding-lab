## 2. 내일 할 것 — 순서대로

> **전부 «세션»이 아니다.** 2.1~2.4는 그냥 앱을 쓰는 것이고, Claude를 부르지 않는다.
> 세션은 §3의 조건이 걸릴 때만 연다.

### 2.1 앱을 띄운다

```bash
cd /c/Users/bhy99/proj/ai-prompt-vault
npm run dev
```

### 2.2 프롬프트를 넣는다 — **내일 몫 최소 3개**

마일스톤은 10개(r11 §2.1)다. 하루에 다 채우는 게 아니라, **이미 쓰고 있는 것부터** 옮긴다.
새로 지어내면 그건 데모지 사용이 아니다.

넣을 것이 있는지 판단하는 기준 하나:

```
지난 한 주에 두 번 이상 같은 말을 Claude에게 친 적이 있는가?
```

있으면 그게 이 앱에 들어갈 프롬프트다. 없으면 **억지로 채우지 않는다** — 그 경우
"이 앱은 내 실무에 필요한 물건이 아니었다"가 관측 결과이고, r8 §6.1이 그 행을 이미 갖고 있다.

### 2.3 다운로드 버튼을 한 번 누른다 ← **오늘 고친 것의 실측**

| 확인 | 기대 |
|---|---|
| 파일이 실제로 내려받아지는가 | `<제목>.md`가 다운로드 폴더에 생긴다 |
| 내용 | 본문 원문만 (제목은 파일 안에 없다 — SPEC U19) |
| 제목에 `:`나 `/`를 넣은 항목 | 하이픈으로 바뀐 이름으로 저장된다 (U20) |

**안 되면 그건 사건이 아니라 버그다** — `docs/usage/`에 «F 아님: 브라우저 API» 로 기록만 하고 고친다(r11 §4).
**되는데 결과물이 원하던 게 아니면**(예: 제목이 파일 안에 있었으면 좋겠다) **그건 R이다.** U19가 뒤집힌 것이고,
`SPEC.md` §2에 U19가 **먼저 적혀 있었으므로 적중**이다. 그 순간을 그날 바로 적는다.

### 2.4 «꺼내 쓴다»를 한 번 한다

r11 §2.1의 마일스톤 절반이 이것이다. 판정 기준은 **다른 작업 중에** 앱을 열어 복사 버튼을 눌러
실제로 붙여넣은 것. 앱을 확인하려고 누르는 건 데모라서 안 친다.

세션을 여는 조건은 하나다:

`--safe-mode`를 주지 않고, 평소 말투로 시킨다.

### 3.1 세션이 열리면 지킬 것 — 여전히 한 줄

```
★ SPEC.md 를 고쳤으면, 구현을 커밋하기 전에 SPEC.md 를 먼저 커밋한다 ★
```

오늘 `86d3f1e` → `d89fddc`가 8초 차이로 이걸 지켰다. 그대로 하면 된다.

### 3.2 세션이 안 열려도 된다

## 4. 사건이 나오면 — 그날 바로

`proj3/docs/usage/2026-08-09.md`(그 주 파일)에 한 줄 더한다. 형식은 r11 §5.

```markdown
- R/Q/F: <한 줄> → §2 적중(U번호) | 누락 | (F 아님: 라이브러리/환경)
```

**미루지 않는 이유**: `specHit`은 «`SPEC.md` 커밋 시각 < 사건 시각»에 전부 걸려 있다(r8 §4.1).
일주일 뒤 기억으로 복원하면 그 순서가 흐려지고, 흐려진 것을 유리하게 읽는 것이 r8 §8의 리스크다.

**애매하면 누락으로 센다.** 관찰자가 곧 사용자라서, 바라는 방향의 반대로 기울이는 것이 유일한 방어다.
