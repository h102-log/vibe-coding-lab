## 2. 첫 세션은 왜 `proj3` 세션에서 못 도나

r8 §3.1이 배포 형태를 **(가) 대상 프로젝트의 `CLAUDE.md`**로 확정했다. 즉 43줄은
**cwd가 `ai-prompt-vault`일 때만 로드된다.**

`proj3` 세션에서 대상 리포 파일을 원격으로 편집하면 로드되는 것은 `proj3/CLAUDE.md`(실험 규칙 문서)이고,
43줄은 **한 글자도 안 들어간다.** 그 상태로 쓴 `SPEC.md`는 관측 대상이 아니라 **그냥 다른 물건**이다.
r8 §4가 재려는 것이 «43줄이 로드된 상태에서 §2가 침묵 지점을 잡는가»이므로, 여기서 대신 쓰면 트랙이 무효가 된다.

**그래서 사용자가 새 세션을 열어야 한다. 대행할 수 있는 종류의 단계가 아니다.**

## 3. 첫 세션 절차

```bash
cd /c/Users/bhy99/proj/ai-prompt-vault
claude
```

`--safe-mode`를 **주지 않는다.** 실사용은 평소 환경 그대로다(r8 §2.1) — 글로벌 `CLAUDE.md`·플러그인·훅이
켜진 채로 재는 것이 이 트랙의 조건이고, 그래서 실험의 효과 크기는 여기로 이월되지 않는다.

### 3.1 첫 프롬프트 — **이대로만 준다**

> 프롬프트 **제목**과 **마크다운 본문**을 입력받아 리스트로 띄우고,
> 버튼을 누르면 **클립보드로 복사**되는 단일 페이지 웹 앱을 만들어줘.
> 저장은 localStorage로 충분해. 스택은 Vite + React (TypeScript).

### 3.2 **말하지 않는 것 — 채우지 않는 것이 설계다**

검색 · 태그 필터링 · DB 연동 · 수정/삭제 UX · 파라미터 입력창 · 정렬 · 내보내기

에이전트가 이 중 하나를 **먼저 물으면** 그건 **Q 사건이다**(r8 §4.1). 답해주되,
**그 순간을 기록한다** — 물어본 것 자체가 §2가 일한 증거다.
먼저 안 물었는데 나중에 필요해지면 그건 R 또는 F다.

### 3.3 세션 중 지켜야 할 것 하나

```
★ SPEC.md 를 쓴 그 세션에 커밋한다 ★
```

r8 §4.1: **커밋 시각 < 사건 시각**이어야 적중이다. 커밋 안 된 §2는 없는 것으로 친다.
사건이 터진 뒤 §2에 항목을 보태는 것을 막는 장치가 이것뿐이다.

## 4. 첫 세션이 끝나면

```
proj3/docs/usage/2026-08-03.md   ← 5줄 이내. 형식은 r9 §6 초안대로, 여기서 굳힌다
```

```markdown
# 2026-08-03
- R/Q/F: <사건 한 줄> → §2 적중 | 누락 | (F 아님: 라이브러리/환경)
- §2 누적: N개
- §4.4 신호: 없음 | <있으면 한 줄>
```

**애매하면 누락으로 센다**(r8 §10). 관찰자가 곧 사용자라서, 결과를 바라는 방향의 반대로 기울이는 것이 유일한 방어다.
사건이 0건이면 «0건»이라고 적는다. 안 적으면 분모가 조용히 줄어든다(r8 §8).

### 4.1 F로 세지 않는 것 (r9 §4.3)

`react-markdown` 줄바꿈 · 하이라이팅 누락 · 빌드/환경 문제 → **기록만.**
기준: **의도가 명확했는데 도구가 안 따라준 것은 F가 아니다.**
