«문안이 도달해 지시된 산출물이 나왔는가»의 판정이다.

## 1. 계측 사고 2건 (점수 아님, 앱 시드 복원 후 재실행)

1. **A 1차 — 출력 JSON 소실 (실험자 과실).** 백그라운드로 띄운 런이 완료 알림을 조기에 보내
   비어 있는 출력을 «완료»로 오독, 같은 `--session-id`로 전경 재실행을 겹쳐 걸었다. 전경
   프로세스는 «Session ID already in use»로 즉사했지만 리다이렉트(`>`)가 원문 JSON을 0바이트로
   truncate했다. 에이전트 세션 자체는 무오염(전경은 세션 등록 전에 죽음)이나 원문 없는 런은
   기록 불가 → 시드 복원(설정 3파일 diff 0 확인) 후 새 UUID로 재실행. **교훈: 런은 전경
   단독으로만 실행한다.**
2. **B 1차 — `permission_denials` 2건.** 에이전트가 cwd 밖 **이웃 디렉터리 `s1-tdd/`**의
   테스트 파일·package.json을 Read 시도(자가 배선 선례를 찾은 것으로 추정), acceptEdits에서
   거부됨. CLAUDE.md 무효 조건 그대로 무효 처리. 재실행은 변이된 `s2-dom/`을 원문으로 남기고
   **새 디렉터리 `s2b-dom/`**(seed 재복사·동일 조정)에서. 스모크 디렉터리가 나란히 있는 배치
   자체가 실측(exp*)에는 없던 접촉 경로를 만든다 — 다음 스모크 설계 시 참고.

## 2. 판정

### A. 대조 런 — «만들고 지움» (exp3 (b) 패턴 재현)

스킬 없는 에이전트는 `tests/_scratch.test.ts` 1개를 만들어 5/5 통과 확인 후 **지웠다**
(logprobe `testsWritten: 1, testsDeleted: 1`). 종료 상태 테스트 0개, 파일명도 일회용(`_scratch`).
**r17 §2-A의 사전 등록 해석대로: s1의 잔존은 과제 성격만으로는 설명되지 않는다 — 판정 기준
①은 정보를 담는다.** 과제 교체 불필요(§4-2 분기 미발생). 여기까지만 말한다 — n=1끼리의
비교는 효과 주장이 아니다.

### B. DOM 과제 런(s2b) — 기준 ①②③ 전부 충족

과제: 태그 입력 컴포넌트(`sent-s2.txt`), React+vitest+jsdom(= 주 용도 조건).

- **① 잔존**: 테스트 3파일 14케이스가 `src/`에 남았고 실제 실행 14/14 통과
  (`testsWritten: 3, testsDeleted: 0`). 파일명 전부 자기 설명적
  (`TagInput.enter-adds-trimmed-nonempty-unique-tag.test.tsx` 등).
- **② 요구 인용**: 각 파일 헤더가 과제 명세문을 그대로 인용하고 «이 저장소에는 SPEC.md가
  없어 과제 문장을 인용한다»는 분기 명시 — s1에 이어 DOM 조건에서도 참조 내부화의 조건
  분기가 의도대로 작동. 명세가 안 정한 구현 선택(«이 테스트가 고정하는 것»)까지 구분해 적었다.
- **③ 환경 의존 단언 0건** (Date.now·mtime·random·fetch류 grep).

관찰(판정 기준 아님, 기록만):
- **jsdom 자가 배선**: 에이전트가 루트 `vitest.config.ts`(jsdom) + `test` 스크립트를 스스로
  구성. 실측에서도 자체 테스트 러너는 항상 에이전트가 구성했으므로(exp4 `todo-eb/vitest.config.ts`
  등) 실측과 동일 조건이다.
- **Testing Library 쿼리**: getByRole 6·getByLabelText 4·getByText 10·queryByRole 3·queryByText 3
  — **접근성 쿼리가 사용됐다.** 단 REPORT5 §4-1(0건)과 동일 조건이 아니다: 실측에는
  `getByTestId` 위주의 AC 견본이 보였고 여기는 견본이 없다. §2 축 재료로만 둔다.
  (무효 B 1차도 getByRole 19회 — 같은 방향, 역시 기록만.)
- B의 자체 테스트는 `npm run build`가 타입체크하지 않는다(seed tsconfig가 `tests/` 미포함·
  `src/**/*.test.*` 제외) — 그래서 판정은 build 성공 추론이 아니라 vitest 실행으로 했다.

### C. 회수 런 — 찾고, 돌리고, 보존하고, 새 파일로 얹었다

변경 요구: truncate ellipsis 인자(`sent-s3.txt`), 새 세션, SPEC.md 없는 최초의 회수 관찰(r17 §1-3).

- **발견**: `ls -la` → `find -type f`(디렉터리 훑기) → **SPEC.md를 세 위치에서 능동 탐색 후
  부재 확인**. SPEC 인덱스 없이 파일명만으로 회수가 성립 — SKILL.md의 파일명 지시(r16 §3-1
  작업 2)가 겨눈 경로 그대로다.
- **실행**: 런 중 `npm test` 2회(케이스 추가 전후). 종료 후 전수 재실행 28/28 통과.
- **보존·확장**: 기존 3파일 무변경·삭제 0. 확장은 같은 파일이 아니라 **새 파일**
  (`truncate-custom-ellipsis-respects-max-and-surrogate-pairs.test.ts`, 10케이스) — 같은 명명
  규약을 따르고, 헤더에 확장 명세 인용 + «기본값 시절 요구는 기존 파일이 그대로 지킨다»는
  **기존 자산 상호 참조**까지 적었다. REPORT3(같은 파일 확장 3/3)과 다른 형태인데, 당시는
  SPEC 있는 조건이었다 — 형태 차이의 원인 분리는 스모크 범위 밖, 기록만.

### D. 문안 재독 — 수정 0건, 유예 2건 유지

- A~C에서 SKILL.md 문안이 원인인 실패·왜곡 없음. 실측 원문 2문장 그대로. **r16 1단계에 기록할
  수정 사유 없음.**
- 검토 유예 2건(r17 §1-4): ① 설치형 발동 시점 ② `name: tdd` 과발동 — **유예 유지.** 단 A~C는
  전부 주입식(frontmatter 포함 통째 주입, 설치형과 비대칭)이라 유예 판단의 재료는 «주입식에서
  문안이 의도대로 작동했다»는 간접 증거뿐이다. 이 재점검이 유예를 해소한 것이 아니다 —
  설치형 실측은 4단계(r16 §3-4) 그대로.

## 3. 부수 기록

1. **seed 사본 조정 내역(s2-dom·s2b-dom 공통)**: `node_modules`·`tests/` 제외 복사,
   `test:ac` 스크립트 제거, `App.tsx`의 «implement the todo app» 문구 중립화, name 필드 변경.
   제외 사유는 (a) r17 §2-B «동결 계약 재사용은 해석만 흐린다» — todo AC가 곧 todo 계약 (b)
   실무: vitest 기본 include가 AC 테스트를 잡아 스타터 앱에서 실패를 쏟아냄. (절대 규칙 4는
   동결 **원본**을 프롬프트 투입물로 주지 말라는 것 — 실측 런에서 앱 내 AC 사본은 에이전트에게
   보였으므로 제외의 근거가 아니다. «실측 검증된 스택 그대로»에서 AC 하네스 제거만큼은 이탈이며
   스택 자체는 동일.)
2. **logprobe 특이점**: `ownTestTrace`가 s1·C 세션에서 «실행실패»로 찍히나 실제로는 통과
   (28/28 재확인) — AC 없는 컨텍스트의 출력 형식을 파서가 못 읽는 것. exp3/logprobe.mjs는
   수정 금지(절대 규칙 1·3) — 프레임워크 전용 계측이 필요해지면 `framework/`로 **복사**해서.
   `testsWritten`/`testsDeleted`/`testFiles`는 기지 s1 세션으로 사전 검증했고(3·0·파일명 일치) 정상.
3. **다음 스모크를 위한 실무 교훈**: 런은 전경 단독 실행(§1-1) · 재실행은 새 디렉터리(§1-2) ·
   스킬 주입 런의 종료 상태 테스트 0개는 즉시 무효가 아니라 logprobe로 «안 만듦»(무효·재실행)과
   «만들고 지움»(기준 ① 실패 — D의 최우선 재료)을 먼저 가른다.
