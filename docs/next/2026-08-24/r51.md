# r51 — KF4 R4: 볼륨 임계 Warning + 저장 mute 소비 (5개 KF 전부 종료)

별도 지시서 없이 계획서 2장을 직접 집행했다 — `docs/next/2026-08-19/plankf4ruleset.md` §5 R4(WBS 소유)와
`docs/next/2026-08-19/plankf5volume.md` §4-4(값 계약). 선행 조건(KF5 R1·R2 = r50, KF2 R1 = r43)은
전부 충족돼 있었다. **이 라운드로 KF1~KF5의 모든 라운드가 닫혔다**(KF5 R3만 실사용 조건부로 남는다 — r50 §7).

## 1. 만든 것

| `framework/spec-interview.mjs` | 224→265줄 | `readMuted()` export(`.specgate.json` `interview.mute`) · stats에 `muted` 필드 + 저장 범주의 권장 억제 · report 1줄 · selftest T13~T15 |

`hooks/spec-gate.mjs`·`specprobe.mjs`·`spec-verify.mjs`는 **한 글자도 안 고쳤다** — 훅은 Error만 내고
volume은 verify 랩 층에서만 판정하므로 손댈 이유가 없는 것이 곧 «차단 승격 금지»(조사 Q4)의 구조적 증거다.
specprobe는 여전히 임계를 모른다 — `probe` 서브커맨드 패스스루도 그대로다(T10 무변경).

## 2. 계획서가 비워둔 것을 이 라운드가 정한 6건

1. **`.specgate.json` `volume` 스키마 = 평평한 3키.** `{"volume":{"activeSentences":30,"inferenceRatio":0.5,"tableRows":80}}` —
   키 이름은 probe 필드명을 따르고 `activeSentences`는 total(S+I+U)의 임계다. SG1034는 수치 임계가
   없으므로(조건 = SG1031 발동 중 ∧ 후보 ≥ 1) 키도 없다. 미지 키는 조용히 무시한다(전방 호환).
2. **깨진 임계 값은 «기본값 + 통지»다.** 숫자가 아닌 값은 `구성 무시: volume.<키>는 숫자가 아니다`
   한 줄을 내고 기본값으로 판정한다(T23) — 임계가 조용히 바뀌는 것도, 깨진 값이 조용히 무시되는 것도 안 된다.
3. **`interview.mute` 로더는 spec-interview.mjs에 뒀다.** specgate의 `loadConfig`를 import하면 그쪽 정적
   사슬(spec-verify·spec-delta·spec-anchor)이 통째로 딸려온다 — 읽을 것은 JSON 한 파일이라 20줄 로더가 싸다.
   규약 밖 값(0·11·문자열)은 걸러지고 중복은 접힌다(T14). 저장된 범주는 `muteSuggest` 권장에서도 빠진다 —
   권장은 «저장할까»라는 질문이고 이미 답이 있다(T13이 T8과 같은 시드로 차분을 증명).
4. **verify는 probe()를 부르고 inspect() 중복 1회를 감수한다.** KF5 §4-4의 계약이 «verify가 probe()를
   읽어 발행»이다 — 파생 로직(S/I/U 분해·ratio)을 verify에 복제하면 두 곳이 갈라질 수 있는 자리가 생긴다.
5. **볼륨 Warning은 기존 mute 메커니즘을 그대로 탄다.** SG1031~1034가 Warning이므로 `{"mute":["SG1034"]}`가
   추가 코드 0으로 작동한다(applyMute는 룰 ID만 본다 — T5가 이미 그 층을 덮는다).
6. **T1~T3a(픽스처 6장 대조)는 무변경으로 뒀다.** 집행 전에 6장의 볼륨을 실측했다 — 최대 total 18 ·
   tableRows 54 · ratio 0(F3은 ID 없음·결측). 기본 임계에 전부 미달이라 V 경고가 안 뜨고 기존 대조가
   그대로 성립한다. 픽스처는 동결이라(절대 규칙 6) 이 전제는 안 움직인다.

## 3. 실물 대조 (`framework/smoke/i1-cart-r1/SPEC.md` 사본 — 스크래치패드, 원문은 읽기만)

```
기본 임계:            SG1006 · SG1032([추론] 비율 0.621 > 0.5)          → Error 0 · Warning 2 · exit 0
임계 조정(0.7 · 30):  SG1006 · SG1031(활성 39 > 30, S11·I18·U10) · SG1034(후보 28건) → Warning 3 · exit 0
```

- 수치 전부 r50 §3의 육안 대조값과 일치한다(total 39 = 접기 점검 전 값 아님 — 원문 39문장 그대로).
- **실물 SPEC이 기본 임계에서 이미 SG1032를 밟는다.** r50 §5-3이 예고한 역방향(접을수록 ratio가
  오른다)의 시작점이 0.621이다 — 실사용에서 SG1031을 끄려는 접기가 SG1032를 못 끈다는 것이 실물로 보인다.
- 두 실행 모두 exit 0 — Warning은 판정이 아니다(계약 유지).

SG1034의 조건부(후보 3건이 있어도 SG1031 없이는 안 뜬다)를 같이 잡는다.

## 5. 한계

1. **경고가 리뷰 행동을 바꾼다는 실측은 여전히 0이다**(KF5 §9-8). 이 라운드는 «형태»를 닫았을 뿐이고,
   Warning을 에이전트·사람이 소비하는지는 실사용 2회차 관측 항목이다.
2. `/spec`의 「있으면」 분기는 여전히 `spec-verify`(원형)를 부른다 — SG 번호·볼륨 경고를 에이전트가
   한 줄 포맷으로 받는 경로는 CI와 수동 실행뿐이다. 문안 교체는 §6 선택 대기로 남겼다.
3. `interview.mute` **쓰기** 경로는 문안 1줄(Edit + 승인)뿐이고 기계 검증이 없다 — 잘못 쓴 JSON은
   다음 stats에서 muted가 비는 것으로만 드러난다(T15의 무해성이 하한선).
4. SG1032의 임계(0.5)와 SG1031의 임계(40)는 반대로 움직인다(§3 실물·r50 §5-3) — 임계 조정은 실사용에서
   쌍으로 봐야 한다(KF5 §10 #1~#3은 그대로 열려 있다).
5. volume 블록의 미지 키 무시는 오타를 침묵시킨다(`activeSentence` 오타는 기본값 40으로 조용히 동작).
   통지 대상을 아는 키의 깨진 값으로 한정한 대가다.
