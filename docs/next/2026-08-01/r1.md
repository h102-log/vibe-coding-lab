# 완성 조건 & 비교실험 설계 — r1

**상태**: draft. 2절의 세 항목은 Claude가 제안한 기본값이고 아직 확정 안 됨.
**관련**: [docs/thoughts/2026-08-01-완성조건-정하기.md](../../thoughts/2026-08-01-완성조건-정하기.md) — 이 문서가 나온 대화 원문.

## 1. 완성 조건

> 동일한(또는 거의 동일한) 프롬프트로, (a) 프레임워크 없이 맨 Claude Code로 만든 산출물과 (b) 이 프레임워크로 만든 산출물을 같은 평가 항목으로 채점한 비교 리포트가 나오면 완성.

프레임워크만 만들고 끝내는 게 아니라, 없을 때/있을 때를 비교한 결과물까지 나와야 완성으로 친다.

## 2. 비교실험 설계 (기본값 — 확정 필요)

### 2.1 비교 대상: 할일 목록(Todo) 앱

인증·결제처럼 판정이 애매한 영역이 없는 순수 CRUD. AC를 결정론적으로(Playwright/vitest exit code) 걸기 쉬운 범위라 선택.

### 2.2 두 그룹

- **(a) 베이스라인** — 프레임워크 없이, 맨 Claude Code로 제작.
- **(b) 처치군** — 이 프레임워크(TDD 강제 + SDD + 페이즈 분할)를 적용해 제작.
- 최초 사용자 요청 프롬프트는 두 그룹 동일하게 유지.

### 2.3 평가 항목 (5개 이내로 동결)

1. AC 충족 개수/비율
2. 테스트 존재 여부 + 커버리지
3. 완료까지 걸린 턴수/토큰(비용)
4. 재작업(수정 요청) 횟수
5. 린트·빌드 통과 여부

코드 가독성 등 정성 평가는 뺀다 — 결정론적 항목만으로 시작 (Gate/Advisory 분리 원칙과 동일한 이유).

### 2.4 한계

n=1 비교. 통계적 유의성을 노리고 반복 실행하는 건 의도적으로 하지 않는다 — 지금 목적은 "완성"이지 "논문급 실증"이 아니다. 최종 리포트에 "n=1, 재현성 미검증"을 명시한다.
