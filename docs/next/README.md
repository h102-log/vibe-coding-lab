# next/

**작업 세션 하나 = 문서 하나.** "지금까지 뭘 했나 → 결정해야 할 것 → 다음 단계"를 적는다. 다음 세션을 이거 하나만 읽고 시작할 수 있게 쓰는 게 목적.

## 이름 규칙

`YYYY-MM-DD/rN.md` — `N`은 리비전 번호로 날짜를 넘겨서도 이어진다 (`2026-08-01/r1.md` → `2026-08-02/r2.md`). 각 문서는 맨 위에서 이전 rN을 링크한다.

## 결번·번호 충돌 (2026-08-14)

리포 밖(원격 컨테이너)에서 개정된 sdd 계획 계열이 r20(v2)·r21(v3)·r22(v4) 번호를 썼고, 그중
v4만 `2026-08-14/r22.md`로 반입됐다. 경위와 판정은 `2026-08-14/r23.md`.

- **r21 = 결번(예약)** — sdd 계획 v3, 리포 밖. 반입 수요가 생기면 r23 §3-3의 2커밋

  그 전까지 기본값은 비반입이다(r23 §3-2).
- **r20** — sdd 계열 v2가 예약했던 번호이지만 verify-tdd 작업계획서가 먼저 채택했다
  (`2026-08-14/r20.md` 채택 노트, `feat/framework-v01-verify-tdd` 브랜치). v2를 반입할 일이
  생기면 새 번호로 채택한다(r20 채택 전례).
- **r19** — 결번이 아니다. `2026-08-13/r19.md`(sdd 계획 원본)로 커밋돼 있고, 그 결정은 r22
  §1·§5-1에 흡수됐다(r22 §0-3-3).

## 구조

```
1. 지난번에 한 것      — 산출물 표 + 설계 결정과 근거
2. 결정해야 할 것       — 선택지·트레이드오프·권장안. 답이 없으면 다음으로 못 감
3. 다음 단계           — 각 줄에 "→ 검증: 무엇으로 확인하나"
4. 열어둔 리스크        — 알고 감수한 것
```

## 여기 적지 않는 것

확정된 실험 설계. 그건 `exp/FROZEN.md`로 간다. rN은 **결정에 이르는 과정**이고 FROZEN.md는 **결정된 결과**다. 둘이 어긋나면 FROZEN.md가 이긴다.
