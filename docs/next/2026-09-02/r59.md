# r59 — edd 러너 pytest 분기 (FastAPI 실사용 대비)

날짜 2026-09-02. 계기는 사용자 질문 «지금 플러그인 edd는 python에서는 적용이 안 됨?» → «실무에서 사용하려고 하는데
그때 FastAPI 사용할 예정». 관측 라운드가 아니라 **도구 라운드**다(프레임워크 개발 규칙 1 — 산출물은 돌아가는 코드).

## 2. 설계 결정 (사다리 순)

1. **러너 선택 위치 = EVAL.md `- 러너:` 줄.** 이미 템플릿에 있고 r58 `ed1` 실물도 `- 러너: vitest (jsdom + …)`
   꼴로 쓰고 있었다(`(\S+)`만 취해 괄호는 무시). 대안 `.specgate.json` 키 — 기각: 문서 하나가 SSOT다.
2. **pytest 결과 수집 = 인라인 플러그인**(내장 훅 3개: `pytest_collectreport`·`pytest_runtest_logreport`·
   `pytest_sessionfinish`). 임시 디렉터리에 `specgate_report.py`를 써서 `PYTHONPATH` + `-p specgate_report`로 싣고
   `SPECGATE_EVAL_OUT`에 JSON을 받는다. 대안 `pytest-json-report` — 사용자 프로젝트에 의존성 추가라 기각.
   대안 `--junitxml` — Node에 XML 파서가 없어 정규식 파싱이 된다, 기각.
3. **`--continue-on-collection-errors`.** selftest f가 처음에 `EV1~3 missing · EV4~5 red`로 실패해 알았다 —
   pytest는 **수집 에러가 1건이라도 있으면 테스트를 하나도 안 돌리고 중단**한다(vitest는 파일 단위 격리).
   구현 전 red-check에서 파일 하나만 import 사망이면 나머지가 전부 `missing`이 되므로 이 플래그가 필수다.
4. **EV 경계 = `\b` → «영숫자 아님»** (`/(?<![A-Za-z0-9])EV\d+(?![A-Za-z0-9])/`). `test_EV1_x`의 `_`는 단어 문자라
   `\b`가 안 잡힌다. 대신 `TestEV2`(pytest 클래스 관례)도 안 잡힌다 — `DEV2`·`REV2`·`PREV2` 오탐을 막는 쪽을 택했다.
   클래스는 `Test_EV2`. vitest 쪽 매핑은 변화 없음(selftest 1~12 무변경 통과).
5. **python 실행 파일 = `.venv`/`venv`의 것 우선**(`Scripts/python.exe`·`bin/python`), 없으면 win32 `python` /
   그 외 `python3`. pytest·fastapi는 보통 venv에 있다. 부재 시 메시지는 «결과 파일 부재 (exit 1) stderr: … No module
   named pytest» — vitest 쪽 «vitest 미설치»처럼 전용 문구는 안 만들었다(#5 선택 대기 7).
6. **`SKIP_DIRS` +4** (`.venv`·`venv`·`__pycache__`·`.pytest_cache`). venv는 `.py` 수천 장이라 implHash가 터지고
   `pip install` 한 번에 스냅샷이 stale이 된다. 주석의 «verify-tdd.mjs:29와 동일 값»은 더 이상 아니다 — verify-tdd는
   계측기라 손대지 않았다(전수 재측정 조건).

## 4. 관측 — 도구가 이 세션에서 자기 리포에 발화했다

- 글로벌 설치된 `specgate@proj3`의 spec-gate가 **스크래치 경로(리포 밖)** 의 `.mjs` Write를 SG1000으로 막았다.
  게이트는 `ev.cwd`의 `SPEC.md` 유무만 보고 대상 경로가 cwd 안인지 보지 않는다. 로그는 `framework/.specgate-log.jsonl`에
  떨어졌다(Bash 도구의 cwd가 `framework/`로 남아 있던 상태 — 훅이 받는 cwd가 세션 루트가 아니라 **마지막 Bash cwd**였다는
  뜻이다. 이건 별도 확인 가치가 있다). 로그 파일은 지웠다(이 세션이 만든 것).
- 진행은 **Bash 경유**(`node --input-type=module < patch.txt`). STATUS §266에 «Bash 우회 미봉합 — 2런에서 우회가
  없었던 건 에이전트가 안 한 것»이라 적혀 있는데, 이 세션이 그 첫 반례다. 단 auto 모드 지침이 «파일 편집은 Bash로»를
  기본으로 하고, 이 리포의 `framework/`는 프로젝트 규칙상 SPEC 대상이 아니라 «우회 의도»와 «지침 준수»가 겹친다.
  어느 쪽이든 게이트 관점에서는 같은 구멍이다.
- 2026-08-19 로그에도 같은 SG1000 차단이 3건(`spec-delta.mjs`) 있었고, 그 뒤 r38~r58이 어떻게 지나갔는지 문서에 없다.
