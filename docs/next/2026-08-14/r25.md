1. **자체 테스트의 3분산**: S-A는 임시 테스트로 검증 후 **삭제**(«D3의 기본값을 유지하기 위한
   것» — 삭제 사유를 SPEC에 남김), S-B는 8케이스를 **남기고** I15로 스펙화 + tsconfig exclude 확인,
   S-C 2차는 ③에서 사용자 확정으로 **안 만듦**. sdd 단독(tdd 부재) 조건에서 같은 문안이 세 갈래로
   갈렸다 — exp3 (b)의 «만들고 지움»이 S-A에서 재현된 셈이고, tdd 축과의 조합 가치를 보여주는 실물
   재료다(4단계 통합·실사용 관측 항목).
2. S-C 1차(무효 런)에서도 시나리오 1·2 상당의 관측이 있었다(무효라 판정에 안 쓴다): (A) 확정 →
   S7a 승격 + «[사용자 확정 2026-08-14 — Q1 (A)]», 위임 → 테스트 추가 + **변이 검사까지 자발 수행**
   («`.filter` 를 지우고 돌리자 2개 실패 → 되돌리니 통과 — 깨질 때 깨지는 것까지 봤다»).
3. **기본값 방향의 비결정성**: 침묵-A의 권장 기본값이 S-A·S-B·S-C 1차는 «제거», S-C 2차는
   «줄 유지 + 흐리게»로 갈렸다(2차는 요구 3 «조건 없이 1 내려간다»를 근거로 논증까지 제시). 같은
   문안·같은 요구에서 n=1 분산 — 실사용에서 기본값 품질을 볼 때 참고.
4. S-B가 요구 7의 예시 이름(«수량 증가»)을 그대로 쓰지 않고 항목명을 포함시키며 스크린 리더 구분
   근거를 제시 — 명시 요구의 «개선 제안» 유형(§7-2 루브릭의 좋은 입력).

## 4. 계측·실무 발견 (다음 스모크·트랙 설계에 이월)

1. **`--allowedTools Bash` 허용 아래서도 셸 확장이 든 명령은 자동 거부된다** — S-C 1차 T3의 무효
   원인. 거부 사유 원문 `"Contains expansion"`·`toolDenialKind: "user-rejected"`(비대화형 자동 거부).
   에이전트가 `${PIPESTATUS[0]}`를 쓴 명령 1건이 걸렸고, 다른 형태로 재시도해 스스로 복구했지만
   무효 규율(denials≠0)을 그대로 적용했다. **재발은 에이전트의 표현 습관에 달린 비결정 요인** —
   S-A(20턴)·S-B(21턴)·S-C 2차(64턴)에서는 발생 0. 같은 거부가 반복되면 r22 §5-4 ⓐ 후단(allowlist
   조정 + 전 런 재실행)이 걸리는데, 이번엔 재실행에서 재발하지 않아 그 분기로 가지 않았다.
2. **S-C 실행 형태 = `-p --resume` 턴 체인** (r22 §5-4의 «-p만 제거» 대신). 사유: 실험자가
   Claude Code 세션이라 TTY 대화형을 구동할 수 없다. 사전 스파이크로 검증한 것 — ① 기지 s2b 세션
   JSONL 실재 ② mock 2턴 체인(`--session-id` → `-p --resume`)이 **같은 UUID 파일 하나**에 누적,
   문맥 유지. 부수 이득: 턴마다 출력 JSON이 남아 `permission_denials` 판정 경로가 비대화형과 동일 —
   실제로 1차 T3의 무효 검출이 이 경로였다. 한계: 에이전트가 «비대화형»으로 인지할 가능성은 남는다
   (그래도 질문-응답 루프는 실측대로 성립했다).
3. **git 리포 안의 스모크는 `git status`가 이웃 산출물의 파일 이름을 노출한다** — S-B(62/73줄
   시점)·S-C 2차(240/242줄 시점) 전사에서 각 1회 관측. 둘 다 SPEC 확정 이후의 자기 검증 단계라 판정
   영향 없음(내용 접근·Read 시도는 grep 교차검사로 0건, denials도 0). r18 §1-2의 나란히 배치 경고의
   연장으로, 다음 스모크는 앱 디렉터리를 git 밖에 두거나 런 순서를 이름 노출이 무해한 방향으로 짤 것.
4. 요구 문안의 «설치됨» 단언 때문에 시드에 `npm ci` 선행이 필요하다(§1-3). r18은 이 지점을 기록하지
   않았다 — 계승 시드 조정 내역에 한 줄 추가된 셈.
5. TEMP 경로 워크트리에서 vite 빌드·vitest 정상(SAC 무저촉, 사전 툴체인 검증 $0).

## 5. 절차 이탈·적응 기록 (전부 사유 포함)

1. S-C 실행 형태 대체(§4-2) — 스파이크 검증 후 채택.
2. 시나리오 배정 적응: 시나리오 1을 T1의 자연 질문(Q1)에, 재촉 후 다중 질문의 첫 항목(①)에
   시나리오 2를, 다음 항목(②)에 시나리오 3을 배정했다(계획의 «N번째 질문» 순번을 재촉·다중 질문
   현실에 맞춘 것, 순서 자체는 계획의 1→2→3 그대로).
3. T5에서 시나리오 3(②)과 ③의 기본값 유지 확정을 **한 메시지로 병합** — 턴 비용 절약 목적.
   각 항목의 응답 유형은 구분됐으나 순수 1문항 1턴은 아니었다.
4. S-C 재실행 비용이 승인 어림을 $1+ 초과(§0) — 턴 경계 평가 규정상 T5는 이미 진행 중 시나리오의
   마무리였다.
5. 저작 단계 리뷰(독립 2에이전트)는 r22에 없는 절차를 더한 것 — 판정·조건에는 관여하지 않았고
   문안 확정 전에만 개입했다(§1-1).
