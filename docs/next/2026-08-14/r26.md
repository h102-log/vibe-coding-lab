## 2. 지표 판정 (r24 §3 사전 등록 그대로)

### A 일치 — **4/4 (대조 가능 전 라운드 일치)**

pass·pass·pass·none. run-error 0건이라 «대조 제외» 없음. 특기: e2b-tdd는 에이전트가 별도
`vitest.config.ts` 없이 **vite.config.ts에 test 블록을 내장**한 배치 변주였는데, 스크립트의
독립 임시 config 실행(고정값 5개)이 자체 배선 결과와 동일(17/17) — 실행 전략이 앱 설정
변주에 흔들리지 않는다는 실물 근거 1건.

### B 미탐 — **0건 (노출 있음 → 검증됨)**

- 노출: e1-ctrl `tests/textkit.test.ts` = 인용 없는 테스트 파일 1건(그라운드 트루스 확정).
- 스크립트가 flags:1로 검출 — **미탐 0.** 열거 누락 0, 헤더 오추출 0(무관 주석을 헤더로 승격한
  사례 없음).
- **e1-tdd 3건의 분류 근거 (이 평가에서 가장 판정이 갈릴 수 있는 지점)**: 세 파일 모두 요구
  인용 주석이 실재하지만 위치가 **import 2줄 뒤**다. §2.3의 B 미탐 정의는 «실재 **선두** 헤더의

  정의된 동작이지 오추출이 아니다. 따라서 §2.3의 오탐 정의(«헤더 부재 플래그가 재확인 결과
  헤더 실재») 쪽에 해당한다 — **오탐 3건.** (인용의 의미 판정이 아니라 «주석 실재»의 재확인
  이므로 정확도 지표 산입이 맞다.)

### B 오탐률 — **3/4 (75%, 과반) → 실용성 감점 기록**

플래그 4건 중 진성 1(e1-ctrl)·오탐 3(e1-tdd). §3 그대로 채택에는 영향 없음(«기록만» +

## 3. 채택 판정 (§3 사전 등록 문장 적용)

- **채택**: A 전 라운드 일치(4/4) + 노출된 검사(B)의 미탐 0 → **verify-tdd는 tdd 산출물
  판정의 1차 도구**. 범위는 «tdd 산출물 판정»뿐(§6-7 — sdd·edd 산출물은 별도 도구의 몫).
- **육안 축소의 범위**: 미탐이 실제 검증된 **B만** «플래그 + 재료 재확인»으로 축소 가능.
  **C·D는 «오탐 방향만 검증됨» — 육안 전수 유지**, 이후 실전(full 스모크·실사용 2회차)에서
  자연 발생 위반의 미탐 0이 확인되는 시점에 축소 전환(§3 그대로).
- A는 hard 판정으로서 4/4 — 스모크·실사용에서 A의 실행·집계를 스크립트에 맡긴다.
- 평가 중 스크립트 수정은 [out-dir] 인자 추가 1건뿐(판정 로직 무변경, §0-④ 불변 재검) —
  §5의 «결함 수정 → 재실행» 경로는 발동하지 않았고, §3의 «수정판 새 표본» 조항도 해당 없음.
- **한계 (r24 §6-2 그대로): 단일 실험자·비맹검이다.** 같은 실험자가 선판정과 대조를 다 했고,
  방어는 선기록 커밋 하나뿐이다 — 이것은 순서 조작만 막지 인지 편향은 못 막는다. 특히 이
  평가의 실험자는 계측기를 이전 세션에 직접 만든 당사자라, 세션 내 미열람이 패턴에 대한
  사전 지식까지 지우지는 못한다. §2.2-3의 «정의 기준 통독»(C를 SKILL.md 문안으로 판정)이
  패턴 공유 오염의 방어였고, 육안 판정 기록(human-*.md)에 근거를 남겨 사후 검증 가능하게
  한 것까지가 이 평가가 한 방어의 전부다.

   않는다** — 판정 로직 변경은 §6-4 절차(사유 + patternListVersion)와 새 표본을 요구하므로
   수요가 다시 생길 때(full 스모크) 일괄 검토.
3. **«Contains expansion» 무효 라운드 3회 누적**(e2-tdd·e2-ctrl + sdd S-C 1차; denial
   건수로는 1+2+1=4건) — 에이전트가 `${PIPESTATUS[0]}`·`$?`를 echo하는 관용구를 쓸 때마다
   라운드가 무효가 된다. 런 규약 차원의 대응(예: 프롬프트에 «빌드 종료 코드는 별도 실행으로
   확인» 문구)은 **처치 오염**이라 기각하고, 무효-재실행 비용(라운드당 ~$0.4~0.9)을 계속
