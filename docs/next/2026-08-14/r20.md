## 0. 왜 만드는가

1. **판정이 수동이다.** 스모크 판정 기준 ①(잔존·실행)·②(요구 인용)·③(환경 의존 단언)을
   지금까지 매 런 육안 + 수동 grep으로 했다(r16 §3-1 «육안 확인», r18 §2-B «grep»).
2. **같은 판정이 반복될 자리가 정해져 있다.** full·설치형 스모크(r16 §3-4단계)와 실사용 2회차
   관측, 그리고 향후 tdd 재스모크가 동일한 tdd 산출물 판정을 요구한다. (초안의 «남은 스모크
   전부»는 과대였다 — sdd·edd 단독 스모크의 판정물은 SPEC.md·평가 파일이지 tdd 산출물이
   아니다. r16 §3-2단계·3단계.)
3. **계측기 재사용 경로가 이미 지정돼 있다.** `exp3/logprobe.mjs`는 AC 없는 컨텍스트의 vitest
   출력을 오독한다(r18 §3-2, `ownTestTrace` «실행실패» 오탐). exp*는 동결이라 수정 불가 —
   프레임워크 쪽 계측은 `framework/`에 새로 짓는다.
4. **차별점이 된다.** 2026-08-14 오픈소스 조사(deep-research, 9개 프로젝트 검증) 결과, **조사
   범위에서** 유사 목적 도구 중 자기 평가 장치를 가진 곳이 0곳이다. «스킬 16줄 + 검증 하네스»가
   한 세트일 때 이 스킬의 유일성(실측 근거 보유)이 물건으로 성립한다.

## 2. 요구사항 — 검사 4종 + 실행

| 검사 | 스킬 지시 대응 | 판정 방식 | 자동화 수준 |
|---|---|---|---|
| **A. 잔존·실행** | «지우지 마라» | 자체 테스트를 **내용 기반**으로 열거(`expect(` + `it(`/`test(`; 제외는 `tests/ac/`·`node_modules`·`dist`·`.git`·`coverage` — 정의는 FROZEN2 §4.2의 실행기와 동일, 교훈은 REPORT2 §5.2-1: 파일명 규약 의존 금지) → vitest `--reporter=json --outputFile`로 실행 → 파일/케이스 수·통과/실패 | **hard** (자산 0개·실행 불능·케이스 실패를 구분해 보고) |
| **B. 요구 인용** | «지키는 요구를 파일 안에 적는다» | 파일 선두 주석 존재(블록 `/* */`·연속 라인 `//` 모두 인정). **선두 판정에서 빈 줄·shebang·지시어성 라인(`// @ts-*`·`/// <reference`·`@vitest-environment` 독블록·`"use client"` 류)은 건너뛰고 그다음 첫 주석 블록을 헤더로 본다** + SPEC 참조/인용 흔적 검사(파일 전체) → 헤더 원문을 추출해 함께 출력 | **flag** — 인용의 의미 판정은 사람이 한다. 기계가 확정하는 것은 «선두 헤더 부재»라는 **사실**까지다 — 스킬 문안은 «파일 안에 적는다»라 위치를 특정하지 않으므로, 헤더 부재는 지시 위반 확정이 아니라 사람 확인 트리거다 |
| **C. 환경 의존 단언** | «환경 의존 단언 금지» | 패턴 매치: `Date.now(`·인자 없는 `new Date(`·`Math.random(`·`fetch(`·`XMLHttpRequest`·`fs.stat`/`mtime`·`performance.now(`. 단 `vi.useFakeTimers`·`vi.setSystemTime`·고정 인자 `new Date("…")`는 **완화 장치이므로 제외**. 매처는 **패턴별 식별자 경계 정규식 상수**(예: `(?<![\w$])fetch\s*\(`) — 선행 문자가 식별자면 제외해 `prefetch(`·`refetch(` 오탐을 없애고, `.`·공백 선행은 매치해 `globalThis.fetch(`·`window.performance.now(` 수식 접두를 그대로 잡는다. `mtime`은 후행 경계를 두지 않아 `mtimeMs`도 잡는다. 주석 안 매치(라인 선두 `//`·블록 주석 내부, 보수 휴리스틱)는 버리지 않고 `inComment: true`로 **강등해 함께 출력**하고, flags 카운트는 비주석 매치만 센다. 매치 라인 원문(`text`)을 함께 기록한다 | **flag** — 오탐 전제, 사람 최종 확인. 구조 분해(`const { now } = Date`) 같은 우회는 기지 미탐으로 남긴다(§6-4). 패턴 리스트는 스크립트 상수로 버전 관리. **v1로 박제되는 시점은 첫 verify 기록이다** |
| **D. 파일명 자기설명** | «파일명이 지키는 내용을 설명» | 전체 파일명 목록 출력 + 제네릭 이름 디나이리스트(`_scratch`·`tmp`·`temp`·`check`·`test1`·`foo`…) 플래그 | **flag** — 자기설명성 판정은 사람. 스크립트는 명백한 일회용 이름만 지적 |

A만 hard이고 B·C·D가 flag인 이유: 의미 판정을 기계 규칙으로 확정하면 규칙이 곧 처치의 사실상
정의가 되어버린다(잡히는 것만 지키게 됨). 특히 **B를 hard로 올리면 «선두 헤더»라는 휴리스틱이
스킬 문안(«파일 *안에* 적는다» — 위치 미특정)보다 좁은 규칙을 사실상의 정의로 만든다.**
스크립트의 역할은 **사람 판정의 재료를 빠짐없이, 같은 방식으로 뽑아주는 것**까지다.
(C의 주석 매치를 삭제가 아니라 강등으로 처리하는 것도 같은 원칙 — 숨기지 않고 분류만 한다.)

**A의 hard는 «판정 확정»이지 «게이트»가 아니다**(v5 명시) — A가 `"fail"`이어도 종료 코드는 0이다(§3).

## 3. 산출물·인터페이스

- **파일**: `framework/verify-tdd.mjs` — 단일 파일 node 스크립트(`judge.mjs` 스타일), 의존성
  추가 없음. (**§7-1 확정**)
- **사용**:
  - `node framework/verify-tdd.mjs <app-dir> <label>`
    → `framework/smoke/runs/verify-<label>.json` + 콘솔 사람용 요약 (**§7-3 확정**)
  - `node framework/verify-tdd.mjs --selftest`
    → §4 음성 픽스처를 OS 임시 디렉터리에 생성·실행·판정 (**v5 신설**, §4)

- **종료 코드 — 판정을 싣지 않는다** (v5 신설, §7-2 확정의 일부):
  `0` = 판정 산출 완료(**A가 `"fail"`이어도 0**) · `1` = 계측 실패(`run-error`) · `2` = 사용법 오류.
  판정은 전부 JSON 안에만 있다. **근거**: 리포의 실물 계측기 2개(`exp3/judge.mjs`·
  `exp3/logprobe.mjs`)에서 `process.exit`는 usage(2) 한 곳뿐이고 판정은 JSON + stdout으로만
  나간다 — 같은 규율의 계승이다. **목적**: §6-7(게이트화 유혹)의 **구조적 차단**. `&&`로 물릴
  종료 코드가 없으면 게이트화는 «유혹»이 아니라 **개조**가 되고, 개조는 눈에 띈다.
- **최상위 불리언 금지** (v5 신설): JSON 최상위에 `ok`·`success`·`pass` 류 필드를 만들지
  않는다. 만드는 순간 그게 게이트다. `judge.mjs`의 verdict에도 없다(`gateAC` 문자열·
  `regression`·`acRunOk`뿐 — 실물 확인).
- **B·C·D는 A와 독립으로 산출한다** (v5 신설): 헤더·패턴·파일명은 정적 검사이므로 vitest 실행
  결과와 무관하게 채운다. A가 `"run-error"`(§3 고정값 4·5 발동)여도 B·C·D 재료는 JSON에 남는다.
  **부수 이득**: 음성 픽스처 ①②③이 `node_modules` 없이 검증된다(현재 픽스처 4앱 전부
  `node_modules` 미설치 실측 — §5-5의 `npm ci`가 필요한 것은 **A 검사와 음성 ④뿐**).

- **JSON 스키마 초안**:
  ```jsonc
  {
    "label": "…", "appDir": "…", "when": "ISO8601",
    "patternListVersion": 1,                 // C 패턴 상수 버전
    "vitestVersion": "4.1.10",               // 앱 로컬 vitest (node_modules/vitest/package.json)
    "testFiles": [{ "path": "…", "cases": 7, "passed": 7, "failed": 0,
                    "header": "…원문…", "headerPresent": true,
                    "envFlags": [{ "line": 12, "match": "Date.now(",
                                   "text": "…매치 라인 원문…", "inComment": false }],
                    "nameFlag": null }],
    "totals": { "files": 4, "cases": 28, "passed": 28, "failed": 0 },
    "runOk": true,          // vitest 실행 자체의 성공 여부 (계측 실패 구분 — judge 규율).
                            // 자산 0개면 실행이 없으므로 true로 두고 A가 "none"을 든다
    "runError": null,       // A가 "run-error"일 때만 사유 문자열
                            // (예: "vitest 미설치 — §5-5 npm ci 선행" | "타임아웃 120s — 프로세스 그룹 SIGKILL")
    "verdict": { "A": "pass",   // "pass" | "none"(자산 0) | "run-error"(실행 불능) | "fail"
                 "B": "flags:0", "C": "flags:0",   // C 카운트는 inComment:false 매치만
                 "D": "flags:0" }
    // 최상위 ok/success/pass 없음 — 의도적 부재(위 규정)
  }
  ```
- **실행 전략**: 앱의 vitest 설정을 쓰지 않고, **발견 파일을 절대경로 명시 include로 박은 임시
  config를 리포 밖 OS 임시 디렉터리에 생성**해 `--config` 절대경로로 준다. vitest의 JSON
  `--outputFile`도 같은 임시 디렉터리에 둔다. 즉 **스크립트가 앱 워킹 트리에 쓰는 파일이 0개**.
  finally의 임시 디렉터리 정리는 유지하되 보증 수단이 아니라 청소다. 임시 config는 **import
  없는 순수 객체 export**로 생성한다. **직렬화는 `JSON.stringify`로만 하고 경로는 POSIX
  구분자(`/`)로 정규화해 넣는다.** 고정값 5개(전부 실측 근거 — §8·§9·§10):
  1. **`globals: true` 항상.** Testing Library의 자동 cleanup은 전역 `afterEach`를 요구한다.
     s2-dom은 4파일 전부 자동 cleanup에 의존하므로 globals 없이 돌리면 같은 자산이 17/17 →
     4/17로 무너진다. 명시 import 파일에는 무해(s1-tdd 28/28·s2b-dom 14/14 그대로).
  2. **jsdom은 파일 확장자(`.tsx`)/import로 판정해 지정, react 플러그인은 넣지 않는다.**
     플러그인 없이 DOM 두 앱이 전부 통과함을 실측했다(§8).
  3. **`--reporter=json --outputFile=…`.** stdout 오염 회피 + 결과 파일 부재 = 수집 단계 사망.
  4. **vitest 호출은 `node <app-dir>/node_modules/vitest/vitest.mjs` 명시 경로.** 폴백 없음 —
     엔트리 부재 시 A `"run-error"` + `runError` 사유로 보고한다.
  5. **프로세스 타임아웃 120초 + 프로세스 그룹 SIGKILL.** POSIX는 `detached` 스폰 + 음수 PID
     `SIGKILL`, Windows는 `taskkill /PID <pid> /T /F`. 발동 시 A `"run-error"` +
     `runError`에 «타임아웃(120s)» 명시.

  `exp2/selftest.vitest.config.ts`는 **사본 재사용이 성립하지 않는다**(jsdom·react 플러그인
  하드코딩 → s1-tdd 로드 실패 실측). exp2에서 계승하는 것은 파일이 아니라 **규율**(내용 열거·
  명시 include). include는 생성 config에 직접 박고, `root`는 **앱 절대경로 명시**로 준다.

## 5. 작업 순서 (1세션 어치)

1. JSON 스키마·CLI 확정 → 골격 작성 (§7 미결은 v5에서 전부 확정 — 사용자 대기 없음)

## 6. 함정·리스크 (미리 등록)

1. **vitest 출력 텍스트 파싱 금지** — logprobe 오독 전례(r18 §3-2). 반드시 `--reporter=json
   --outputFile`. 픽스처는 vitest 3(s1-*)·4(s2*) 혼재인데 JSON 키는 동일함을 실측했다(§8).
   단 `numRuntimeErrorTestSuites`처럼 없을 수 있는 키는 `?? 0`으로 읽는다.
2. **파일명 규약 의존 금지** — exp2에서 계측기 3개가 동시에 뚫린 전례(REPORT2 §5.2-1).
   열거는 내용, 실행은 명시 include. **s2b-dom의 테스트가 `src/`에 있다는 실물이 이 규율의
   근거다** — `tests/` 가정은 그 앱에서 즉사한다.
3. **임시 config 자체가 실패를 제조할 수 있다** — s2-dom 실측: `globals` 한 줄 차이로 같은
   자산이 17/17 ↔ 4/17. §3 고정값 5개를 지키고, s2-dom 기지값이 이 회귀를 감시한다.
   고정값 5의 타임아웃도 같은 급의 제조 지점이다(느린 머신) — 발동 시 `runError` 원문 확인.
4. **C 패턴의 오탐·미탐** — flag-only인 이유. 패턴 상수에 버전을 박고, 변경 시 사유를 r문서에
   기록한다. 경계 정규식·주석 강등이 소음을 줄이지만 구조 분해류 미탐은 그대로 남는다.
5. **build 성공 ≠ 테스트 건전** — seed tsconfig가 테스트를 타입체크하지 않는 실측(r18 §2-B).
   판정은 항상 vitest 실행으로.
6. **SAC Enforced** — 네이티브 바이너리 불가. node + vitest + jsdom만.
7. **범위 확장 유혹** — 이 스크립트가 잘 돌면 에이전트 완료 게이트로 쓰고 싶어진다. 그건
   edd(3단계)다. **v5에서 다짐을 장치로 바꿨다**: 판정이 종료 코드에 실리지 않고 최상위 불리언도
   없으므로(§3) 게이트화하려면 스크립트를 **개조**해야 하고, 개조는 diff에 남는다.
8. **주석 판정 과욕 금지** — 완전한 주석 제거는 토크나이저 없이 불가능하다(문자열 안 `//`·템플릿
   리터럴 오절단). 라인 선두 `//`·`/* */` 블록 추적의 **보수 휴리스틱까지만** 쓰고, 처리도
   제거·재작성이 아니라 `inComment` **강등까지만** 한다.
9. **self-test의 순환 오인 금지** (v5 신설) — `--selftest`는 스크립트가 자기를 채점하는 것이
   아니다. **픽스처 변형은 스크립트 상수, 기대값은 §4 표(문서)**다. 기대값이 코드로 들어가면
   그때부터 순환이니, «음성 ②는 C flags ≥ 1» 같은 판정 로직을 스크립트에 넣지 않고 산출된 JSON을
   사람이 §4 표와 대조한다.

**방법**: 제3자 검토의 지적 3건(임시 config 잔존 · C 오탐/미탐 · vitest 실행 환경)과 확정안
4건을 **리포 실물 + 픽스처 실실행으로 각각 검증한 뒤** 취사했다(Linux·node 22, `npm ci`는
s1-tdd·s2-dom 2개 앱). 실행 후 워킹 트리 무변경 재확인.

**채택·변형 1 — 임시 config 잔존**: 지적은 사실이나(SIGINT는 finally를 안 돈다) 제안된 신호
핸들러는 증상 완화다. v3는 **원인을 제거한다** — 임시 config와 vitest JSON을 **리포 밖 OS 임시
디렉터리**에 두어 앱 트리 기록 파일을 0개로. **실측 4건**: ① 순수 객체 config + 절대경로
root·include가 vitest 3.2.7·4.1.10에서 정상 ② s1-tdd 28/28 ③ s2-dom 17/17, globals 제거 시
4/17 회귀도 재현 ④ 실행 후 `git status` 무변경.

**채택·축소 2 — 주석 오탐**: «주석 제거 전처리(B/C/D)» 중 **적용 범위는 C뿐**(B는 주석이 검사
대상, D는 파일명). 방식도 제거가 아니라 **강등**(`inComment: true`) — 지우면 §2의 «재료를
빠짐없이» 원칙이 깨진다. 완전한 주석 파싱은 하지 않는다(§6-8).

**기각 1 — C 미탐 예시 2/3건**: `globalThis.fetch`·`window.performance.now`는 부분 문자열
매치가 이미 잡는다 — 성립하지 않는 지적. 다만 매치 의미론이 문서에 없던 게 원인이라 §2-C에
명시(서술 보강). 구조 분해 미탐은 실재하나 v1 패턴에 넣지 않는다(오탐 증가 > 검출 이득).

**채택·역전 3 — vitest 실행 환경**: 문제의식은 정당하나 **폴백 체인(`.bin`→`npx`→전역)은
기각**한다 — 앱과 다른 버전을 조용히 섞어 «계측 실패 → 자산 실패 둔갑» 경로를 연다(globals
사건과 같은 급). 대신 **역방향 확정**: `node <app>/node_modules/vitest/vitest.mjs` 고정, 부재
시 폴백 없이 `run-error`. 실측: vitest 3·4 모두 이 엔트리로 정상 실행.

**§7 확정안 처리**: 외부 검토의 확정안 4건은 전부 본문 권장안과 동일. concurrence로 기록하되
확정은 반영하지 않았다(당시 §7은 사용자 결정 예약 항목).

## 10. 개정 내역 — v3 대비 (2026-08-14 2차 외부 검토(Gemini) 반영·검증)

**방법**: 2차 검토의 구현 엣지 케이스 5건(① 타임아웃 ② Windows 경로 이스케이프 ③ 경계 매칭
④ 선두 지시어 ⑤ vitest 경로 안전성)을 1차와 같은 규율로 **전 건 실실행 검증 후** 취사.
4건 수용·1건 현행 유지 — 단 ①은 제안대로 구현하면 안 되는 결함을 검증 중 발견해 **강화 수용**.

**강화 수용 ① — 프로세스 타임아웃**: **실측**: 동기 `while(true)`는 vitest `testTimeout`(5초)이
못 끊고 15초 내내 매달렸다(워커 이벤트 루프 차단). 그러나 **단순 timeout+kill도 불충분** —
자식만 SIGKILL하면 워커 포크가 고아로 남아 **CPU 99.9% 점유**(ppid 1 재부모화). 해법은 프로세스
**그룹** 킬(POSIX `detached` + 음수 PID SIGKILL — 실측 생존 0, Windows `taskkill /T /F`).
수치는 **120초**(정상 픽스처 1.3초의 ~90배 여유, SAC 오버헤드 감안). 비동기 hang은 vitest가
6초 만에 «fail»로 수렴 — 이 타임아웃은 백스톱.

**수용 ② — 경로 직렬화 규정 승격**: v3 실험은 이미 `JSON.stringify` + 슬래시 정규화로 돌았으나
**문서에 규정이 없었다** — 템플릿 리터럴로 짜면 Windows 절대경로에서 `\u`(SyntaxError)·`\t`(무음
변형)로 깨진다. §3에 규정 승격.

**수용 ③ — 식별자 경계 정규식**: **실측**: 경계 정규식 v1 후보로 픽스처 전체 재스캔 0건(기대값
불변), 데모에서 `globalThis.fetch(`·`window.performance.now()`·`stats.mtimeMs` 포착 유지,
`prefetch(`·`refetch()` 오탐 제거. 매치 라인 원문(`text`) 출력도 수용.

**수용 ④ — 선두 지시어 스킵**: shebang·`// @ts-*`·`/// <reference`·`@vitest-environment`
독블록·`"use client"` 류를 건너뛴다. **실물 확인**: 픽스처 3앱은 전부 1행부터 `/** */` 헤더라
기대값 불변 — 방어 대상은 미래 산출물. 덤으로 «헤더 없음 = 사람 확인 트리거»를 명시.

**현행 유지 ⑤ — vitest 경로 안전성**: 검토 결론 자체가 «v3 방식 유지로 충분». pnpm 심링크는
`existsSync`·node 실행 모두 따라가므로 비문제. 워크스페이스 호이스팅 대응(`createRequire`
상위 탐색)은 **v0.1에서 도입하지 않는다**(의도치 않은 상위 설치본으로 새는 경로 재개방).

**§7 concurrence 2호**: 2차 검토도 옛 §7 1~4 전부 본문 권장안과 동일 결론.

## 11. 개정 내역 — v4 대비 (2026-08-14 §7 확정)

**방법**: 확정을 «권장안이 그럴듯하니까»로 하지 않기 위해, 결정에 걸리는 실물 4종을 다시

**확정 5건**: §7 참조. 1·3·4는 본문 권장안 그대로, 2·5는 **근거와 규정을 보강**해 확정했다.

1. **종료 코드에 판정을 싣지 않는다 + 최상위 불리언 금지** (§3·§7-2). 근거는 실물 —

**구현 리뷰에서 확정된 결함 7건 — 전부 수정**. 구현 직후 다중 에이전트 적대 리뷰(4개 렌즈 →
발견별 반박 검증, 발견 전건 실실행 재현)를 돌렸고, 기지값 재현이 잡을 수 없는 결함 7건이
확정돼 같은 세션에서 수정·재검증했다:

1. **§2-B «SPEC 참조/인용 흔적 검사(파일 전체)» 미구현.** §3 스키마 초안에 해당 필드가 없던
   계획서 내부 불일치가 원인 — 검사 정의는 §2 표가 규정하므로 구현했다:
   `testFiles[].specRefs: [{line, text}]` (판정 없음, 재료만. B flags는 여전히 헤더 부재만
   센다). §3 스키마 초안 원문은 그대로 두고, 확정 스키마와의 차이는 이 절이 기록한다.
2. **앱 루트 read 실패(ENOTDIR·EACCES)가 A `"none"`·exit 0으로 둔갑.** 경로 오타 한 번이
   s1-ctrl 기지값과 구별 불가능한 가짜 «none» 판정을 만든다. walk의 관용 catch에서 앱
   루트(rel === "")만 rethrow → 계측 실패 exit 1·JSON 미기록.
3. **C 분류기: 같은 줄에서 블록 주석이 닫힌 뒤 재개방되면 그 안의 매치가 강등되지 않음.**
   라인 종단 상태 머신과 매치 분류기가 어긋나 flags가 참값보다 부풀던 방향 — 재개방 검사 추가.
4. **B 추출기: `/** @see SPEC… */`류 전부-@태그 헤더를 지시어 독블록으로 오인** → «헤더 부재»
   오탐. 독블록 인정 태그를 `@vitest-environment(-options)`·`@jest-environment`로 한정.
5. **B 추출기: 지시어 독블록 닫는 `*/` 뒤 같은 줄 코드가 통째로 스킵**돼 뒤따르는 무관 주석이
   헤더로 승격. 잔여 코드 발견 시 «코드 도달 = 헤더 없음»으로 처리(플래그 발생 = 사람 확인
   트리거, 보수 방향).
6. **§6-1이 예시로 박은 `numRuntimeErrorTestSuites`는 vitest 3·4 어디에도 실존하지 않는 키다**
   (양쪽 리포터 JSON 최상위 키 전수 실측 — 실존 키는 `numFailedTestSuites`·`success`).
   이대로면 import 단계에서 죽은 스위트(케이스 실패 0)가 A `"pass"`로 확정된다.
   `numFailedTestSuites > 0 || success === false`로 교체하고 import 사망 사본으로 A `"fail"`
   전환을 실측했다. 참고: `exp2/selftest.sh` 60행도 같은 유령 키를 읽고 있으나 exp2는
   동결이므로 손대지 않고 여기 기록만 남긴다(그쪽은 `numFailedTests`가 먼저 잡아 실해가 좁다).
7. **라인형 `// @vitest-environment` 지시어가 헤더로 인정됨**(블록형만 스킵하고 있었다) —
   `DIRECTIVE_LINE`에 라인형 environment 지시어 추가.

결과 기대값 불변. C 패턴 상수는 변경 없음 — `patternListVersion` 1 유지(수정 3은 패턴이
