# r48 — KF4 R3: `delta`·`drift` 서브커맨드 + A 블록

지시서 `docs/next/2026-08-21/r47.md` 집행. 계획서 `docs/next/2026-08-19/plankf4ruleset.md` §5 WBS의
**R3**. R4(volume·interview)는 **KF5 부재로 착수 불가**라 열지 않았다 — 그래서 이 라운드로
**KF4는 사실상 종료**다.

## 1. 만든 것

| 파일 | 변경 | 내용 |
|---|---|---|
| `framework/specgate.mjs` | 300→491줄 | A 블록 RULES 7키 · `delta`·`drift` 서브커맨드 · `pack()` 공통화 · selftest 18→22건 |
| `framework/README.md` | +13/-2 | 실행 2행 · 번호대에 `SG1021~1027` · `drift`의 loc 비대칭 · «record는 없다» |
| `CLAUDE.md` | +5/-3 | 커맨드 절 |

**감싸이는 셋(`spec-verify`·`spec-delta`·`spec-anchor`)은 한 글자도 안 고쳤다.** r46이 매핑 키를
`kind ?? check`로 잡아둔 덕이다(r46 §2-2) — D·A 블록은 check 하나가 룰 하나라 그대로 키가 된다.

실물(스크래치에 복사한 `i1-cart-r1` SPEC — 앵커 28건·스팬 31):

```
$ node framework/specgate.mjs drift <스크래치>/SPEC.md      # 무변경
→ Error 0 · Warning 0 · muted 0 · exit 0

$ node framework/specgate.mjs drift <스크래치>/SPEC.md      # vite.config.ts 삭제 + formatWon.ts에 한 줄 삽입
SG1024 (Error): I17 → vite.config.ts:8-11 (파일 소멸)
  ↳ 파일이 사라졌다 — 그 문장이 아직 참인지 다시 읽고 SPEC의 지목을 고친다
SG1025 (Error): I8 → src/formatWon.ts:7-9 (범위 소멸)
  ↳ 스팬이 갈라졌다 — 그 문장이 아직 참인지 다시 읽고, 참이면 `spec-anchor record`로 갱신한다
→ Error 2 · Warning 0 · muted 0 · exit 1
```

**검증** — `specgate --selftest` 22건 전건. 회귀 4종 무변경(`spec-verify` 6장 · `spec-delta` 19건 ·
`spec-anchor` 15건 · `spec-gate` 23건). **기대값을 고친 것은 0건이다**(r46은 2건이었다).

**부작용 1건(측정함)**: 훅이 `specgate.mjs`를 import하므로 이제 `spec-anchor.mjs`(+`node:crypto`)가
훅의 로드 체인에 들어온다. 훅 pre 실측 123~132ms(빈 `node -e ""`가 92ms) · `spec-anchor` 체인 로드
14ms — 그중 `spec-verify`·`spec-delta`는 훅이 이미 로드하던 것이라 순증분은 그보다 작다. 무시할
수준이지만 «Write마다 도는 경로»라 기록해 둔다.

## 2. 지시서와 달라진 3건

1. **`record`를 감싸지 않는 것이 사용자 확정으로 굳었다**(r47은 «기본값»이었다). 근거는 성격
   차이다 — specgate의 나머지 넷은 읽기 전용 판정인데 `record`만 `SPEC.anchors.json`을 **쓴다**.
   CI 한 줄·에이전트 계약이라는 KF4의 성격에 쓰기 명령을 섞지 않는다. 대가는 §3-2.
2. **T20을 T3b에 흡수했다.** 성질이 같고(소스 리터럴 정적 대조) 읽는 파일만 다르다 —
   `/check: '(A\d)'/g` 한 줄 추가. 케이스를 따로 두면 selftest 줄만 늘고 잡는 것은 같다.
3. **T18을 3범주 전부로 강화했다**(r47은 stale 1범주). `drift.missing`·`stale`·`modified` 세 키는
   **specgate가 만드는 이름이라 spec-anchor 소스에 리터럴이 없다** — T3b 같은 정적 대조가 원리상
   못 잡고, 런타임으로 밟는 것이 유일한 전수 검사다. 시드 하나(3문장 SPEC + `src/a,b,c.ts`)에서
   델타 선언·미선언·삭제로 3범주를 동시에 만든다.

## 3. 남긴 비대칭 2건 (의도)

1. **`drift`의 `loc.file`만 SPEC이 아니라 코드 파일이다.** 드리프트의 조치 대상이 코드이기
   때문이고, `verify`·`delta`에서 성립하는 «`loc.file` === `target`» 불변식이 거기서만 깨진다.
   파일 머리 ⚠ 주석 · README · T18 단언 세 곳에 계약으로 박았다.
2. **A1~A3(SG1021~1023)은 등재됐지만 specgate로 발행되지 않는다** — §2-1의 대가. 등재하는 이유는
   매핑 전수성(T3b) 하나다. 이 자리가 선택 대기 #8이다.

## 5. 한계 (전부 유효 — 계획서 §9 · r46 §5)

1. **검출력은 R3에서도 1도 늘지 않았다.** D4는 C4의 «ID를 다시 적었는가» 한계를 상속하고,
   `drift` exit 0은 «문장이 아직 참»이 아니라 «앵커 스팬이 그대로»라는 뜻이다(스팬 밖 변경엔 침묵).
2. `drift`가 exit 2로 죽을 때(`SPEC.anchors.json` 부재) `--json`이 나오지 않는다 —
   `spec-anchor`의 `die()`를 그대로 통과시킨 결과이고, `verify`의 `fatal` 경로와 같은 동작이다.
3. **자기수정 루프는 여전히 미실측이다**(조사 Q1). R1~R3이 만든 것은 **형태**뿐이고, 효과는
   실사용 2회차 관측 항목이다(`.specgate-log.jsonl`의 `rules` 필드).
4. `drift`는 **어떤 훅에도 걸지 않았다**(planmain §5-3 — Stop에 걸면 FIELD-GUIDE 예언 P2를
   재생산한다). 명시 실행·CI 전용이라 **안 돌리면 아무것도 실증되지 않는다.**
