# r47 지시서 — KF4 R3: `delta`·`drift` 서브커맨드 + A 블록

**전제**: r46이 KF4 R1+R2를 끝냈다(`framework/specgate.mjs` 신설 · C·D 블록 RULES · 훅 stderr
개정 · 로그 `rules`). 이 지시서는 계획서 `docs/next/2026-08-19/plankf4ruleset.md` §5 WBS의 **R3**만
다룬다. R4(volume·interview)는 **KF5가 없어 착수 불가**이므로 이 지시서의 범위가 아니다.

**라운드의 산출물은 돌아가는 코드 + selftest다**(프레임워크 개발 규칙 1). 판정 문서 한 장으로
끝나면 실패한 라운드다.

## 0. 착수 전에 읽을 것

- `docs/next/2026-08-19/plankf4ruleset.md` §4-1(서브커맨드) · §4-2(배정표) · §5(R3) · §6(T11)
- `docs/next/2026-08-21/r46.md` §2(계획서와 달라진 4건) · §4(SG1027) — **이 지시서의 전제다**
- `framework/specgate.mjs`의 `RULES`·`mk()`·`verify()` — R3은 이 셋의 형태를 그대로 늘린다

## 1. 할 일

### 1-1. A 블록 RULES 등재 (7키)

`specgate.mjs`의 `RULES`에 아래를 더한다. 키는 `check` 그대로다(A 블록도 1:1이라 kind가 없다).

| 키 | ruleId | 근원 | 심각도(도출) |
|---|---|---|---|
| `A1` | SG1021 | 지목한 파일이 없다 / 못 읽는다 | Error (`record`의 V) |
| `A2` | SG1022 | 줄 범위가 뒤집혔다 / 파일 길이 초과 | Error (`record`의 V) |
| `A3` | SG1023 | 문장 ID 없음 · 앵커 미기록 | Warning (`record`의 W) |
| `drift.missing` | SG1024 | 파일 소멸 | Error |
| `drift.stale` | SG1025 | 범위 소멸 · 해시 불일치 · 읽기 실패 | Error |
| `drift.modified` | SG1026 | 선언된 수정, 앵커 미갱신 | Error |
| `A4` | SG1027 | 앵커가 SPEC보다 낡았다(3종) | Warning (`drift`의 W) |

**SG1027은 계획서 §4-2 배정표에 없던 것이다** — 실물 `spec-anchor.mjs`에 A4 경고 3종이 있고
(`spec-anchor.mjs:117`·`:146`·`:147`), 등재하지 않으면 T3(«`SG----` 0건»)가 깨진다.
사용자가 2026-08-21에 신설로 확정했다(r46 §4-1).

힌트는 룰당 정적 1줄이다. A1·A2는 «지목을 고치거나 record를 다시 돌려라», SG1024~1026은 조치가
서로 다르다 — missing/stale은 **문장 재검토**, modified는 **record 재실행**(r45 §1).

### 1-2. `delta` 서브커맨드

```
node framework/specgate.mjs delta <SPEC.delta.md 경로> [--json]
```

- `spec-delta.mjs`의 `inspectDelta(deltaText, baseText, label)`를 **정적 import**한다.
  계획서 §4-1의 동적 import + «미도입 안내» + T11은 **만들지 않는다** — KF1이 실재하고 플러그인
  루트가 `framework/` 전체라 둘이 항상 같이 배포된다(r46 §2-4). 「일어날 수 없는 상황에 대한
  에러 처리」다.
- base는 델타와 같은 디렉터리의 `SPEC.md`, 없으면 `null`(콜드스타트).
- 반환 형태가 `verify`와 같다(`{violations, warnings}` 각 원소 `{check, msg}`) — `mk()`를 그대로 쓴다.
  D 블록 RULES는 r46이 이미 등재했으므로 **RULES 수정 없이 돈다**.

### 1-3. `drift` 서브커맨드

```
node framework/specgate.mjs drift <SPEC.md 경로> [--json]
```

**여기가 R3의 유일한 난점이다.** `spec-anchor.mjs`의 반환이 다른 둘과 형태가 다르다:

1. **`drift()`에는 `violations`가 없다.** 반환은 `{ drift: { missing, stale, modified }, warnings, exit, … }`이고
   3범주의 원소는 `{ id, file, startLine, endLine, why }`다(`spec-anchor.mjs:100-157`).
   → specgate가 3범주를 각각 `check: 'drift.missing'` 등으로 **Error finding으로 변환**한다.
   `loc`는 `{ file: a.file, line: a.startLine }`로 실을 수 있다(verify와 달리 SPEC이 아니라
   **코드 파일**을 가리킨다 — `--json` 소비자가 헷갈리지 않게 이 사실을 헤더 주석에 적어라).
   `msg`는 `${id} → ${file}:${startLine}-${endLine} (${why})` 골격이면 사람도 읽는다.
2. **`record()`/`drift()`는 경로를 받고, 실패 시 `die()`로 `process.exit(2)`를 직접 부른다**
   (`spec-anchor.mjs:26`·`:105`). `SPEC.anchors.json`이 없으면 «먼저 record를 돌려라» 한 줄을
   내고 그 자리에서 죽는다.
   → specgate의 exit 규약(파일 없음 = 2)과 **우연히 일치하므로 그대로 둔다.** 대신 그때는
   `--json`이 나오지 않는다는 것을 한계로 적어라. `die()`를 없애려고 `spec-anchor.mjs`를 고치는
   것은 이 라운드의 범위가 아니다(KF3는 종료됐다).
3. **`record`는 서브커맨드로 넣지 않는다** — 계획서 §4-1이 `verify`/`delta`/`drift`/`probe` 넷만
   규정했다. A1~A3(SG1021~1023)은 `drift`가 아니라 `record`가 내는 것이라, 등재는 하되 **specgate를
   통해서는 발행되지 않는다**. 이 비대칭을 R3 기록에 명시하고, 「record도 감쌀 것인가」를 선택
   대기로 남겨라(기본값: 감싸지 않음 — 계획서가 안 시켰다).

### 1-4. selftest 확장

r46이 만든 케이스 18건은 그대로 두고 더한다. **기존 기대값을 고쳐야 통과한다면 멈추고 원인을 가른다.**

| # | 케이스 | 기대 |
|---|---|---|
| T16 | `delta` exit 패스스루 | 인라인 델타 2장(위반 있음/없음)에서 exit가 `spec-delta.mjs verify` 직접 실행과 같다 |
| T17 | D 블록 매핑 | D1 위반 델타 → `SG1011`, `SG----` 0건 |
| T18 | `drift` 3범주 | mkdtemp에 SPEC+소스 시드 → `spec-anchor record` → 소스 변경 → specgate `drift`가 SG1025를 Error로 내고 exit 1 |
| T19 | `drift` 앵커 없음 | `SPEC.anchors.json` 없이 `drift` → exit 2 |
| T20 | A 블록 전수 | `spec-anchor.mjs` 소스의 `check: 'A\d'` 리터럴 전부가 RULES에 있다 (T3b 확장) |

T20이 T3b와 같은 성질이다 — 픽스처로 A4의 3종을 다 밟기 어려우니 **정적 대조로 전수를 잡는다.**

### 1-5. `framework/README.md` 룰 표 절

계획서 §7-①이 예산으로 잡은 «약 30행». 룰 ID · 근원 · 심각도 · 조치 한 줄. 코드가 돈 뒤에 짧게 쓴다.

## 2. 검증 (수용 기준)

```bash
node framework/specgate.mjs --selftest        # 18 + T16~T20
node framework/spec-verify.mjs --selftest     # 회귀 6장
node framework/spec-delta.mjs --selftest      # 회귀 19건
node framework/spec-anchor.mjs --selftest     # 회귀 15건
node framework/hooks/spec-gate.mjs --selftest # 회귀 23건
```

전건 통과 + 회귀 무변경. 실물 1회는 `spec-anchor record`를 돌린 리포에서 `specgate drift`를
눈으로 본다.

## 3. 하지 말 것

- `spec-anchor.mjs`·`spec-delta.mjs`·`specprobe.mjs` 수정 — R3의 값어치는 **감싸는 것**이지
  감싸이는 것을 고치는 게 아니다. 고쳐야만 감쌀 수 있는 자리가 나오면 그것 자체를 기록하고 멈춘다.
- `drift`를 훅에 배선하는 것 — planmain §5-3이 명시적으로 금한다(«Stop에 걸면 FIELD-GUIDE 예언
  P2를 재생산한다»). 명시 실행·CI 전용이다.
- 새 검사 추가 — KF4는 재포장이다. 검출력은 R3에서도 1도 늘지 않는다.

## 4. 그다음

R3이 끝나면 KF4에서 남는 것은 R4뿐이고 그건 KF5 착수 후다. 후보는:

1. **r28 작업 ①** — 설치형 트리거 확인(«실사용 개시 전 필수»로 표시돼 있다). r44 §5의 미해결 1건
   («`/plugin install` 형태에서도 `/spec`이 `/specgate:spec`인가»)도 여기서 같이 닫힌다.
2. **r28 작업 ②** — `framework/README.md` 정비.
3. **KF5 착수** — 볼륨 4종. 그래야 KF4 R4가 열린다.
4. **실사용 2회차(사용자 게이트 G3)** — 도구가 값을 하는지는 결국 여기서만 관측된다. r46 §5-2가
   말하듯 «형태를 만들었다»와 «자기수정 루프가 돈다» 사이는 아직 비어 있다.
