# r49 지시서 — KF5 R1+R2: 아카이브 절 + 볼륨 계측

**전제**: r48로 KF4 R3까지 끝나 **KF1~KF4가 전부 종료**됐다. planmain §133의 P1 = KF1·KF3①·KF2·KF5
중 **KF5만 남았고**, KF5 R1·R2는 다른 KF에 의존하지 않는다(KF5 §8 — 즉시 착수 가능). KF4 R4
(volume 배선)는 이 라운드가 값 계약을 고정해야 열린다.

이 지시서는 계획서 `docs/next/2026-08-19/plankf5volume.md` §5 WBS의 **R1·R2**만 다룬다.
**R3(첫 접기 실측)는 실사용 SPEC의 볼륨이 시작점에 접근할 때만 도는 조건부 라운드라 범위 밖이다** —
임계를 밟으려고 스펙을 부풀리는 억지 과제는 금지다(G3 정신, r38 작업 B).

**라운드의 산출물은 돌아가는 코드 + selftest다**(프레임워크 개발 규칙 1). 판정 문서 한 장으로
끝나면 실패한 라운드다.

**세션 배분**: R1+R2가 한 세션에 들어간다고 본다(r48이 KF4 R3를 한 세션에 끝냈다). 넘치면
**R1에서 끊는다** — R1만으로도 마스킹·반환 확장·템플릿이 돌고, R2는 R1의 반환 필드를 파생할 뿐이다.

## 2. R1 — spec-verify 아카이브 마스킹 + 반환 확장 + 템플릿

### 2-1. 마스킹 (`spec-verify.mjs`의 `inspect()`)

**탐지**: 코드펜스 제거 **후**, `^##\s+(?:\d+[.)]\s*)?아카이브\b`에 걸리는 헤딩 줄부터 다음
`^##\s` 헤딩 직전(또는 파일 끝)까지. 여러 개 걸리면 각각 적용한다(계획서 §4-3).

**순서가 이 작업의 전부다.** 현행 85~87행은 이렇다:

```js
const lines = stripFences(text.split('\n'));
text = lines.join('\n');       // 이하 모든 계수는 코드펜스 밖만 본다
const tbls = tables(lines);
```

여기에 **마스킹을 끼우되 C1의 `[추론]` 계수만은 마스킹 전 원문으로 센다**(계획서 §4-3 — 추론
문장이 전부 접힌 성숙한 SPEC에서 C1이 위양성으로 pre 게이트를 막지 않게 하기 위해서다). 즉
현행 95행의 `inferMarks` 계산을 **마스킹보다 위로 끌어올린다**:

```js
const fenced = stripFences(text.split('\n'));
const inferMarks = fenced.join('\n').split('[추론]').length - 1;   // C1만 마스킹 전 원문
const { lines, archive } = maskArchive(fenced);                    // 아카이브 줄 → 빈 줄
text = lines.join('\n');
const tbls = tables(lines);
```

`maskArchive()`는 마스킹된 줄 배열과 함께 **접기 전에 뽑아 둔 파생값**을 반환한다(마스킹 후에는
못 센다): `{ present, sentences, pendingInArchive }`. `sentences`는 아카이브 절 안에서 줄
선두(표 첫 셀 / 리스트 마커 뒤)에 오는 문장 ID 수 — **147~148행의 `head` 추출과 `SENT_ID`를 그대로
재사용한다**(파서 중복 금지, 개발 규칙 2). `pendingInArchive`는 그 구간의 `선택 대기` 리터럴 수다.

### 2-2. 신규 경고와 SG 번호 — **이 라운드의 결정 포인트**

계획서 §4-3의 «경고 1건 신설»: 마스킹 영역에 `선택 대기` 리터럴이 있으면 경고.
문안은 «아카이브 절에 `선택 대기` 행 N건 — 미확정은 아카이브 자격이 없다». 정당한 인용일 수
있으므로 **위반이 아니라 경고**다.

**check·kind·ruleId의 기본값(근거와 함께)**:

| 축 | 값 | 근거 |
|---|---|---|
| `check` | **`C3`** | 재는 것이 «미확정 항목이 있으면 안 될 자리에 있다»이고 C3이 미확정표 담당이다. 새 축(`C6`)을 만들면 README 「검사 5종」 표 · 훅 시점 분기 · FIELD-GUIDE까지 파급된다 — KF5 비목표(«파이프라인 단계 불추가»)와 어긋난다 |
| `kind` | **`C3.archivePending`** | C2·C4·C5가 이미 한 check에 여러 kind를 갖는다. kind는 룰 매핑용 안정 문자열이지 검사 축 정의가 아니다(`spec-verify.mjs:89` 주석) |
| `ruleId` | **`SG1010`** | C 블록의 유일한 빈 번호(SG1009 다음, SG1011부터 D 블록). 계획서 §10-7의 «SG1010 후보»와 같다. 대안 SG1035(볼륨 블록 뒤)는 «spec-verify가 내는 것 = C 블록»이라는 KF4 구획을 깬다 |

**이것이 `specgate.mjs` 수정을 강제한다** — `RULES`에 1행을 더한다:

```js
'C3.archivePending': { id: 'SG1010', hint: '그 행을 §2.3 미확정표로 되돌린다 — 아카이브는 «구현·검증 완료» 보존이다' },
```

**등재를 잊으면 `specgate --selftest`의 T3b가 즉시 깬다**(소스에서 `'C\d\.\w+'` 리터럴을 뽑아
RULES와 대조한다). 그게 T3b의 설계 목적이고, 여기서 실제로 작동하는 첫 사례다 — 깨졌다면 고칠 것은
T3b가 아니라 RULES다.

훅(`spec-gate.mjs`)은 **무수정**이다: 훅은 `violations`만 읽으므로(`spec-gate.mjs:57·93·100·108`)
신규 «경고»는 차단 경로에 닿지 않는다.

### 2-3. 반환 확장 (전부 additive — 기존 필드 불변)

| 필드 | 값 | 구현 메모 |
|---|---|---|
| `counts.tableRows` | 아카이브·펜스 밖 모든 표의 행 수(헤더 포함·구분선 제외) | `tables()`의 `rows`가 이미 `isRule`(구분선)을 걸러내고 헤더를 포함한다 → `tbls.reduce((n, t) => n + t.rows.length, 0)` 한 줄 |
| `counts.archive` | `{ present, sentences, pendingInArchive }` | §2-1의 `maskArchive()` 반환을 그대로 싣는다 |
| `c4.ids` | 정의된 활성 문장 ID 배열 | 실물 152행의 `sentIds` 그대로 |
| `c4.located` | **hit − vague** = «파일:줄 보유 줄 어딘가에서 언급된 활성 문장» | 실물 165~166행의 지역 변수 `located`/`vague`에서 파생: `[...hit].filter((id) => located.has(id))`. **`positions`(173행, 정의 줄 제외)로 바꾸지 마라** — §1 표 #5 |

`c4`가 `null`인 SPEC(문장 ID 없음)에서는 `c4.ids`·`c4.located`도 존재하지 않는다. 소비자(specprobe)가
`c4 ?? null`을 먼저 본다.

### 2-4. `spec-template.md` — `## 4. 아카이브` 절

계획서 §4-2의 골격을 §3(완료 전 대조) **뒤**, 파일 끝에 더한다. 기존 절은 한 글자도 안 고친다.
주석의 진입 조건은 **KF3①②가 끝난 지금 상태로** 쓴다(§1 표 #4):

- ① §3.1에 `파일:줄` 지목 ② `spec-verify` 위반 0 ③ `spec-anchor record` 통과(A1·A2)
  ④ 그 문장 앵커의 `drift` 결과 0 — **넷 다 기계로 확인된다.** 남은 사람 몫은 **승인**뿐이다.
- 접기는 **에이전트 제안 + 사용자 승인**으로만 한다(자동 아카이브 금지 — 계획서 §2 비목표).
- `선택 대기` 행은 어떤 경우에도 접지 않는다.
- 새 문장 ID는 **아카이브 포함 문서 전체의 최대 번호 +1** — 재사용하지 않는다(마스킹의 대가로
  검사기가 ID 충돌을 못 잡는다, 계획서 §9-7).
- 기각(REMOVED) 문장은 이 절의 대상이 **아니다**(진입 조건 ①을 원리적으로 못 채운다).

표는 5열이다: `| ID | 문장(원문 그대로) | 최종 지목 | 접은 날짜 | 근거 |`.

### 2-5. `spec-verify --selftest` 확장

현행 selftest는 `EXPECTED` 6장 루프뿐이다. **인라인 픽스처 케이스 배열을 옆에 더한다**
(파일 신설 금지 — 개발 규칙 4, `framework/smoke/`는 읽기 전용 회귀 대상이다). 공통 픽스처 `KA`는
계획서 §6의 코드블록을 그대로 쓴다.

| # | 재료 | 기대값 |
|---|---|---|
| V-A1 아카이브 제외 | KA | 위반 1(C2 점검표 없음) · 경고 1(C4 vague: I1) · `c4.total` **3**(S0 제외) · `counts.archive.sentences` 1 · `pendingInArchive` 0 |
| V-A2 아카이브 내 선택 대기 | KA의 아카이브 행 «근거» 셀을 `선택 대기`로 치환 | 위반 1 · 경고 **2**(신규 `C3.archivePending` +1) |
| V-A3 마스킹 차분 | KA에서 `## 4. 아카이브` 헤딩 줄**만** 삭제 | 위반 **2**(C2 + **C4 S0 미지목**) — 마스킹이 실제로 분모를 바꾼다는 차분 증명 |

V-A3이 이 라운드에서 가장 중요한 케이스다. 나머지 둘은 «값이 나온다»를 보지만 V-A3만 «마스킹이
없으면 판정이 달라진다»를 본다 — 이게 없으면 마스킹이 통째로 죽어 있어도 selftest가 통과한다.

## 3. R2 — specprobe v2

**R1이 R2에 선행한다**(R2가 R1의 반환 필드를 파생한다).

### 3-1. `probe()` export + CLI 껍데기

`export function probe(text, path)`를 만들고 CLI는 그것을 JSON으로 찍는 얇은 껍데기가 된다 —
KF4 R4의 `verify`가 **프로세스 재실행 없이 import**한다(계획서 §4-4). `spec-verify.mjs`의
`isMain` 가드(273행)를 그대로 베낀다.

**파일 없음이 지금은 스택트레이스로 죽는다**(14행 `readFileSync`가 맨몸이다) → 메시지 + `exit 2`로
고친다. 성격은 유지다: **센다. 막지 않고, 판정을 종료 코드에 싣지 않는다** — 사용법·파일 오류만 2,
그 외 0 고정.

### 3-2. `volume` 블록 산출 규칙

기존 출력 4종(`statusLiterals`·`inferenceMarks`·`missingMarks`·`pendingChoice`)은 **원문 리터럴
계수 규칙 그대로** 둔다(펜스·아카이브 미제외 — 과거 기록과의 비교 연속성). 그 옆에 `volume`을 더한다.
전부 `inspect()` 파생이다(파서 중복 구현 금지):

| 값 | 계산 | 주의 |
|---|---|---|
| `activeSentences.S`·`.I` | `c4.ids` 중 접두어 S / I의 수 | 정의는 최초 등장만 — 재등장은 지목이지 문장이 아니다(`inspect()`가 이미 그렇게 센다) |
| `activeSentences.U` | `counts.pending` | 확정돼 §1로 올라간 행은 S로 이미 잡힌다 |
| `activeSentences.otherPrefixes` | S·I 외 접두어(골격 «직접 정의» 프로젝트의 R·T 등)의 `{접두어: 수}` | total에는 **안 넣는다**. 참고용 |
| `inferenceRatio` | `I ÷ (S + I)`, **U 제외** | 재려는 것은 «확정 문장 중 근거 없는 것의 비중»이다. 분모 0이면 `null`. `[추론]` 리터럴 계수(`inferenceMarks`)가 아니라 **ID 기반**인 이유: 리터럴은 산문 인용에 오염된다 |
| `tableRows` | `counts.tableRows` | |
| `archive` | `counts.archive` | |
| `archiveCandidates` | `{ count, ids }` = `c4.located` | §1 표 #5 — 위양성 감수, P-4가 기대값으로 고정 |
| `note` | 문장 ID가 없으면(`c4` null) `activeSentences`를 `null`로 두고 «문장 ID 없음 — 볼륨 판정 불가» | **결측 표기지 판정이 아니다** |

**소수 표기 규칙을 고정하라**(계획서 §6이 «±소수 표기 규칙 고정»으로 남긴 자리): `inferenceRatio`는
셋째 자리 반올림(`Math.round(x * 1000) / 1000`). P-1의 기대값 `0.333`이 이 규칙에서 나온다.

**임계값은 넣지 않는다.** KF5는 값만 내고 판정은 KF4 R4의 `.specgate.json` `volume` 블록이 한다
(계획서 §4-4·§10-8). 시작점 40 · 0.5 · 80은 **계획서 표에만** 있고 코드는 임계를 모른다.

머리 주석 2행(«앵커는 리터럴 4종뿐 — 표 헤더·섹션 제목을 앵커로 쓰지 않는다»)은 volume에는 맞지
않으므로 «**기존 4종에 한한다. volume은 spec-verify 파서 파생값이다**»로 갱신하고, 이 성격 변경을
선택 대기 #9로 올린다(계획서 §10-9).

| P-3 기존 출력 불변 | KA | `statusLiterals`·`inferenceMarks`·`missingMarks`·`pendingChoice`가 v1 산출 규칙과 **동일 값** |
| P-4 근거 위치 위양성 | KA에 S3 추가 — 정의 줄에 `(근거: CONTRACT.md:12)`, 대조표 지목은 `실행 확인` | `archiveCandidates`에 S3 **포함**. §9-10의 알려진 위양성을 **기대값으로 고정**한다 — 고치면 계산 계약이 바뀐 것이다 |

P-3이 회귀 축이다 — v2가 v1 출력을 건드리면 과거 기록과의 비교 연속성이 끊긴다.

### 3-4. `commands/spec.md` 볼륨 보고

**«있으면» 분기에만** 3~5줄 더한다(42~51행). 커맨드 수는 불변이고, 새 커맨드를 만들지 않는다.

- `node "${CLAUDE_PLUGIN_ROOT}/specprobe.mjs" SPEC.md` 한 줄과, 그 출력에서 **사람이 볼 요약
  1~2줄**(활성 문장 수 · [추론] 비율 · 표 행수 · 아카이브 후보 수)을 보고하라는 지시.
- **임계 판정을 문안에 넣지 마라** — KF4 전에는 어떤 도구도 임계를 모르고, 지금은 사람이 계획서
  §4-1 표와 육안 대조한다. 에이전트가 «40을 넘었으니 접자»고 스스로 판단하면 그게 곧 LLM 판정이다.
- 기존 `spec-verify.mjs` 실행 줄은 **그대로 둔다**(`specgate verify`로 바꾸는 것은 이 라운드 범위 밖).

## 4. 검증 (수용 기준)

```bash
node framework/spec-verify.mjs --selftest      # 6장 + V-A1~V-A3
node framework/specprobe.mjs --selftest        # P-1~P-4 (R2)
node framework/specgate.mjs --selftest         # 22건 — T3b가 SG1010 등재를 강제한다
node framework/spec-delta.mjs --selftest       # 회귀 19건
node framework/spec-anchor.mjs --selftest      # 회귀 15건
node framework/hooks/spec-gate.mjs --selftest  # 회귀 23건 (계획서의 «10건»은 낡았다 — §1 표 #2)
```

**수용 기준**: 전건 통과 + **회귀 무변경**. 특히 두 가지를 명시적으로 확인하라:

1. **`spec-verify`의 `EXPECTED` 6장이 한 글자도 안 바뀐다** — 픽스처에 아카이브 절이 없으므로
   값이 변하면 **마스킹이 새고 있는 것**이다(계획서 회귀-1).
2. **`spec-gate --selftest` 23건의 exit가 전부 그대로다** — 훅은 `inspect()` 경유라 무수정이고,
   수정 0이 곧 정합 증거다(계획서 §3 표).

기대값을 고쳐야 통과한다면 **멈추고 원인을 가른다**. r48은 기대값 수정 0건이었다.

실물 1회: 스크래치패드에 실물 SPEC 1장을 복사해 `specprobe`를 돌리고 volume 값을 **육안과 대조**한다
(`framework/smoke/`에서 직접 돌리지 마라 — 읽기만 하면 안전하지만 접기 실험은 실측 원문을 덮는다).
**수치와 육안이 어긋나면 육안이 이긴다** — 불일치는 specprobe 버그로 기록하고 스크립트를 고친다.

## 5. 하지 말 것

- **볼륨으로 차단하지 마라.** pre·stop 어느 훅에도 볼륨 검사를 걸지 않는다. SG1031~1034는
  Warning 전용이고 차단 승격은 금지다 — 조사 Q4(최적 분량 미정량)가 닫히기 전까지 «모르는 값을
  도구가 조용히 강제하는» 자리다.
- **임계값을 코드에 넣지 마라.** 이 라운드의 산출은 **값**이고 판정은 KF4 R4다.
- **자동 아카이브를 만들지 마라.** 접기는 에이전트 제안 + 사용자 승인으로만 일어난다. `/spec`
  문안이 «접었다»가 아니라 «접을 후보다»까지만 말하게 하라.
- **`specprobe`의 기존 출력 4종을 건드리지 마라**(P-3이 감시한다).
- **`hooks/spec-gate.mjs`를 고치지 마라.** 고쳐야만 정합이 되는 자리가 나오면 그것 자체를
  기록하고 멈춘다 — 무수정이 이 설계의 증거다.
- **`archiveCandidates`를 `c4.positions` 파생으로 «개선»하지 마라**(§1 표 #5 — 번복 조건 미충족).
- 2차 문서(요약본·리뷰 보고서·질문 목록 md)를 만들지 마라. 산출물은 여전히 단일 `SPEC.md`
  또는 진행 중 델타 1장이다.

## 6. 선택 대기 갱신 (계획서 §10 — 이 라운드가 닫거나 옮기는 것)

| # | 항목 | 이 라운드의 처리 |
|---|---|---|
