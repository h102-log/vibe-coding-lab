# r50 — KF5 R1+R2: 아카이브 절 + 볼륨 계측

지시서 `docs/next/2026-08-21/r49.md` 집행. 계획서 `docs/next/2026-08-19/plankf5volume.md` §5 WBS의
**R1·R2**를 한 세션에 끝냈다. R3(첫 접기 실측)는 조건부라 범위 밖이다 — 아래 §3의 접기는
스크래치패드 기계 점검이지 R3가 아니다.

## 2. 지시서와 달라진 6건

1. **`아카이브\b`는 실물에서 한 번도 매칭되지 않는다.** `\b`는 ASCII `\w` 기준이라 한글 뒤에서
   절대 성립하지 않는다(실측: `/^##\s+(?:\d+[.)]\s*)?아카이브\b/.test('## 4. 아카이브')` → `false`).
   같은 의도(«아카이브»로 끝나는 낱말만)를 살리는 **부정 전방탐색 `(?![가-힣])`**으로 바꿨다 —
   `## 아카이브되지 않은 것`·`## 4. 아카이빙`은 그대로 배제된다. 지시서대로 썼으면 마스킹이
   통째로 죽고 V-A1이 첫 줄에서 깨진다.
2. **P-3의 재료를 KA → KA + `KA_PEND`로 늘렸다.** KA의 아카이브 절에는 리터럴이 하나도 없어서
   KA만으로는 «v2가 기존 4종을 아카이브 인지로 바꿔도» 통과한다 — V-A3에 지시서가 적용한 논리
   («없으면 죽어 있어도 통과한다») 그대로다. `KA_PEND`에서 `pendingChoice`가 2로 나와야 원문
   계수 유지가 증명된다.
3. **P-2에 exit 계약 2건을 접었다.** 지시서의 «exit 0»(위반 8건짜리 F3에서도 0)에 더해 §3-1이
   신설한 **파일 없음 exit 2**까지 같은 케이스에서 밟는다. 새 분기에 검사 하나(개발 규칙 4).
4. **템플릿 주석의 `선택 대기` 리터럴을 문안으로 바꿨다.** 지시서 §2-4대로 쓰니 템플릿이
   **자기 새 경고(SG1010)를 밟았다** — 정당한 인용이지만 모든 새 SPEC이 SG1010으로 시작하는 건
   나쁘다. «§2.3에서 상태가 확정되지 않은 행은…»으로 바꿨다. (HTML 주석 안 리터럴을 세는 것은
   기존 동작 그대로다 — 템플릿의 C1이 2건 나오는 것도 같은 이유다. 파서는 안 고쳤다.)
5. **픽스처 `KA`를 `spec-verify`에서 export해 `specprobe`가 import한다.** 사본을 두면 두 selftest가
   다른 재료를 보게 되고, 값이 갈라졌을 때 어느 쪽이 참인지 못 가린다.
6. **`CLAUDE.md`의 «specprobe를 에이전트에게 절대 주지 않는다»가 거짓이 됐다** — §3-4가 `/spec`
   문안에 배선하는 순간 그건 계측기가 아니라 도구다. 그 줄을 «r49부터 도구다»로 고쳤다.

지시서 §2-1의 «147~148행 재사용»은 `headId()` 헬퍼 추출로 이행했다 — 두 자리가 같은 2줄을
갖는 것은 재사용이 아니라 복제다.

## 3. 실물 대조 (`framework/smoke/i1-cart-r1/SPEC.md` 사본 — 스크래치패드, 원문은 읽기만)

```
volume: S 11 · I 18 · U 10 · total 39 · ratio 0.621 · tableRows 54
        archive {present:false} · archiveCandidates 28
```

**육안과 전건 일치**(불일치 0 → specprobe 버그 기록 없음):

| 값 | 육안 | 근거 |
|---|---|---|
| S 11 · I 18 | 일치 | 줄 선두 `- S…`/`- I…` 정의 줄 수 |
| U 10 | 일치 | `선택 대기` 13등장 중 미확정표 상태 열은 U1~U10. 나머지 3건(산문 1 · 대조표 인용 1 · 헤딩 1)은 정확히 제외됐다 |
| tableRows 54 | 일치 | `\|` 줄 57 − 구분선 3, 코드펜스 0 |
| ratio 0.621 | 일치 | 18/29 = 0.62069 → 셋째 자리 |
| 후보 28 | 일치 | C4 지목 29/29 중 S11만 vague(«확인함 — `npm run build` 종료 코드 0», 위치 없음) → 29−1 |

**접기 기계 점검 1건**(R3 아님 — 사용자 승인도 실사용도 없는 스크래치패드 조작이다). S1을 §1·§3에서
빼고 아카이브 5열 행으로 옮긴 뒤:

- `spec-verify` **위반 0 유지**(접기 전 0 → 후 0) · C4 분모 **29 → 28**
- volume: total 39→38 · S 11→10 · tableRows 54→53 · `archive {present:true, sentences:1}` · 후보 28→27
- ratio 0.621→**0.643** — 분모(S+I)만 줄어 올라간다. 접을수록 비율 경고에 가까워지는 방향이라
  실사용에서 SG1032와 SG1031이 반대로 움직일 수 있다(§5 한계 3).

## 4. 검증

| selftest | 결과 |
|---|---|
| `spec-verify` | 통과 — **픽스처 6장 무변경** + 인라인 3건 |
| `specprobe` | 통과 — 4건 (신설) |
| `specgate` | 통과 — 22건 무변경 |
| `spec-delta` · `spec-anchor` · `spec-gate` | 통과 — 19 · 15 · 23건 무변경 |

**기대값을 고친 것은 0건이다**(r48에 이어 2라운드 연속). `EXPECTED` 6장은 diff에 한 줄도 없다 —
픽스처에 아카이브 절이 없으므로 그것이 곧 «마스킹이 새지 않는다»의 증거다.

**T3b가 설계 목적대로 작동한 첫 사례**: `C3.archivePending`을 만들고 `RULES`에 등재하기 전에
`specgate --selftest`가 «RULES 미등재: C3.archivePending»으로 즉시 깨졌다. 고친 것은 T3b가 아니라
RULES다.

## 5. 한계 (계획서 §9 유효 + 이 라운드가 관측한 것)

1. **검출력은 0 늘었다.** 볼륨은 아무것도 막지 않고 아무 판정도 내지 않는다 — 값만 낸다.
   임계를 아는 도구는 아직 없다(KF4 R4).
2. **마스킹의 대가**: 접힌 절 ID는 검사기 시야 밖이라 **ID 재사용 충돌을 기계가 못 잡는다.**
   규약은 템플릿 주석 1줄뿐이다. «아카이브» 이름의 타용도 절은 오마스킹된다.
3. **비율 축과 문장 수 축이 반대로 움직인다**(§3 실측). 접기는 total을 내리고 ratio를 올린다 —
   SG1031을 끄려는 조치가 SG1032를 켤 수 있다. 임계 조정 시 함께 봐야 한다.
4. `archiveCandidates`의 근거-위치 위양성은 **고치지 않고 P-4로 고정**했다(§6 #11).
5. HTML 주석 안의 리터럴은 여전히 계수된다(기존 동작). 템플릿이 자기 경고를 밟은 §2-4가 그
   증상이고, 이번엔 문안으로 피했지 파서로 풀지 않았다.

|---|---|---|

## 7. 남은 것

1. **KF4 R4** — `verify`가 `probe()`를 import해 SG1031~1034 Warning 발행 + `.specgate.json`의
   `volume`·`interview` 키 소비. **이 라운드로 조건이 열렸다**(KF5 R1·R2 + KF2 R1 완료). 닫으면
   5개 KF가 전부 종료된다.
2. **r28 작업 ①** — 설치형 트리거 확인(«실사용 개시 전 필수»). r44 §5의 미해결 1건도 여기서 닫힌다.
3. **실사용 2회차(사용자 게이트 G3)** — KF5 R3(첫 접기 실측)는 여기서만 돈다. 임계를 밟으려고
   스펙을 부풀리지 않는다. «형태를 만들었다»와 «자기수정 루프가 돈다» 사이는 여전히 비어 있다.
