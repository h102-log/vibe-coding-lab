# KF5 수정계획서 — 스펙 볼륨 예산 + 수명 관리

## 0. 요약

SPEC.md의 리뷰 부담을 설계 제약으로 만든다. 만드는 것은 둘 — ① `specprobe.mjs` 확장(활성 문장 수 S/I/U · [추론] 비율 · 표 행수 계측, 판정 없음·exit 불변) ② SPEC.md `## 4. 아카이브` 절(구현·검증이 끝난 문장을 접어 활성 본문을 현재 진행분으로 유지)과 그에 맞춘 `spec-verify.mjs`의 아카이브 절 제외 확장. 약속하지 않는 것 — 최적 분량의 결정(조사 Q4 — 미정량), 볼륨에 의한 차단(경고 전용), 사용자 승인 없는 자동 아카이브, 요약 문서 등 2차 산출물. 신규 파일은 0개다 — 기존 4파일(specprobe·spec-verify·spec-template·commands/spec.md)의 확장만으로 한다.

## 1. Pain Point와 근거

- **지배 비용은 생성된 스펙의 인간 리뷰다**(조사 F1). 원 요청 원문: «기존 SDD가 죽은 원인이 코드 리뷰가 아니라
  생성된 스펙 문서의 인간 리뷰였기 때문입니다(3.5시간 중 코드 리뷰는 30분)» — 2,577줄 스펙의 실측이다.
  읽히지 않는 스펙은 가짜 안심의 문서판이다.
- **성장은 설계상 필연이다.** KF1의 «SPEC.md는 도구를 거친 변경의 누적으로 자란다» 아래서 델타 병합마다 본문이
  는다(원 요청: «델타가 계속 병합되면 SPEC.md는 무한 성장»). 게다가 템플릿 §3.1이 S·I 전건을 대조표에 다시 싣는
  골격이라 문장 1개가 표 행 1개를 더 만든다 — 증가 속도는 최소 2배다.
- **리포 실측의 규모감**: 과제 하나짜리 실물 SPEC(i1-cart)에서 `선택 대기`가 이미 10행(r35 판정 IV), sd1-cart는 C5 위반만 9건(`hooks/spec-gate.mjs` selftest 주석). 과제 하나에 이 규모다.
- **Stop 훅 마찰과의 연결**: FIELD-GUIDE 예언 P2 — Stop 훅의 전 문장 대조 요구는 «제일 먼저 끄고 싶어질 것»이고 본문이 클수록 커진다. 아카이브는 완료·검증 문장을 그 분모에서 뺀다(§4-3).
- **경고여야 하는 근거**(조사 Q4): «2,577줄도 0줄도 반증됐지만 그 사이의 최적점을 정량화한 소스가 없습니다(Q4).
  모르는 값을 도구가 조용히 강제하면 안 되므로, 임계값 자체를 기본값 + 선택 대기로 노출합니다»(원 요청).
  그래서 SG1031~1034는 Warning 전용이고 차단 승격을 금지한다(메인 §5-2).

## 2. 목표 / 비목표

**목표**

1. 볼륨 계측 3종(활성 문장 수 S/I/U · [추론] 비율 · 표 행수)과 아카이브 파생값(접힌 문장 수 · 아카이브 후보 수)을
   **결정론적으로**(같은 입력 → 같은 값, LLM 0) 산출한다.
2. `## 4. 아카이브` 절로 활성 본문을 «현재 진행분»으로 유지하는 수명 관리 경로를 연다 — 접기는 삭제가 아니라
   이동이고, 원문·최종 지목·근거가 보존된다.
3. `spec-verify.mjs`가 아카이브 절을 C4 분모에서 제외해 접기가 게이트(특히 Stop)와 정합하게 한다 — 기존
   selftest 6장 기대값 무변경이 조건이다.
4. KF4가 SG1031~1034 Warning을 낼 수 있도록 값 계약(JSON 필드 명세)을 고정한다.

**비목표**

- 최적 분량을 정하지 않는다 — 임계 기본값은 임의의 시작점이고 실사용 관측 항목이다(조사 Q4).
- 볼륨으로 차단하지 않는다 — pre·stop 어느 훅에도 볼륨 검사를 걸지 않는다.
- 자동 아카이브를 하지 않는다 — 접기는 에이전트 제안 + 사용자 승인으로만 일어난다.
- 문서 품질을 판단하지 않고, LLM 요약본·리뷰 보고서 등 2차 문서를 만들지 않으며, 파이프라인 단계를 더하지 않는다 — 산출물은 여전히 단일 SPEC.md 또는 진행 중 델타 1장이다.

## 4. 설계

### 4-1. 볼륨 계측 — specprobe v2

specprobe의 성격은 유지한다: **센다. 막지 않고, 판정을 종료 코드에 싣지 않는다**(사용법·파일 오류만 exit 2,
그 외 0 고정). Warning으로 바꾸는 것은 KF4 CLI가 이 값을 읽어 SG103x로 내는 시점이고, **그 전에는 출력만
있다.** 출력은 기존 4종을 그대로 두고 `volume` 블록을 더한다:

```json
{
  "spec": "SPEC.md",
  "statusLiterals": "…", "inferenceMarks": 5, "missingMarks": 0,
  "pendingChoice": { "all": 6, "pipeRowCount": 4 },
  "volume": {
    "activeSentences": { "S": 12, "I": 5, "U": 4, "total": 21, "otherPrefixes": {} },
    "inferenceRatio": 0.294,
    "tableRows": 41,
    "archive": { "present": true, "sentences": 9, "pendingInArchive": 0 },
    "archiveCandidates": { "count": 13, "ids": ["S1", "S2", "…"] },
    "note": null
  }
}
```

산출 규칙(전부 `spec-verify.mjs`의 `inspect()` 파생 — 코드펜스 밖·아카이브 절 밖만 본다):

- **활성 문장 수** — `S` = `c4.ids` 중 접두어 S인 것의 수, `I` = 접두어 I, `U` = `counts.pending`(미확정표에서
  상태가 `선택 대기`인 행 수 — 확정돼 §1로 올라간 행은 S로 이미 잡힌다). `total` = S+I+U. 다른 접두어(골격 «직접
  정의» 프로젝트의 R·T 등)는 세지 않되 `otherPrefixes`에 참고로 싣는다. 정의는 최초 등장만 — 재등장은 지목이지 문장이 아니다.
- **[추론] 비율** — `inferenceRatio` = I ÷ (S + I). U 제외 근거: U는 문장이 아니라 대기 행이고, 재려는 것은
  «확정 문장 중 근거 없는 것의 비중»이다. 분모 0이면 `null`. `[추론]` 리터럴 계수(기존 `inferenceMarks`)가
  아니라 ID 기반인 이유: 리터럴은 산문 인용에 오염된다.
- **표 행수** — `counts.tableRows` = 아카이브·펜스 밖 모든 표의 행 수(헤더 포함, 구분선 `---` 제외).
- **아카이브 파생값** — `archive.sentences` = 아카이브 절 안 줄 선두(표 첫 셀·리스트 마커 뒤) 문장 ID 수.
  `archiveCandidates` = `c4.located`(= hit − vague — **문서 안 «파일:줄» 보유 줄 어딘가에서 언급된**
  활성 문장. 기존 계산 그대로라 정의 줄을 제외하지 않는다 — 정의 줄의 근거 표기 «(근거: 문서:줄)»도
  위치 보유로 세는 위양성이 있다. §9-10, 대안은 §10-11).
  `pendingInArchive` = 아카이브 절 안 `선택 대기` 리터럴 수(0이어야 정상).
- 문장 ID가 없으면(`c4` null) `activeSentences`는 `null`, `note`에 «문장 ID 없음 — 볼륨 판정 불가». 결측 표기지 판정이 아니다.

기존 4종(statusLiterals 등)은 **원문 리터럴 계수 규칙 그대로** 둔다(펜스·아카이브 미제외 — 과거 기록과 비교
연속성). 머리 주석의 «표 헤더·섹션 제목을 앵커로 쓰지 않는다»는 «기존 4종에 한한다. volume은 spec-verify 파서
파생값이다»로 갱신하고, 이 성격 변경은 §10 #9에 선택 대기로 올린다. `--selftest`의 exit 0/1은 자기검사 결과지
SPEC 판정이 아니다(spec-verify 선례). 파일 없음은 현재 스택트레이스로 죽는데 v2에서 메시지 + exit 2로 고친다.

**임계 기본값 — 임의의 시작점이다.** 유일한 앵커는 양끝 반증(0줄도 2,577줄도 실패, 조사 Q4 — 사이 최적점 정량화
소스 없음)뿐이므로 사이 값은 찍고 실사용으로 조정한다. KF4 전에는 도구가 임계를 모른다 — 사람이 `/spec` 보고의 수치를 이 표와 육안 대조한다.

| 값 | 시작점 | 초과의 뜻(Warning 문안 방향) |
|---|---|---|
| `activeSentences.total` | 40 | 활성 본문이 리뷰 예산을 넘고 있다 — 아카이브 후보를 보라 |
| `inferenceRatio` | 0.5 | 확정 문장의 절반 이상이 추론이다 — 확정 절차(§2)로 되돌려라 |
| `tableRows` | 80 | 표가 본문을 삼키고 있다 — 대조표·미확정표 정리 시점 |

### 4-2. 아카이브 절 — 형식·진입 조건·접기 절차

`spec-template.md`에 추가하는 골격(코드블록은 템플릿 실물 형식):

```markdown
## 4. 아카이브

<!-- 구현·검증이 끝난 문장을 옮겨 보존한다. 삭제가 아니다 — 원문·최종 지목을 남긴다. 진입 조건:
     ① §3.1에 파일:줄 지목 ② spec-verify 위반 0 ③ 드리프트 0(감시 도구 전에는 사람 확인). 접기는 에이전트
     제안 + 사용자 승인으로만 한다. 이 절은 검사기(C4)·Stop 게이트 분모에서 빠진다.
     새 문장 ID는 아카이브 포함 문서 전체의 최대 번호 +1로 매긴다 — 재사용하지 않는다. -->

| ID | 문장(원문 그대로) | 최종 지목 | 접은 날짜 | 근거 |
| --- | --- | --- | --- | --- |
| S0 | 카운터가 화면에 렌더된다. | src/app.ts:12 | 2026-08-20 | verify 0위반 · 사용자 승인 |
```

**진입 조건 — 시기별 사다리.** «드리프트 0»은 KF3②(spec-anchor drift) 후에만 기계로 완전하다:

| 시기 | 기계로 확인하는 것 | 사람 몫 |
|---|---|---|
| KF3 전 (지금) | ① 해당 문장이 `c4.located`에 있다(파일:줄 지목 보유 — §9-10의 위양성 유의) ② `spec-verify` 위반 0 | 지목 위치가 지금도 유효한지 열어 확인 + 승인 |
| KF3①(실증기) 후 | + ③ `spec-anchor record`의 A1(파일 실존)·A2(줄 범위 유효) 통과 | 승인 |
| KF3②(드리프트) 후 | + ④ 해당 문장 앵커의 `drift` 결과 0 | 승인 |

**기각(REMOVED) 문장은 이 절의 대상이 아니다.** 아카이브는 «구현·검증 완료» 보존이고, 기각 문장은
진입 조건 ①(파일:줄 지목)을 원리적으로 못 채우며 5열 표의 «최종 지목»도 채울 수 없다. KF1 델타의
REMOVED는 삭제(이력은 git)로 남는다 — «기각 보존» 하위 구획의 신설 여부는 KF1 병합 규칙 확정
라운드에서 합동 확정한다(메인 §10-4).

**접는 절차 — 누가 접는가: 에이전트 제안 + 사용자 승인.** 5단계다.

1. 계기 — `/spec` 실행 시 볼륨 값이 시작점 초과(KF4 후에는 SG1031 Warning), 또는 사용자의 직접 정리 요청. 도구가 스스로 세션을 끊고 나서지 않는다(중단 0 원칙).
2. 에이전트가 후보 표를 제시한다 — ID·문장·최종 지목·진입 조건 충족 근거. **제안만 한다.** 승인 전 수정 금지.
3. 사용자가 승인한다. 부분 승인(ID 열거)이 된다.
4. 에이전트가 Edit로 옮긴다 — 승인 문장을 §1(또는 §2.2)·§3.1 대조표에서 제거하고 `## 4. 아카이브`에 5열 행으로 추가. `선택 대기` 행은 어떤 경우에도 접지 않는다(«구현·검증 완료»가 진입 조건이다).
5. `spec-verify` 재실행으로 위반 0 확인. 위반이 나면 옮긴 것을 되돌리고 원인을 로그로 남긴다.

### 4-3. spec-verify.mjs의 아카이브 절 제외 확장

- **탐지**: 코드펜스 밖에서 `^##\s+(?:\d+[.)]\s*)?아카이브\b`에 걸리는 헤딩 줄부터 다음 `^##\s` 헤딩
  직전(또는 파일 끝)까지. 걸리는 헤딩이 여럿이면 각각 적용한다.
- **마스킹**: `stripFences` 직후 아카이브 절 줄을 빈 줄로 바꾼다. 단 **C1의 `[추론]` 계수만은 마스킹 전
  원문으로 센다** — 추론 문장이 전부 접힌 성숙한 SPEC에서 C1이 위양성으로 pre 게이트를 막지 않게 하기
  위해서다. 결과적으로 C2~C5의 표·정의·지목 대조 전부에서 아카이브 절이 빠진다 — 메인 §5-3의
  «아카이브 문장을 검사 분모에서 제외»가 이것이다. 마스킹 범위가 C4 한정이 아니라 C2~C5인 이유:
  접힌 표 행을 C3(미확정표)·C5(재확인)가 계속 세면 접기가 새 위반을 만든다. 범위 자체는 §10-10
  선택 대기로 노출한다.
- **경고 1건 신설**: 마스킹 영역에 `선택 대기` 리터럴이 있으면 경고 — «아카이브 절에 선택 대기 행 —
  미확정은 아카이브 자격이 없다.» 정당한 인용일 수 있어 차단이 아니다. SG 번호는 KF4에서 배정(§10 #7).
- **반환 확장(additive)**: `counts.tableRows` · `counts.archive = { present, sentences, pendingInArchive }` ·
  `c4.ids`(정의된 활성 ID 배열) · `c4.located`(파일:줄 지목 보유 ID 배열 = hit − vague — 정의 줄
  미제외, §9-10). 기존 필드 불변.
- **게이트 자동 반영**: `hooks/spec-gate.mjs`는 `inspect()`를 import하므로 **무수정으로** Stop 검사에서
  아카이브 문장의 재지목 요구가 사라진다. P2 마찰의 구조적 완화다.

### 4-4. KF4 값 계약 — SG1031~1034 (배선은 KF4 R4 몫 — `verify`가 `probe()`를 읽어 발행. 필드는 여기서 고정)

specprobe v2는 `export function probe(text, path)`를 제공하고 CLI는 이를 JSON으로 찍는 얇은 껍데기다. KF4의 단일 CLI는 프로세스 재실행 없이 import한다.

| 룰 | 읽는 필드 | 발동 조건(기본값 기준) | 심각도 |
|---|---|---|---|
| SG1031 | `volume.activeSentences.total` | > 40 | Warning |
| SG1032 | `volume.inferenceRatio` | > 0.5 | Warning |
| SG1033 | `volume.tableRows` | > 80 | Warning |
| SG1034 | `volume.archiveCandidates.count` | SG1031 발동 중이고 count ≥ 1 — «후보 N건, 접기 제안» | Warning |

넷 다 Warning 전용, 차단 승격 금지(메인 §5-2 — 조사 Q4). 임계값은 KF4의 `.specgate.json` `volume`
블록으로 들어가되 기본값은 위 표다. KF4 전에는 어떤 도구도 임계를 판정하지 않는다. **발행·저장
배선을 WBS로 갖는 라운드는 KF4 R4다**(KF4 §5) — 이 문서는 값 계약만 정의한다.

### 4-5. 실패 모드

- SPEC 파일 없음 → specprobe exit 2 + 메시지(판정 아님, 사용법 계열).
- «아카이브» 이름의 타용도 절은 오마스킹된다(헤딩 정규식이라 산문 오탐은 없다) — `archive.present` 출력으로 육안에서 잡는다(§9-7).
- 접기 후 spec-verify 위반 → 절차 5단계에서 되돌린다(되돌림도 Edit, 로그 한 줄).
- volume 수치와 육안 불일치 → **육안이 이긴다.** 불일치는 specprobe 버그로 기록하고 고친다.
- KF4 전 임계 초과 → 아무 일도 자동으로 일어나지 않는다. `/spec` 보고에서 사람이 본다.

- **읽기**: 순증은 spec-template 주석 ~10줄(프로젝트당 1회성)과 specprobe JSON ~15줄(기계 출력 — 사람은 `/spec`

  (이동일 뿐) 리뷰 대상인 활성 본문과 Stop 게이트의 대조 분모를 줄인다(P2 완화).
- **중단**: 0회. 훅에 볼륨 검사를 걸지 않고 SG1031~1034는 Warning 전용이다. 접기 승인 1회는 사용자가 `/spec`을
  부른 대화 안의 응답이지 도구가 만든 인터럽트가 아니다.
- **화폐**: LLM 신규 패스 0. 계측·마스킹·후보 산출 전부 정적이고, 접기 제안·Edit은 이미 돌고 있는 세션 안에서 일어난다.

- **공통 전제**: r38 관문 A-3(설치 형태 차단 확인) 통과 + 실사용 투입 개시. 전 KF 공통이다.

## 9. 명시적 한계

1. **임계값·아카이브 규칙은 «설계 판단»이고 최적점은 실사용 관측 항목이다**(원 요청 KF5의 명시 한계, 조사 Q4).
2. 임계 기본값(40 · 0.5 · 80)은 **임의의 시작점**이다. 유일한 앵커는 양끝 반증(0줄도 2,577줄도 실패)뿐이다.
3. 문장 수·표 행수는 읽기 부담의 **대리 지표**다 — 문장 길이·밀도·난도는 재지 않는다.
4. 볼륨 계측은 문장 ID 규약(S/I/U)에 의존한다. ID 없는 SPEC은 volume이 결측이다 — C4 «판정 불가»와 같은 결이고, ID를 안 붙이는 우회(FIELD-GUIDE P3)에 같이 뚫린다.
5. 아카이브 진입의 «검증 완료»는 KF3② 전에는 기계 판정이 불완전하고 대체 조건은 사람 확인에 기댄다 — F3(빈손
   완료 신고)의 재유입 경로일 수 있다. C4의 알려진 한계도 상속한다: 지목 보유는 «ID를 위치와 함께 다시 적었다»이지 구현 사실의 증명이 아니다(README·r36 §9-2에 명문).
6. 접힌 문장은 «참이었다»는 기록이지 «지금도 참»의 보증이 아니다. KF3② 전에는 아카이브 부패를 감지할 수단이
   없고, KF3② 후에도 앵커가 안 바뀐 의미 변화는 놓친다(KF3의 한계 상속).
7. 마스킹의 대가: 아카이브 절 ID는 검사기 시야 밖이라 **ID 재사용 충돌을 검사기가 못 잡는다**(«최대 번호 +1»
   규약은 템플릿 주석 1줄뿐이다). «아카이브» 이름의 타용도 절은 오마스킹된다(§4-5).
8. Warning은 무시할 수 있다. 경고가 리뷰 행동을 바꾼다는 실측은 없다 — 차단이 품질을 올린다는 통제 비교조차
   없고(조사 Q1), 경고는 그보다 약한 개입이다. 이 기능의 효과 자체가 실사용 관측 대상이다.
9. «육안이 이긴다»는 volume 블록에도 적용된다 — 수치와 육안이 어긋나면 육안을 기록하고 스크립트를 고친다.
10. **`archiveCandidates`(= hit − vague)에는 근거-위치 위양성이 있다.** 기존 located 계산은 정의 줄을
    제외하지 않으므로, 지목이 «실행 확인»뿐인 문장도 정의 줄의 근거 표기(«(근거: 문서:줄)») 덕에
    후보로 오를 수 있다(P-4가 이 동작을 기대값으로 고정). 사람 승인이 뒤에 있어 실해는 제한적이다.
    KF3①의 `c4.positions`(정의 줄 제외)가 생기면 그 파생으로의 교체를 검토한다(§10-11).
