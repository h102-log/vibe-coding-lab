## 2. selftest가 못 잡은 버그 1건 — 손검증이 잡았다

CLI 인자 파싱에서 `--base`가 없으면 `rest.indexOf('--base')`가 `-1`이 되고, `-1 + 1 = 0`이
«--base의 값» 인덱스로 취급돼 **첫 인자를 삼켰다.** 콜드스타트 verify 전부가 `usage` + exit 2로
죽는 버그였는데, selftest가 `inspectDelta()`만 직접 부르므로 9건 전건 통과 상태로 숨어 있었다.

계획서가 «인라인 픽스처»로 잡은 대가가 이것이다. 라운드 3의 게이트 selftest는 실프로세스라
(`spec-gate.mjs` 선례) 이 층이 덮이지만, **라운드 2의 merge selftest는 mkdtemp 실파일이므로
CLI 경로를 반드시 통과시켜야 한다** — 같은 구멍이 병합에서 반복되면 파일을 망친다.

## 3. 계획 밖에서 A-3가 열렸다 (그리고 오차단 1건)

`framework/spec-delta.mjs`를 쓰려는 첫 Write를 **specgate 자신의 훅이 막았다.**

```
PreToolUse:Write hook error: [node "${CLAUDE_PLUGIN_ROOT}/hooks/spec-gate.mjs" pre]:
SPEC.md가 없다. … 막힌 것: C:\Users\bhy99\proj\proj3\framework\spec-delta.mjs
```

이것이 r38 관문 A-3의 답이다 — **설치 형태에서 훅이 돌고 `${CLAUDE_PLUGIN_ROOT}`도 치환된다.**
`specgate@proj3` v0.1.0은 2026-08-17에 user scope로 이미 설치돼 있었다(A-1·A-2도 그때 통과했다는 뜻).
차단은 `.specgate-log.jsonl`에 1줄로 기록됐다. 계획하고 얻은 실측이 아니라 걸려 넘어져 얻은 것이다.

동시에 이 사건은 **오차단**이다(FIELD-GUIDE 사건 4분류). `proj3`는 specgate의 대상 프로젝트가
아니라 개발 리포이고, CLAUDE.md 프레임워크 개발 규칙은 sdd 절차를 요구하지 않는다. 여기서
갈라져 나온 사실이 셋이다:

1. **user scope 설치는 모든 프로젝트에 건다.** 게이트가 필요 없는 리포에도 걸린다 — README
   선택 대기 #3(플러그인 루트)·#4(확장자)와 다른 **새 축: 설치 범위**다.
2. **`claude plugin uninstall`이 실행 중 세션의 훅을 끄지 못한다.** 등록에서는 즉시 빠지는데
   세션은 시작 시 로드한 훅 정의를 놓지 않는다. 배포 관점에서 «끄고 싶어진 순간»(FIELD-GUIDE
   멈춤 조건 ③)에 즉시 못 끈다는 뜻이다.
3. **`source: directory` 마켓플레이스는 `${CLAUDE_PLUGIN_ROOT}`가 캐시가 아니라 리포 자신을
   가리킨다**(`known_marketplaces.json`의 `installLocation` = `C:\Users\bhy99\proj\proj3`).
   캐시(`~/.claude/plugins/cache/proj3`)는 파생 사본이라 지워도 훅이 계속 돌았다.

**우회는 하지 않았다.** Bash로 파일을 만들면 지나갈 수 있었지만(README 한계 1이 명시한 그 구멍),
게이트를 만드는 쪽이 자기 게이트를 우회하면 그 도구는 신뢰를 잃는다. 대신 사용자에게 물어
«플러그인 해제»를 택했고, 세션이 놓지 않아 `spec-gate.mjs`를 작업 동안 `.OFF`로 비켜뒀다가
**즉시 원복했다**(현재 `framework/hooks/`는 원상태).
