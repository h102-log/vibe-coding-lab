# 계획서 세트 사용 가이드 — planmain.md는 무엇이고, 다음에 뭘 하나

작성 2026-08-19. 대상 독자 = 다음 코드 라운드를 여는 사람.
이 문서는 **조망의 조망**이고 사실의 SSOT가 아니다 — 어긋나면 `planmain.md` §5 > 세부 계획서 > 이 문서 순으로 이긴다.

## 1. planmain.md가 하는 일

`docs/next/2026-08-19/`에 계획서가 **6장** 있다. planmain은 그중 **조망 1장**이고, 나머지 5장이 실제 작업 지시서다.

| 문서 | 무엇 |
|---|---|
| `planmain.md` (309줄) | 전체 조망 — 헌법(3예산) · 5기능 개요 · 상호 연결 · 착수 순서 · 공통 이름/번호 규약 · 진행 게이트 · 세트 수준 선택 대기 5건 |
| `plankf1delta.md` (380줄) | KF1 델타 스펙 수정 루프 (`spec-delta.mjs`) |
| `plankf2interview.md` (281줄) | KF2 예산제 침묵 인터뷰 (`spec-interview.mjs`) |
| `plankf3anchor.md` (282줄) | KF3 지목 실증기 + 드리프트 감시 (`spec-anchor.mjs`) |
| `plankf4ruleset.md` (307줄) | KF4 SG 룰셋 + 단일 CLI (`specgate.mjs`) |
| `plankf5volume.md` (298줄) | KF5 볼륨 예산 + 아카이브 (신규 파일 0) |

**planmain을 들고 코드를 짜지 않는다.** 코드 라운드는 세부 1장만 열고 시작한다(라운드당 1장 — 계획서 세트 자체가 1,860줄이라 전부 읽으면 그게 곧 §8이 경고한 «계획의 읽기 비용»이다).

planmain을 여는 때는 셋뿐이다:
- 어느 KF부터 할지 고를 때 (§2 개요표 · §4 착수 순서)
- 세부 문서가 이름·번호·경계를 물어올 때 (§5 — 여기가 SSOT)
- 새 기능을 채택할지 판단할 때 (§1 헌법 — 세부 §7이 없으면 채택 불가)

**핵심 한 줄(§8 Q1):** 이 다섯 중 효과가 실측된 건 **아직 없다.** «차단 게이트가 작동한다»($0.36 프로브)까지만 확인됐고 «차단이 품질을 올린다»는 통제 비교는 존재하지 않는다. 다섯은 검증된 처방이 아니라 실패 증거로부터의 추론이다.

## 2. 지금 리포의 실제 상태 (계획 대비)

계획서가 쓰인 뒤 리포가 앞서 나간 곳이 셋 있다. **계획서 본문은 이 셋을 모른다.**

|---|---|---|
| 계획서 반입 | §10-5 기본값 = «반입하지 않음» | **이미 반입됨** (커밋 c1ab6b8). 선택 대기 #5는 사실상 반입으로 닫혔다 |
| KF1 착수 | 전제 관문 A-3 · G3 통과 후 | **R1이 절반 진행 중, 미커밋** (아래) |
| A-3 관문 | 미확인 | **정황상 통과** — `.specgate-log.jsonl`에 실차단 1건이 남았다. 단 그게 플러그인 설치 경로였는지 직접 등록이었는지는 로그로 갈리지 않는다 → **다음 세션에서 확인할 것** |

**미커밋 작업 = KF1 라운드 1 (§5 WBS 1행) 중 2/3.**

- `framework/spec-verify.mjs` — 파서 유틸 export 완료(`cellsOf`·`stripFences`·`tables`·`SENT_ID`·`expandRanges`·`mentions`) + `POS` 정규식을 함수 안에서 모듈 스코프로 승격해 export. **additive이고 회귀 무변경 확인됨**(2026-08-19 실행: `spec-verify --selftest` 6장 전건 · `spec-gate --selftest` 10건 전건 통과).
- `framework/delta-template.md` — 신규, 완료.
- `framework/spec-delta.mjs` — **없다. 게이트가 막았다.** 로그 1건이 그것이다:
  `{"mode":"pre","file":"framework/spec-delta.mjs","first":"SPEC.md가 없다..."}`

즉 **specgate가 자기 자신의 개발을 막고 있다.** 이 리포 루트에 `SPEC.md`가 없고 `.mjs`는 게이트의 `SRC` 대상이기 때문이다(`.md`는 대상이 아니라 delta-template은 통과했다).

## 3. 다음에 할 일 — 순서대로

### ① 막힌 것부터 푼다 (이번 세션 첫 5분)

선택지는 둘이고, **CLAUDE.md 하네스 절이 (b)를 명시한다.**

- (a) 이 리포 루트에 `SPEC.md`를 쓴다 → 게이트 아래서 개발한다. 도그푸딩이라 관측값이 나오지만, 이 리포는 실험 기록 리포라 SPEC 골격이 안 맞는다.
- (b) **시험 설치를 해제한다**(`/plugin uninstall specgate@proj3`) → 게이트 시험은 리포 밖 스크래치에서만. CLAUDE.md 하네스 절이 정한 방식이고, 실험자 세션 오염도 막는다. **기본값 권장.**

어느 쪽이든 **Bash로 파일을 만들어 게이트를 우회하지 않는다** — 우회 유혹이 생겼다는 사실 자체가 FIELD-GUIDE §1의 관측 대상이니, 우회하기 전에 한 줄 적는다.

### ② A-3을 말로 닫는다 (질문 1개)

로그의 차단 1건이 **플러그인 설치 형태**였는지 확인한다. 맞으면 r38 작업 A 완료 → 관문 A-3 통과로 기록하고 planmain §0의 전제에서 지운다. 아니면 r38 작업 A를 그대로 한다(스크래치 프로젝트에서).

### ③ KF1 라운드 1을 끝낸다

남은 산출물은 `spec-delta.mjs` 하나다 — `inspectDelta` + `verify` CLI + `--selftest` V1~V9(인라인 픽스처, `plankf1delta.md` §6 표가 케이스 전문). 완료 기준은 selftest 전건 + 아래 §4 회귀 3줄.

### ④ 그 다음 = 계획이 정하지 않는다

planmain §4: P1(KF1·KF2·KF3①·KF5) 안의 **순서는 실사용이 정한다**(선택 대기 #3). KF1 R1을 끝내고 나면 두 갈래다.

- KF1 R2·R3으로 계속 (merge → 게이트 분기)까지 밀어 «델타 루프»를 완성한다
- 또는 여기서 멈추고 **r38 작업 B(실사용 투입)**를 먼저 한다 — G3(실수요) 통과가 조건이고, **억지 과제는 금지**다.

계획서 정신은 후자 쪽이다(§4 «실사용에서 무엇이 아쉬웠는지가 정한다»). 다만 KF1 R1이 반쯤 열려 있으니 **최소한 R1은 커밋 가능한 상태로 닫고** 갈라지는 게 낫다.

## 4. 매 라운드 체크리스트

**착수 전**
1. 세부 계획서 **1장만** 연다. §5 WBS에서 이번 라운드 행을 고른다.
2. 공유 파일(`spec-verify.mjs`·`hooks/spec-gate.mjs`·`commands/spec.md`)을 건드리는가? → **다른 KF와 병행하지 않는다**(§4 직렬화 규칙).

**종결 조건 — 예외 없이 3줄**(planmain §7 층 2)
```bash
node framework/spec-verify.mjs --selftest      # r32 픽스처 6장 기대값 무변경
node framework/hooks/spec-gate.mjs --selftest  # 기존 10건 exit 무변경 (추가만 허용)
# verify-tdd.mjs · framework/smoke/ · framework/verify-eval/ 는 무접촉(읽기만)
```
기대값을 **고쳐야** 통과한다면 판정이 바뀐 것이다 → 멈추고 원인을 가른다.

**라운드 실패 판정**(프레임워크 개발 규칙 1): 산출물이 판정 문서 한 장이면 실패한 라운드다. 코드가 돌고 난 뒤 문서를 짧게 남긴다.

**조용한 확정 금지**(규칙 6): 기본값으로 진행해도 되지만 `선택 대기` 행에 기본값·대안·번복 조건을 남긴다.

## 5. 자주 틀릴 곳

- **planmain §5를 세부가 이긴다고 착각** — 이름·번호·경계는 planmain §5가 SSOT다. 설계 상세만 세부가 SSOT.
- **SG 번호를 미리 붙임** — 룰 목록이 안정될 때까지 KF4는 열지 않는다(재번호 비용). 예약 블록은 §5-2에 있지만 **도입은 KF4에서 일괄**.
- **`.specgate.json`을 KF2·KF5에서 만듦** — 설정 파일은 **KF4에서 도입**한다. 그전까지 KF2는 제안만, KF5는 문서 상수만.
- **drift·record를 훅에 배선** — 하지 않는다(§5-3). Stop에 걸면 FIELD-GUIDE 예언 P2를 재생산한다.
- **`exp*/`·`framework/smoke/` 수정** — 절대 규칙 1·6. 읽기만.
- **KF2 효과 보고 시 병기 누락** — r31 대조군이 반증 방향이다. «모델 기본 행동일 수 있다»를 **반드시 병기**한다.
