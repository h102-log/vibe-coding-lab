# proj3 — 바이브 코딩 프레임워크

Claude Code용 자체 바이브 코딩 프레임워크(TDD + SDD, 페이즈별 컨텍스트 분할)를 만드는 프로젝트.

**지금 단계는 프레임워크가 아니다.** 프레임워크 없이 돌린 베이스라인이 *실제로 무엇을 틀리는지* 먼저 관측하고, 그 실패만 고치도록 설계한다. 순서를 바꾸면 프레임워크가 추측이 된다.

```
1. 조사            → docs/analysis/   (완료)
2. 완성 조건·실험 설계 → docs/next/       (완료)
3. AC 동결 + 채점기   → exp/            (완료)
4. (a) 베이스라인 실행 → exp/runs/       ← 지금
5. 관측된 실패만 고치는 최소 프레임워크
6. (b) 처치군 실행 → 비교 리포트
```

## 폴더

| 경로 | 무엇 |
|---|---|
| `docs/` | 조사 정리, 다음 할 일(rN), 다듬지 않은 생각 |
| `exp/` | 비교실험 — 동결 AC, 채점기, 시드, 실행 산출물 |
| `*.md` (루트) | 2026-07-30 조사 원문 3건. 요약은 `docs/analysis/` |

## 어디부터 읽나

1. `exp/FROZEN.md` — 실험 설계의 SSOT. 여기 안 적힌 건 확정된 게 아니다
2. `docs/next/` 최신 rN — 오늘 뭘 해야 하는지
3. `docs/analysis/2026-07-30-조사-핵심정리.md` — 왜 이렇게 설계했는지의 근거

## 손대면 안 되는 것

`exp/` 안의 동결 자산과 실측 원문 — `ac/`, `seed/`, `todo-a/`, `runs/`의 기존 파일. 파일을 **추가**하는 것만으로 동결이 깨지는 곳도 있다. 이유는 `exp/README.md`.
