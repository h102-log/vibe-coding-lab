# SPEC — Todo 앱 (구현 전 확정)

작업 문서. 구현 산출물이 아니다.
근거 위치는 「구현 계약 — Todo 앱(얇은 판)」의 절 이름으로 단다. 계약에서 읽어낼 수 없는 것은 `[추론]`.

판정 대상은 `src/App.tsx`의 default export를 렌더한 화면과 저장소의 파일 상태다.

---

## 1. 명시된 것

### 1-1. 고정 자산

- **M1** — 앱의 렌더링 진입점은 `src/App.tsx`의 default export 컴포넌트다. 〔§고정된 것〕
- **M2** — 의존성에 Vite·React·TypeScript 외의 UI 프레임워크가 추가되지 않는다. 〔§고정된 것〕
- **M3** — `tests/ac/**`의 파일은 내용이 변경되지 않고, 삭제·이동되지 않는다. 〔§고정된 것〕
- **M4** — `package.json`의 `build`·`test:ac` 스크립트 문자열이 변경되지 않는다. 〔§고정된 것〕
- **M5** — `tsconfig.app.json`의 `"strict"`가 `true`로 남는다. 〔§고정된 것〕
- **M6** — `src/App.css`·`src/index.css`의 내용이 변경되지 않고, 새 스타일 파일(`.css`·`.scss` 등)이 추가되지 않는다. 〔§범위 밖〕

### 1-2. DOM 계약

- **M7** — 화면에 `data-testid="todo-input"`인 요소가 정확히 1개 있고, 그것은 텍스트를 입력할 수 있는 입력창이다. 〔§DOM 계약〕
- **M8** — 항목 n개가 있을 때 `data-testid="todo-item"`인 요소가 n개 렌더된다(n=0이면 0개). 〔§DOM 계약〕
- **M9** — 각 `todo-item`의 후손에 `todo-title`·`todo-toggle`·`todo-delete`가 각각 정확히 1개씩 있다. 〔§DOM 계약 — "항목 하나"〕
- **M10** — `todo-title`의 텍스트는 그 항목의 제목과 같다. 〔§DOM 계약〕
- **M11** — `todo-toggle`은 완료 여부를 나타내는 체크박스다. 〔§DOM 계약〕
- **M12** — `todo-delete`는 그 항목을 삭제하는 버튼이다. 〔§DOM 계약〕
- **M13** — 화면에 `data-testid="todo-count"`인 요소가 1개 있고, 미완료 항목 개수를 표시한다. 〔§DOM 계약〕
- **M14** — 화면에 `filter-all`·`filter-active`·`filter-completed`인 요소가 각각 1개씩 있고, 각각 전체·미완료·완료 필터를 거는 버튼이다. 〔§DOM 계약〕

### 1-3. 범위 밖 (없어야 참인 문장)

- **M15** — 다음 기능의 UI·로직이 존재하지 않는다: 로그인/계정, 서버 API·DB 접근, 배포 설정, 제목 인라인 편집(더블클릭 수정), 드래그 정렬, 전체 완료 토글, 완료 일괄 삭제, 마감일·우선순위·태그·검색, 다크모드/테마 전환, 애니메이션, 한국어 외 로케일, SEO 메타태그. 〔§범위 밖〕

### 1-4. 완료 조건

- **M16** — `npm run test:ac`가 종료 코드 0으로 끝난다. 〔§완료 조건〕
- **M17** — `npm run build`가 종료 코드 0으로 끝난다(= `tsc -b` 타입체크 통과 + `vite build` 성공). 〔§완료 조건〕

## 2. 명시되지 않은 것

계약은 "동작의 세부는 이 문서에 적혀 있지 않다"고 스스로 밝힌다. 아래는 그 침묵을 메운 것이다.
근거로 정할 수 없는 것은 `[MISSING]`으로 남긴다.

### 2-1. 항목 추가 — 계약에 추가 트리거가 없다

testid 표에 **추가 버튼이 없다**. 인수 테스트는 표에 있는 testid로만 화면을 찾으므로, 테스트가 항목을 추가할 수 있는 경로는 `todo-input` 하나뿐이다. 여기서 아래가 따라온다.

- **U1** — `todo-input`에 포커스가 있는 상태에서 Enter 키를 누르면 항목 추가가 시도된다. 〔추론〕
- **U2** — 추가는 Enter 외의 경로(별도 버튼 클릭, blur, 타이핑 즉시 등)로는 일어나지 않는다. 〔추론〕
- **U3** — Enter 시점의 입력값에서 앞뒤 공백을 제거한 문자열이 비어 있지 않으면, 그 문자열을 제목으로 하는 항목이 1개 추가된다. 〔추론〕
- **U4** — 저장되는 제목은 앞뒤 공백을 제거한 문자열이다(입력 `"  우유  "` → `todo-title` 텍스트 `"우유"`). 〔추론〕
- **U5** — 입력값이 빈 문자열이거나 공백 문자로만 이루어져 있으면 항목은 추가되지 않고 `todo-item` 개수가 변하지 않는다. 〔추론〕
- **U6** — 항목이 추가되면 `todo-input`의 값은 빈 문자열이 된다. 〔추론〕
- **U7** — 항목이 추가되지 않았으면(U5) `todo-input`의 값은 Enter 직전 값 그대로 남는다. 〔추론 — 입력 내용을 임의로 버리지 않는 쪽을 택한다〕
- **U8** — 새 항목은 목록의 **맨 뒤**에 붙는다. 즉 `todo-item`의 DOM 순서는 추가된 순서와 같다. 〔추론〕
- **U9** — 새로 추가된 항목의 완료 상태는 미완료다(`todo-toggle`의 `checked`가 `false`). 〔추론〕
- **U10** — 제목이 같은 항목을 두 번 추가하면 `todo-item`이 2개가 되고, 한쪽을 삭제해도 다른 쪽은 남는다(중복 허용, 제목은 식별자가 아니다). 〔추론〕
- **U11** — IME 조합 중 발생한 Enter(`isComposing === true`)로는 항목이 추가되지 않는다. 〔추론 — 한국어 단일 로케일에서 조합 확정 Enter가 중복 추가를 일으키지 않게 한다〕

### 2-2. 토글·삭제 — "어느 항목"인지가 정해져 있지 않다

- **U12** — 어떤 `todo-item`의 `todo-toggle`을 클릭하면 그 항목의 완료 상태만 반전되고 다른 항목의 상태는 그대로다. 〔추론〕
- **U13** — `todo-toggle`의 `checked`는 항상 그 항목의 완료 상태와 일치한다(제어 컴포넌트). 〔추론〕
- **U14** — 어떤 `todo-item`의 `todo-delete`를 클릭하면 그 항목만 목록에서 사라지고, 나머지 항목의 상대 순서와 완료 상태는 보존된다. 〔추론〕
- **U15** — 토글·삭제의 대상은 화면에 보이는 목록에서의 인덱스가 아니라 항목마다 부여된 고유 id로 지정된다. 필터가 걸려 목록 일부만 보이는 상태에서 삭제·토글해도 의도한 항목에만 적용된다. 〔추론 — 인덱스로 지정하면 필터 상태에서 어긋난다〕
- **U16** — 각 항목은 생성 시 고유한 id를 받고, 그 id는 항목이 사는 동안 바뀌지 않는다. 리스트 렌더의 `key`는 제목이 아니라 이 id다. 〔추론 — U10 때문에 제목은 key가 될 수 없다〕

### 2-3. 필터 — 초기값·상호작용이 정해져 있지 않다

- **U17** — 최초 렌더 시 필터는 "전체"이고, 항목은 0개다. 〔추론〕
- **U18** — `filter-all` 클릭 후에는 모든 항목이 `todo-item`으로 렌더된다. 〔추론〕
- **U19** — `filter-active` 클릭 후에는 미완료 항목만 `todo-item`으로 렌더된다. 〔추론〕
- **U20** — `filter-completed` 클릭 후에는 완료 항목만 `todo-item`으로 렌더된다. 〔추론〕
- **U21** — 필터에서 제외된 항목은 DOM에 `todo-item`으로 존재하지 않는다(숨김 스타일이 아니라 렌더 제외). 〔추론 — 판정이 testid 개수로 이뤄지므로 숨김으로는 참이 되지 않는다〕
- **U22** — 필터 전환은 항목 데이터를 바꾸지 않는다. `filter-active` → `filter-completed` → `filter-all` 순으로 눌러도 전체 항목 수와 각 완료 상태는 그대로다. 〔추론〕
- **U23** — 필터가 걸린 상태에서 토글하면 그 항목은 필터 조건에 맞지 않게 된 즉시 목록에서 빠진다(예: `filter-active`에서 어떤 항목을 완료로 바꾸면 `todo-item` 개수가 1 줄어든다). 〔추론〕
- **U24** — 필터 버튼은 언제나 클릭 가능하다(선택된 필터의 버튼도 `disabled`가 아니다). 현재 선택된 필터는 `aria-pressed="true"`로 표시한다. 〔추론 — 선택 표시 방법은 계약에 없다. `disabled`는 재클릭을 막아 테스트를 깨뜨릴 수 있으므로 쓰지 않는다〕
- **U25** — 필터 상태에서 항목을 추가하면 항목은 항상 목록에 추가되고, 새 항목(미완료)은 현재 필터가 "완료"일 때는 화면에 보이지 않는다(필터를 바꾸지 않는다). 〔추론〕

### 2-4. `todo-count` — 표시 형식과 셈 범위가 정해져 있지 않다

- **U26** — `todo-count`가 세는 것은 **완료되지 않은 항목의 개수**이며, 현재 걸린 필터와 무관하다(전체 항목 기준). 〔추론 — 계약은 "미완료 개수"라고만 쓴다〕
- **U27** — 항목이 0개일 때도 `todo-count` 요소는 존재하고 `0`을 표시한다. 〔추론〕
- **U28** — 추가·토글·삭제로 미완료 개수가 바뀌면 `todo-count`의 표시가 즉시 그 값으로 갱신된다. 〔추론〕
- **U29** — `todo-count` 요소의 텍스트는 미완료 개수의 십진 표기 **한 개만** 담는다(예: `"2"`). 다른 숫자를 함께 넣지 않는다. 〔추론 — 아래 MISSING에 대한 잠정 결정〕

`[MISSING: todo-count의 표시 문자열 형식]` — 계약은 "미완료 개수 표시"만 말하고 문구·단위·복수 처리를 정하지 않는다. 인수 테스트가 완전 일치(`"2"`)를 보는지 부분 일치(`/2/`)를 보는지 알 수 없다. **숫자만** 담는 U29를 잠정 채택한다(부분 일치·완전 일치 양쪽을 동시에 만족하는 유일한 형식). `npm run test:ac` 출력이 다른 형식을 요구하면 그 출력을 근거로 U29를 고쳐 적는다.

### 2-5. 계약이 범위 밖이라 말하지 않았지만 짚어야 하는 것

- **U30 — 기각됨.** 원래 "항목 상태는 메모리에만 두고 `localStorage`를 쓰지 않는다"로 정했다(추론). `npm run test:ac`의 AC-07 출력이 이 문장을 반증했다 — 언마운트 후 다시 렌더했을 때 제목 `["A","B"]`와 완료 상태가 남아 있어야 한다. 아래 2-6으로 대체한다.
- **U31** — 앱은 네트워크 요청(`fetch`·`XMLHttpRequest`·WebSocket)을 하지 않는다. 〔추론 — §범위 밖 "서버 API·DB"의 귀결〕
- **U32** — 화면 문구는 한국어 하나로 고정하고 로케일 전환 수단을 두지 않는다. 〔§범위 밖 "다국어(한국어 단일 로케일)"의 귀결 + 추론〕
- **U33** — `todo-title`은 클릭해도 아무 일도 일어나지 않는 표시 전용 요소다(`label`로 체크박스에 연결하지 않는다). 〔추론 — 인라인 편집이 범위 밖이고, 제목 클릭에 토글을 붙이면 계약에 없는 동작이 생긴다〕
- **U34** — `todo-delete`와 필터 버튼은 `type="button"`이어서 어떤 폼도 제출하지 않는다. 〔추론 — jsdom에서 폼 제출은 미구현 경고를 낸다〕
- **U35** — 항목 0개일 때 `todo-input`·`todo-count`·세 필터 버튼은 그대로 렌더된다(빈 목록이어도 사라지지 않는다). 〔추론〕
- **U36** — 컴포넌트는 `StrictMode`의 이중 렌더에서 동작이 달라지지 않는다(렌더 중 부수효과 없음, id 생성이 렌더 본문에서 일어나지 않음). 〔추론 — `src/main.tsx`가 `StrictMode`로 감싼다〕
- **U37** — `src/App.tsx` 아래에 새로 만드는 파일 외에 기존 파일(`main.tsx`, `index.html`, 설정 파일)을 수정하지 않는다. 〔추론 — 계약은 구현 범위를 "`src/App.tsx`와 그 아래 네가 만드는 파일"로 한정한다〕

### 2-6. 영속성 — 계약은 침묵했고 인수 테스트가 답했다

근거 위치가 계약이 아니라 `npm run test:ac`의 출력인 문장들이다(계약 §DOM 계약 아래 "무엇이 옳은 동작인지는 인수 테스트가 정한다").

- **P1** — 항목을 추가·토글한 뒤 컴포넌트를 언마운트하고 다시 마운트하면, 이전 항목이 같은 순서·같은 제목·같은 완료 상태로 복원된다. 〔test:ac 출력 AC-07: `cleanup(); render(<App />)` 뒤 `titles()`가 `["A","B"]`, `toggleOf(0).checked === true`, `toggleOf(1).checked === false`〕
- **P2** — 복원된 뒤 새로 추가한 항목의 id는 복원된 어떤 항목의 id와도 겹치지 않는다(겹치면 토글·삭제가 두 항목에 동시에 걸린다). 〔추론〕
- **P3** — 저장된 값이 없거나, JSON으로 파싱되지 않거나, 배열이 아니거나, 원소가 `{id:number, title:string, done:boolean}` 모양이 아니면, 그 값을 버리고 빈 목록(또는 성한 원소만)으로 시작하며 예외를 던지지 않는다. 〔추론〕
- **P4** — 선택된 필터는 저장하지 않는다. 다시 마운트하면 필터는 항상 "전체"다(U17은 그대로 유효). 〔추론 — AC-07은 목록만 요구한다〕
- **P5** — 목록이 바뀌면 저장된 값이 즉시 그 목록으로 갱신된다. 저장소 접근이 예외를 던져도 화면 동작은 그대로다. 〔추론〕
- **P6** — 저장소에 쓰는 것은 항목 목록 하나뿐이고, 서버·네트워크로는 아무것도 나가지 않는다(U31은 그대로 유효). 〔§범위 밖 + 추론〕

## 3. 완료 전 대조

구현 완료를 선언하기 전에 1·2의 문장마다 그것을 참으로 만드는 코드 위치를 지목한다.
지목하지 못한 문장은 구현하거나 여기에 기각 사유를 적는다.

구현 파일은 `src/App.tsx`(수정)와 `src/todos.ts`(신규) 둘뿐이다.

| 문장 | 코드 위치 |
|---|---|
| M1 진입점 | `src/App.tsx:21` (`export default function App`) |
