# SPEC — Todo 앱

구현 전 요구사항 확정 문서. 산출물이 아니라 작업 문서다.
근거 위치는 `계약 §<절>`로 표기한다. 계약 = 과제로 주어진 「Todo 앱 — 구현 계약 (얇은 판)」.
`[CHANGE]`는 과제의 «변경 요구»(인라인 제목 편집)를 가리키며, 계약의 «범위 밖» 목록보다 우선한다.

## 1. 명시된 것

계약에서 직접 읽어낼 수 있는 요구.

### 1.1 스택·진입점

- S-01. 앱은 Vite + React + TypeScript로 구현되며, 다른 프레임워크를 도입하지 않는다. — 계약 §고정된 것
- S-02. `src/App.tsx`는 컴포넌트를 default export 한다. — 계약 §고정된 것
- S-03. `src/App.tsx` 아래의 파일 분할·상태 관리 방식은 임의로 정해도 계약 위반이 아니다. — 계약 §고정된 것
- S-04. `tests/ac/**`의 파일은 읽기·수정·삭제·이동되지 않는다 (실행만 한다). — 계약 §고정된 것
- S-05. `package.json`의 `build`·`test:ac` 스크립트 문자열이 변경되지 않는다. — 계약 §고정된 것
- S-06. `tsconfig.app.json`의 `"strict": true`가 유지된다. — 계약 §고정된 것
- S-07. `src/App.css`와 `src/index.css`의 내용이 변경되지 않고, 새 스타일 파일이 추가되지 않는다. — 계약 §범위 밖
- S-08. `npm run test:ac`가 종료 코드 0으로 끝난다. — 과제 §완료 조건
- S-09. `npm run build`(= `tsc -b && vite build`)가 종료 코드 0으로 끝난다. — 과제 §완료 조건

### 1.2 DOM 계약

렌더된 화면에서 다음 `data-testid`를 가진 요소를 찾을 수 있다. — 계약 §DOM 계약

- S-10. `todo-input`: 새 항목 입력창.
- S-11. `todo-item`: 항목 하나. 개수는 0..n.
- S-12. `todo-title`: 항목 제목 텍스트.
- S-13. `todo-toggle`: 완료 체크박스.
- S-14. `todo-delete`: 항목 삭제 버튼.
- S-15. `todo-count`: 미완료 개수 표시.
- S-16. `filter-all` / `filter-active` / `filter-completed`: 각각 전체·미완료·완료 필터 버튼.
- S-17. 위 속성을 제외한 마크업 구조·클래스명·태그는 임의로 정해도 계약 위반이 아니다.

### 1.3 인라인 제목 편집 (변경 요구)

- S-19. `todo-title`을 더블클릭하면 그 항목의 제목을 고칠 수 있는 상태가 된다. — 과제 §[CHANGE]
- S-20. 편집 입력창은 `data-testid="todo-edit"`를 갖는다. — 과제 §[CHANGE]
- S-21. 편집 중 Enter 키를 누르면 편집 내용이 확정된다. — 과제 §[CHANGE]
- S-22. 편집 중 Escape 키를 누르면 편집이 취소된다. — 과제 §[CHANGE]
- S-23. 편집은 그 항목이 있던 자리에서 이루어진다. 별도 화면·모달·별도 영역으로 옮기지 않는다.
  — 과제 §[CHANGE]("그 자리에서")
- S-24. [CHANGE]가 건드리지 않은 요구는 전부 그대로다. 즉 S-01~S-17과 아래 U-01~U-40이 계속 참이다.
  — 과제 §[CHANGE]("다른 요구사항은 그대로다")

### 1.4 범위 밖 (구현하지 않는다)

- S-18. 다음 기능은 코드에 존재하지 않는다: 로그인·계정, 서버 API·DB, 배포 설정,
  드래그 정렬, 전체 완료 토글, 완료 일괄 삭제,
  마감일·우선순위·태그·검색, 다크모드·테마 전환, 애니메이션, 다국어(한국어 단일 로케일), SEO 메타태그.
  — 계약 §범위 밖
  → 원래 이 목록에 있던 "인라인 제목 편집(더블클릭 수정)"은 [CHANGE]가 우선하므로 제외했다.
  나머지 항목은 [CHANGE]가 건드리지 않았으므로 계속 범위 밖이다.

### 2.8 인라인 제목 편집 — 계약이 침묵하는 지점

[CHANGE]가 정한 것은 네 가지뿐이다: 진입 수단(제목 더블클릭), 입력창의 testid(`todo-edit`),
확정 키(Enter), 취소 키(Escape). **그 외는 전부 아래에서 정한다.**
현재 인수 테스트 8개(AC-01~AC-08)는 편집을 전혀 건드리지 않으므로,
이 절의 문장들은 인수 테스트 출력으로 좁힐 수 없다. 근거를 계약 본문과 U-01~U-40의 일관성에서 끌어온다.

**편집 상태의 범위**

- E-01. 어느 시점에도 편집 중인 항목은 최대 1개다. 따라서 DOM의 `todo-edit`은 0개 또는 1개다. `[추론]`
  — 근거: 테스트가 `getByTestId("todo-edit")`(단수)로 조회하면 2개 이상일 때 예외가 난다.
- E-02. 편집을 시작하기 전에는 `todo-edit`이 DOM에 없다. 최초 렌더 직후에도 없다. `[추론]`
- E-03. 편집을 시작하면 그 항목의 `todo-title`은 DOM에서 제거되고 같은 `todo-item` 안 같은 자리에
  `todo-edit`이 렌더된다. 편집 중이 아닌 다른 항목의 `todo-title`은 그대로 남는다. `[추론]`
  — 근거: [CHANGE]의 "그 자리에서". 제목과 입력창을 동시에 남기면 같은 제목이 두 번 보이고,
  "제목이 입력창으로 바뀌었는지"를 판정하려는 테스트(`queryByTestId("todo-title")`가 null)를 통과하지 못한다.
- E-14. 편집 중에도 그 항목의 `todo-toggle`·`todo-delete`는 계속 렌더되고, `todo-item` 개수도 변하지 않는다. `[추론]`
  — 근거: 편집은 제목 표시만 바꾼다. 항목 자체를 목록에서 빼면 U-33의 인덱스 정합이 깨진다.

**진입**

- E-15. `todo-title`을 한 번 클릭하는 것으로는 편집 상태가 되지 않는다. 더블클릭만이 진입 수단이다. `[추론]`
- E-16. 완료된 항목의 제목도 더블클릭으로 편집할 수 있다. `[추론]`
  — 근거: [CHANGE]에 완료 항목을 제외한다는 말이 없다.
- E-17. 편집 중에 다른 항목의 `todo-title`을 더블클릭하면 편집 대상이 그 항목으로 옮겨간다 (E-01 유지). `[추론]`

**편집 입력창의 초기 상태**
