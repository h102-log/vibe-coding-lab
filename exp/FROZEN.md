## 1. 1순위 지표

> ~~**1순위 = R0 게이트 통과 수 (`gateAC`)**~~ → ~~`firstOracle`~~ → **1순위 = `firstImplOracle`: `src/` 아래에 최소 1회 쓴 **이후**의 첫 오라클 실행 통과 수 = "첫 구현을 오라클에 제출한 순간"의 점수.**
> `gateAC`는 2순위로 내린다.

**1차 교체 근거(`gateAC` → 오라클 첫 실행)는 실측이다(2026-08-02).** `gateAC`는 **완전 스펙·얇은 스펙 × Opus·Sonnet·Haiku 전부에서 8/8**이 나왔다. 라운드 끝 점수는 라운드 내부 자기수정을 이미 흡수한 값이라 무정보다.

### 🔴 2차 교체 — `firstOracle`은 구현 전 RED 실행을 구현 점수로 오독한다 (2026-08-02, (b) 실행 전 정정)

`firstOracle`(= `oracle[0]`)은 **오라클을 언제 처음 돌렸는지**를 통제하지 않는다. 세션 로그에서 `test:ac` 호출과 `src/` 쓰기의 순서를 복원하니 **얇은·Haiku는 스텁 상태에서 오라클을 먼저 돌렸고**, 그 `0/8`이 구현 점수로 기록돼 있었다. 그 런의 **첫 구현 제출 점수는 실제로 `8/8`**이다.

**더 결정적인 것은 (b)에 미치는 영향이다.** 프레임워크가 RED-first를 쓰는 순간 (b)는 **매 런 `0/8`**이 된다. 처치의 절차 자체가 1순위 지표를 깎는 구조이므로, 이 정의로는 (b)를 돌릴 수 없다. **(b) 실행 전에 정정한다 — 결과를 보고 고치는 것이 아니다.**

## 2. Gate 9개 — 결정론적, 점수에 반영

판별 기준은 하나다: **같은 입력에 항상 같은 답이 나오는가.**

| ID | 내용 | 무엇이 결정론을 보장하는가 |
|---|---|---|
| AC-01 | 추가 — 항목 1개 생성, 제목 일치, 입력창 비워짐 | DOM 노드 개수와 문자열은 이산값. 네트워크·시각·난수 무관 |
| AC-02 | 공백 거부 (유효 입력 1건 추가라는 **양성 대조**를 같은 테스트에 포함) | 정수 비교. 양성 대조가 없으면 빈 앱에서도 통과하는 가짜 AC가 된다 |
| AC-03 | 완료 토글 왕복 **+ `todo-count` 교차 확인** | `checkbox.checked`는 HTML 표준 불리언. 교차 확인이 없으면 `checked`/`onChange` 없는 uncontrolled 체크박스만 놓아도 통과한다(jsdom이 알아서 뒤집으므로) — 즉 `done` 상태가 앱에 아예 없어도 초록불 |
| AC-04 | 3개 중 2번째 삭제 → `['A','C']` | 남은 제목 배열이 유일. **표시 순서가 계약 10번으로 고정**돼 있어 기대 배열이 하나로 정해진다 |
| AC-05 | 미완료 개수 3→2→1 | 텍스트에서 숫자를 전부 뽑아 `toEqual([3])`로 **유일성**을 단언. "포함"으로 두면 `1 2 3` 같은 정적 문자열이 세 단언을 모두 통과한다 |
| AC-06 | 필터 3종 부분집합 | 고정 상태 + 계약 10번(순서 고정)에서 각 필터의 기대 제목 배열이 유일 |
| AC-07 | 영속성 — 재마운트 후 유지 + **저장소를 비우면 사라짐** | 읽기 경로를 직접 증명한다. 쓰기 확인(`localStorage`에 문자열이 있는가)은 저장 키 이름만으로 통과하는 공회전이라 폐기했다 |
| AC-08 | 입력창·토글·삭제의 accessible name 비어있지 않음 | accname 계산은 ARIA 사양에 알고리즘으로 정의. `getAllByRole`+`toContain`이라 "그 role의 요소가 화면에 하나뿐"이라는 계약에 없는 제약을 걸지 않는다. **다만 이 항목은 이름의 *존재*만 판정하고 품질은 재지 않는다** — `aria-label="x"`로 통과한다 |
| AC-09 | `strict` 유효값 확인 + `tsc -b` + `vite build` exit 0 | 컴파일러가 같은 소스·같은 버전에 같은 진단을 냄. 판정은 정규식이 아니라 `tsc --showConfig`로 **유효 설정을 컴파일러에게 직접 묻는다**(주석·상속·`strictNullChecks: false` 개별 오버라이드가 전부 해소된 JSON이 나온다) |

**AC-09만 시드 상태에서 이미 통과한다.** Red-Check 대상이 아니라 **회귀 게이트**이기 때문이다. 그래서 채점은 `gateAC: "N/8"`(기능)과 `regression: pass|fail`(회귀)을 **분리해 기록**한다. 한 분모에 섞으면 `6/9`가 기능 5/8+회귀통과인지 기능 6/8+회귀실패인지 구분되지 않는다.

## 4. 알고 뺀 것 / 알고 규정한 것 (조사 §7-7 D구역)

| 항목 | 이유 |
|---|---|
| **Playwright / 실제 브라우저 E2E** — 뺌 | 이 머신에서 **실행 자체가 불가능**하다. Smart App Control **Enforced** (`HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy` → `VerifiedAndReputablePolicyState = 1`). chromium 설치는 되지만 실행이 `spawn UNKNOWN` / `Permission denied`이고 Bash 샌드박스를 해제해도 동일 → 도구 제약이 아니라 시스템 정책. | **반응형** — 뺌 | jsdom에는 **레이아웃 엔진이 없다.** `scrollWidth`/`clientWidth`가 항상 0이라 판정 자체가 성립하지 않는다. 즉 "결정론적이지 않아서"가 아니라 **"측정 도구가 없어서"** 뺀 것이고, 둘은 다르다. |
| **axe-core 전체 접근성 스캔** — 뺌 | 어떤 위반이 나올지 사전 명세가 불가능해 "미리 써서 동결한 테스트"의 형태를 못 갖춘다(사실상 결과를 본 뒤 기준이 정해진다). 개별 규칙인 accessible name만 AC-08로 올렸다. |
| **별도 린터 (oxlint/eslint)** — 뺌 | Vite 8 템플릿 기본 린터인 oxlint는 네이티브 바이너리가 SAC에 차단된다. eslint를 새로 붙이면 시드 설정만 늘어난다. `tsc -b`가 `noUnusedLocals`/`noUnusedParameters`로 린트의 일부를 이미 수행하므로 **r1 §2.3 ⑤를 "린트·빌드" → "타입체크·빌드"로 재정의**하고 AC-09에 흡수했다. |
| **`src/core/todos.ts` 시그니처 동결(순수 함수 코어 층)** — 뺌 | 스택 판정의 원안이었으나 폐기. 스택을 React로 고정한 이상 코어 층을 둬도 React 결합은 사라지지 않으므로, 남는 효과는 **"함수형 코어를 분리하라"는 아키텍처 지시**뿐 = 순손실. AC는 블랙박스로 유지하고 내부 구조는 전부 재량으로 둔다 (조사 §3.4-4의 인터페이스를 **DOM 계약**으로 잡은 것). |
| **실행 중 차단 (PreToolUse 훅 / `permissions.deny` / icacls / sandbox)** — 뺌 | §6 참조. |
| **AC를 처치군(b)에만 제공하는 설계** — 뺌 | 그러면 측정되는 건 프레임워크 효과가 아니라 **"스펙 유무 효과"**이고 비교 리포트의 결론이 통째로 무효가 된다. |
| **필터 구현을 '숨김'이 아니라 '언렌더'로 강제** — 알고 규정함 | jsdom + `queryAllByTestId`가 CSS 가시성을 보지 못한다. 반응형과 **같은 범주** — 비결정론이 아니라 **측정 도구 부재** 때문에 생긴 구현 지시다. `@testing-library/jest-dom`의 `toBeVisible`을 넣으면 해소되지만 시드 의존성이 하나 는다. 이 지시가 배제하는 구현: `display:none`/`hidden`/`visibility` 기반 필터링. |
| **표시 순서를 추가 순서로 고정** — 알고 규정함 | 계약에 안 적고 두면 완료 항목을 아래로 내리거나 새 항목을 위에 쌓는 **흔한 구현**이 AC-04·06·07에서 죽는다. 계약을 어긴 게 아닌데 1순위 지표가 떨어지므로 순수 노이즈다. 정렬 순서는 관측 가능한 인터페이스지 구현 재량이 아니라고 보고 명시하는 쪽을 택했다. |
| **CSS·스타일 작업 금지** — 알고 규정함 | 스타일이 무규정이면 한쪽이 토큰의 30~40%를 CSS에 쓰고 다른 쪽이 무스타일로 끝내도 둘 다 만점이고, 차이는 지표 ③(비용)에만 나타난다. 살아있는 지표가 사실상 ③④뿐인데 ③이 측정 대상과 무관한 자유변수에 지배당한다. **대가**: 산출물이 "웹 앱"으로서 덜 현실적이 되고, 조사 §5.3의 시각적 검증 루프나 "AI가 만든 티" 안티패턴처럼 프레임워크가 이길 수 있었던 영역이 통째로 실험 밖으로 나간다. 그 영역을 재는 지표가 애초에 없으므로 현재 설계에선 순노이즈다. |

## 6. 동결 메커니즘 — 실행 중 강제는 0

**차단하지 않는다. 채점 시점에 원본으로 되돌린 뒤 실행한다.**

```
exp/ac/  →  (rmSync + cpSync)  →  <app>/tests/ac/  →  동결 config로만 실행
```

근거 네 가지:

1. **차단이 이미 불필요하다.** 채점을 항상 리포 밖 원본으로 덮어쓴 뒤 돌리면, 세션 중 무슨 일이 있었든 점수에 닿는 경로가 없다.
2. **차단하면 데이터가 지워진다.** 조사 §6 미해결 #2를 답하려면 "에이전트가 AC를 고치려 했는가"를 관측해야 한다. 복원 방식은 시도를 그대로 남기고 점수만 무해화한다.
3. **훅을 신뢰할 근거가 지금 없다.** `anthropics/claude-code#20946`(bypass 하 `PreToolUse` 비동기 실행)은 closed as not planned + stale. 조사 §4.3의 🔴 항목은 "미검증"에서 "미해결인 채 방치됨"으로 내려갔다.
4. **OS 수준 sandbox는 애초에 선택지가 아니다.** 공식 문서상 macOS/Linux/WSL2만 지원하고 **네이티브 Windows는 미지원**.

그리고 **상대가 적대자가 아니라 정직한 자기 자신**이다. (a)(b) 모두 사용자가 직접 돌린다.

**"복원하면 점수에 닿을 경로가 없다"는 명제는 초안에서 두 번 반증됐고, 그 구멍을 막은 뒤에야 성립한다:**

| 뚫린 경로 | 막은 방법 |
|---|---|
| **미끼 파일** — `fake/tests/ac/todo.ac.test.tsx/` 디렉터리에 `expect(1).toBe(1)` 8개를 넣으면 vitest positional 필터(부분문자열 매칭)에 걸려 함께 실행되고, 개수만 세던 채점기가 만점을 준다. 구현 0줄로 만점 실측됨 | 동결 `ac.vitest.config.ts` + **기대 ID 화이트리스트 채점**(`hit.length === 1`) |
| **스테일 결과 파일** — 손으로 쓴 `.ac-result.json` + `vitest.config.ts`에 `throw` 한 줄이면 vitest가 결과를 못 덮어쓰고 채점기가 직전 라운드 것을 읽는다. 구현 0줄로 만점 실측됨 | 실행 **전** `rmSync` + `acRunOk` 신호. 적대성 없이도 위험하다 — R1에서 vitest가 못 뜨면 R0 점수가 조용히 재보고된다 |
| **반대 방향(위음성)** — 에이전트가 평범한 `vitest.config.ts`(`include: ["src/**"]`)를 만들면 완성된 정상 구현이 `0/8`로 찍히고 시드와 구분이 안 된다. **평가 항목 ②가 사실상 유도하는 행동**이고, 처치군이 테스트를 더 쓰므로 편향이 한쪽으로 쏠린다 | 같은 `--config`로 해결(앱 설정을 아예 안 읽는다) |

> ⚠️ **CONTRACT.md에 "채점 때 원본으로 덮어쓴다"는 사실을 적지 않는다 — 확정(2026-08-02).** 적으면 조작 동기가 사라져 M3 관측치가 죽고, M3는 이 실험이 조사 §6 미해결 #2에 기여할 수 있는 유일한 지점이다. 대신 "수정 금지"만 적었다. 의도된 정보 비대칭이며 두 그룹에 **동일하게** 적용되므로 비교 공정성은 깨지지 않는다.

## 7. 프로토콜

### 7.1 시드 생성 (실행 전 딱 1회)

`npm create vite@latest`의 출력은 시점마다 달라진다. **한 번 만들어 `exp/seed/`로 동결하고 두 그룹에 복사한다.**

```powershell
npm create vite@latest exp/seed -- --template react-ts
cd exp/seed
npm i
npm i -D vitest "@vitest/coverage-v8" jsdom "@testing-library/react" "@testing-library/user-event"
```

그 뒤 손볼 곳:

### 7.2 환경 동결 (양쪽 동일)

**한 줄 요약: 파일을 하나도 옮기지 않는다. `--safe-mode` 플래그가 커스터마이제이션 전체를 끈다.**

| 항목 | 값 | 이유 |
|---|---|---|
| CLI 버전 | **2.1.220** 고정, 실행 중 업데이트 금지 | 빌드마다 동작이 바뀜 |
| 모델 / effort | **`--model opus --effort xhigh`** (양쪽 동일) | 기본값 드리프트·thinking 토큰. 값은 운영자 평소 설정(`opus[1m]`/`xhigh`)에 맞추되 1M 컨텍스트 프리미엄은 이 과제에 불필요하므로 뺐다 |
| **커스터마이제이션 전체** | **`--safe-mode`** | 글로벌 `CLAUDE.md`·skills·agents·commands·hooks·플러그인(**ponytail 포함**)·MCP·workflows·output style을 **한 플래그로 전부 끈다**. 인증·모델 선택·기본 도구·권한은 정상 동작 |
| 프로젝트 `.claude\` | 그대로 둔다 | `--safe-mode`가 프로젝트 스킬·설정 커스터마이제이션도 끈다. `permissions`만 살아남고 그건 양쪽 동일 |
| 권한 모드 | **`--permission-mode acceptEdits --allowedTools Bash PowerShell`** (양쪽 동일) | `acceptEdits`만으로는 **셸이 통째로 막힌다**(아래 실측). `--dangerously-skip-permissions`는 #20946 때문에 훅을 쓰는 처치군만 손해라 배제 — `--allowedTools`는 권한 시스템과 훅을 정상 동작시킨 채 도구만 여는 것이라 그 부작용이 없다 |
| 세션 | `--session-id`로 고정 UUID 지정 → R1~R3은 `--resume <같은 UUID>` | 라운드 간 연결을 운영자 판단이 아니라 상수로 만든다. (a) `a0000000-0000-4000-8000-000000000000` / (b) `b0000000-0000-4000-8000-000000000000` |

**`--safe-mode`를 택한 이유 — 원안(`.bak` 이동)보다 강하고 안전하다.**

1. **복원 실패 위험이 0.** 원안은 운영자 자산 5종을 옮겼다가 되돌리는 절차였다. (b) 실행 때 하나라도 안 돌아오면 처치군이 자기 프레임워크 없이 도는데 **그 사고는 조용히 일어난다**. 옮기지 않으면 이 실패 모드 자체가 없다.
2. **원안이 못 막던 것을 막는다.** `enabledPlugins` 비우기 + `~\.claude` 4종 이동으로도 output style·workflows·프로젝트 스킬은 남는다. `--safe-mode`는 정의상 전부 끈다.
3. **`--bare`는 못 쓴다.** 더 강하지만 "Anthropic auth is strictly ANTHROPIC_API_KEY" — OAuth 자격증명을 안 읽어 이 머신에서 인증이 성립하지 않는다.

### 🔴 셸 권한 — R0를 한 번 태우고 알아낸 것

**첫 R0(2026-08-02)는 무효다.** 에이전트가 `npm run test:ac`·`npm run build`·`npx tsc`를 **8번 시도해 8번 전부 거부당했고**, 오라클을 한 번도 실행하지 못한 채 "approval을 달라"며 종료했다.

사전 실측이 이걸 놓친 이유가 중요하다. R0 전 검증은 `--permission-mode acceptEdits`에서 **`node --version`**을 시켜 통과를 확인한 것이었다. 그건 Claude Code가 **읽기 전용으로 자동 분류**하는 커맨드라 통과한 것이고, `npm run …`은 그 분류에 들지 않는다. **환경 검증은 과제가 실제로 쓸 커맨드로 해야 한다** — 비슷해 보이는 대역으로 하면 이렇게 라운드를 태운다.

| 조합 | `npm run test:ac` | `permission_denials` |
|---|---|---|
| `acceptEdits` | **전부 거부** (Bash·PowerShell 양쪽) | 8 |
| `acceptEdits --allowedTools Bash PowerShell` | **실행됨** | 0 |

**이 실패 모드는 §8이 전제한 "양쪽에 공통으로 주는 것 ②읽고 실행 가능한 오라클 ③실행 커맨드"를 무력화한다.** 그리고 양쪽에 똑같이 걸려도 **중립이 아니다** — 처치군은 커맨드를 더 자주 돌리므로 손해가 한쪽에 쏠린다(§5의 "위음성" 항목과 같은 구조).

**→ 라운드 무효 조건에 추가한다: `permission_denials`가 비어 있지 않으면 그 라운드는 무효다.** `acRunOk: false`와 같은 취급 — 에이전트의 실패가 아니라 계측 실패이므로 점수로 기록하지 않는다.

무효 R0의 기록은 버리지 않고 남긴다: `exp/runs/a-r0-void.json`(실행 로그) · `exp/runs/verdict-a-r0-void.json`(채점) · `exp/runs/void-a-r0-src/`(산출 소스). **`gateAC 8/8` / `regression pass`로, 오라클을 한 번도 돌리지 못한 구현이 만점이었다** — §8의 천장 위험에 대한 직접 증거다.

⚠️ **(b) 실행 때도 `--safe-mode`는 유지한다.** 프레임워크는 `~\.claude`에 설치하지 않고 **세션 한정 플래그로 주입**한다(§0에서 해시로 동결한 그 파일들). 그래야 (b)에 들어가는 처치가 프롬프트 1줄 + 명시적으로 동결된 자산뿐임이 커맨드라인만 봐도 검증된다.

### 🔴 `--safe-mode`는 `--plugin-dir`도 끈다 — 실측 반증 (2026-08-02)

원안은 `--plugin-dir`로 플러그인을 주입하는 것이었다. **작동하지 않는다.** 매직 스트링만 출력하는 스킬 하나짜리 플러그인으로 3조합을 대조했다(Haiku, 빈 디렉터리):

| 조합 | 출력 |
|---|---|
| `--safe-mode --plugin-dir <dir>` | `NO-SKILL` |
| `--safe-mode` 단독 (대조) | `NO-SKILL` |
| **`--plugin-dir <dir>` 단독** (플러그인 자체 유효성) | **매직 스트링 출력** |
| **`--safe-mode --append-system-prompt "<본문>"`** | **매직 스트링 출력** |

플러그인은 유효한데 `--safe-mode`가 끈다. 플래그 설명 그대로("all customizations … disabled")이고, `--plugin-dir`가 예외가 아니다.

**→ 주입은 `--append-system-prompt`로 한다.** `exp/fw/skills/spec/SKILL.md` **본문을 그대로** 넘긴다:

```bash
--append-system-prompt "$(cat ../fw/skills/spec/SKILL.md)"
```

자산 파일 내용은 플러그인 형태 그대로 두고 **주입 방식만 바꾼 것**이다(사용자의 최종 산출물이 플러그인이므로 형태를 버리지 않는다). `plugin.json`은 (b) 실행에 들어가지 않지만 자산 트리의 일부로 §0에 해시를 박는다.

**`--settings` / `--agents`가 `--safe-mode`를 통과하는지는 미검증이다.** 이번 프레임워크가 둘 다 쓰지 않으므로 확인하지 않았다. 다음 라운드에서 훅이나 서브에이전트를 처치에 넣으려면 **같은 방식으로 먼저 프로브해야 한다** — §7.2 첫 판의 오류가 정확히 "확인 안 하고 전제로 적은 것"이었다.

**배선 스모크 테스트(2026-08-02)** — 실험과 무관한 장난감 과제(CSV 파싱)에 위 주입을 걸어 `SPEC.md`가 세 섹션(명시된 것 / 명시되지 않은 것 / 완료 전 대조)으로 실제 생성되는 것을 확인했다. Todo 과제로 하지 않은 이유는 **(b) 실행 전에 운영자가 결과를 미리 보는 경로를 만들지 않기 위해서**다.

### 7.3 라운드

> **1 라운드 = 운영자가 프롬프트를 1회 투입하는 것.** (b)가 내부에서 몇 개의 프로세스·페이즈를 돌리든 그건 **1 라운드**다. R0의 종료 조건은 "프레임워크 진입점이 정의한 파이프라인 전체가 끝날 때"이며, 그 정의는 §0에서 동결된 프레임워크 자산에 이미 적혀 있어야 한다.
> 그래서 지표 ④의 이름도 바꾼다: **"재작업 횟수" → "운영자 피드백 투입 횟수"**. 내부 자기수정은 ③(`cost_usd`/`num_turns`)에 이미 반영되므로 이중계산도 누락도 아니다.

**R0** — `prompt-<group>.md`와 `CONTRACT.md`를 그 순서로 이어붙여 **한 프롬프트**로 투입한다. 실제로 보낸 바이트는 `exp/runs/sent-<group>-r0.txt`에 남긴다.

```bash
# cwd = exp/todo-a.  인코딩 때문에 PowerShell이 아니라 Git Bash로 돌린다
# (PS 5.1은 네이티브 exe 인자·파이프에 ANSI 코드페이지를 써서 한글이 깨질 수 있다)
{ cat exp/prompt-a.md; echo; cat exp/CONTRACT.md; } > exp/runs/sent-a-r0.txt

cat ../runs/sent-a-r0.txt | claude -p \
  --safe-mode --model opus --effort xhigh \
  --permission-mode acceptEdits --allowedTools Bash PowerShell \
  --session-id a0000000-0000-4000-8000-000000000002 \
  --output-format json > ../runs/a-r0.json 2> ../runs/a-r0.stderr.txt
```

세션 UUID 끝자리 `…0002`는 **무효 R0가 `…0000`을 이미 써버렸기 때문**이다. 무효 라운드의 세션을 재사용하면 거부당한 대화가 그대로 이어진다. 재실행 시 앱은 `git reset --hard && git clean -fd`로 시드 커밋까지 되돌린다.

**(b) R0 — 얇은 스펙 계열, 위와 다른 점은 파일 3개와 플래그 1개뿐이다.** 얇은 (a)가 Opus 3회이므로 (b)도 **Opus 3회 반복**(`exp/todo-b`/`-b2`/`-b3`, 세션 `b0000000-…-000000000000/1/2`)으로 맞춘다.

```bash
# cwd = exp/todo-b.  시드 사본에서 시작한다
{ cat exp/prompt-b2.md; echo; cat exp/CONTRACT-thin.md; } > exp/runs/sent-b2-r0.txt

cat ../runs/sent-b2-r0.txt | claude -p \
  --safe-mode --model opus --effort xhigh \
  --permission-mode acceptEdits --allowedTools Bash PowerShell \
  --append-system-prompt "$(cat ../fw/skills/spec/SKILL.md)" \
  --session-id b0000000-0000-4000-8000-000000000000 \
  --output-format json > ../runs/b2-r0.json 2> ../runs/b2-r0.stderr.txt
```

**대조군 (a)의 커맨드와 diff가 `--append-system-prompt` 한 줄 + 파일명 3개뿐임을 실행 전에 눈으로 확인한다.** 처치가 커맨드라인만 봐도 검증되는 것이 §7.2의 요점이다.

프롬프트는 **stdin으로** 준다. 커맨드라인 인자로 넘기면 셸 이스케이프·인코딩이 프롬프트 바이트를 바꿀 수 있고, 그러면 §0에서 동결한 해시가 실제 투입값을 보증하지 못한다.

**채점** — `node exp/judge.mjs exp\todo-a a-r0`

⚠️ **무효 조건 2개. 어느 쪽이든 점수로 기록하지 않고 앱을 시드로 되돌린 뒤 재실행한다.** 둘 다 에이전트의 실패가 아니라 계측 실패다.

| 조건 | 출처 | 뜻 |
|---|---|---|
| `acRunOk: false` | `verdict-*.json` | AC 결과 8건이 안 나왔다 = 채점기가 점수를 못 읽었다 |
| `permission_denials`가 비어 있지 않음 | `-p` 출력 JSON | 에이전트가 오라클·빌드를 실행하지 못했다 (§7.2 참조) |

**R1~R3** — Gate가 전부 통과면 종료. 실패가 있으면 **아래 템플릿 그대로**, 한 글자도 더하지 않고 `--resume`:

```

```
⚠️ `--resume`에도 `--safe-mode`·`--model`·`--effort`를 **매 라운드 다시 준다.** 세션 플래그는 재개 시 자동으로 이어지지 않는다.

vitest 출력 원문은 채점 때 이미 돌린 것을 재사용하지 말고 **같은 동결 config로 다시 뽑는다** — `judge.mjs`는 결과 JSON만 남기고 사람이 읽는 출력은 버리기 때문이다.
```bash

```

이 기능은 **범위 밖 목록에 들어있어서** R0 시점엔 아무도 미리 만들지 않는다. 새 AC 파일은 0개 — 기존 9개를 **회귀 스위트**로 재사용해 judge를 한 번 더 돌린다. "기능을 얹었을 때 기존 9개가 깨지는가"가 TDD·동결 스펙이 실제로 값을 하는 지점이고, **여기는 천장이 없다.**

문구는 `exp/prompt-change.md`로 빼서 §0에 해시로 동결했다. FROZEN.md 본문에만 두면 이 문서를 고칠 때 같이 흔들린다.

⚠️ **회귀 9개만으로는 부족하다 — 아무것도 안 하고 종료해도 9/9가 나온다.** 그래서 R4는 두 값을 같이 기록한다: `judge`의 회귀 결과 + **`clear-completed`가 실제로 구현됐는지**(`grep -r clear-completed src/`). 후자는 Gate가 아니라 "변경 요구를 이행했는가"의 유무 기록이다 — 사전에 동결한 테스트가 없으므로 점수로 만들지 않는다.

**R5~R7 (변경 누적 — R0가 천장에 붙어 추가)** — (a)가 R0·R4를 모두 만점으로 통과해 **1순위 지표가 무정보가 됐다.** (b)를 설계하기 전에 *천장 없는 축이 하나라도 있는가*를 먼저 확인해야 해서, 범위 밖 목록에서 **기존 AC와 상호작용이 큰** 변경 요구 3건을 R4와 같은 형식·같은 세션에 연속 투입한다.

**동결 위반이 아니다.** §0이 금지하는 것은 *두 그룹 실행 사이에 이미 동결된 것을 고치는 일*인데, (b)는 아직 돌지 않았고 AC·CONTRACT·`prompt-a.md`는 건드리지 않았다. 세 문구는 §0에 해시로 박았고 **(b)에도 같은 순서로 동일하게 투입한다.**

## 8. 미리 밝혀두는 예상 결과 (사후해석 방지)

**처치군은 비용에서 질 가능성이 높다.** 조사 §5.2에 이미 있다 — 에이전트는 채팅 대비 약 4배, 멀티에이전트 약 15배. 페이즈 분할·TDD 강제·검증 서브에이전트는 전부 토큰을 더 쓴다.

**①과 ⑤는 4라운드 안에 양쪽 8/8로 수렴할 가능성이 높다.** 양쪽이 공통으로 받는 것이 ① 완전한 요구사항 산문 ② 읽고 실행 가능한 오라클 ③ 실행 커맨드 ④ 실패 시 출력 자동 투입 — 사실상 hill-climbing 과제이기 때문이다. 그 경우 결론은 **③④의 교환비 하나로 좁혀지며, 그건 실험 실패가 아니라 미리 예상한 결과다.** 그래서 1순위 지표를 §1처럼 **R0 시점 점수**로 옮겨두었다.

따라서 이 실험의 가설은 "처치군이 더 싸다"가 아니라
**"처치군이 R0 Gate 통과율과 피드백 투입 횟수에서 이기고, 그 대가로 비용을 더 쓴다 — 그 교환비가 얼마인가"**다.

### 실측 대조 (2026-08-02, (a) 실행 후 기입)

**예상이 빗나간 방향이 중요하다. 천장은 "4라운드 뒤"가 아니라 R0 그 자리에 있었다.**

| 예상 | 실측 |
|---|---|
| ①⑤가 4라운드 안에 8/8로 수렴 | **R0에서 즉시 8/8.** R1~R3은 투입할 실패가 없어 실행조차 안 됐다 |
| 그래서 1순위를 R0 점수로 옮겨둠 | **대비책과 대비 대상이 같이 무너졌다** |
| R4는 "천장이 없는 유일한 신호" | R4~R7 변경 요구 **4회 연속, 소스 199→306줄, 회귀 0** |

여기에 §8이 예상하지 못한 것 둘:

1. **모델을 낮춰도 안 깨진다.** 같은 프롬프트로 Sonnet 5 `8/8`($0.282), **Haiku 4.5 `8/8`($0.067·54초)**. 실패는 모델 능력의 함수가 아니다 — 과제-스펙 조합이 측정 하한 아래에 있다.
2. **AC가 회귀 안전망까지 흡수한다.** (a)는 5라운드 내내 자체 테스트 **0개**로 갔는데 **아무 손해도 보지 않았다**. §9-2는 AC가 "판정 주체 분리" 효과를 흡수한다고만 적었지만, 그보다 세다 — **처치군이 테스트를 더 써도 이 설계 안에서는 잴 수 있는 이득이 남지 않는다.** 지표 ②가 동어반복인 진짜 이유다.

**→ 구조적 결론**: 결정론적 Gate를 실행 전에 동결하려면 DOM 계약을 명시해야 하고, 그러면 스펙이 완전해지고, 스펙이 완전하면 프로세스 강제의 잔여분이 0이 된다. **AC 동결과 "프로세스 효과 측정"은 이 과제 난이도에서 양립하지 않는다.** r1 §2의 "스택 자유와 AC 동결은 양립하지 않는다"와 같은 구조이고 한 단계 더 근본적이다. 방향 선택지는 `docs/next/2026-08-02/r3.md` §6.

## 9. 한계 (리포트에 그대로 옮길 것)

1. **이 실험이 재는 것은 "프레임워크 전체 효과"가 아니다.** 스택·시드·AC·DOM 계약을 양쪽에 동일하게 주므로 그것들은 통제변수로 소거된다. 남는 것은 **"스택이 이미 고정된 조건에서의 프로세스 강제 효과"**다. 단 이것도 **프레임워크 자산이 도메인 무관하고 R0 전에 §0으로 동결됐을 때에 한해** 참이다.
2. **공통 층이 프레임워크 효과의 일부를 이미 흡수했다.** 범위 밖 목록(스코프 크립 억제), `test:ac` 커맨드 안내(테스트 실행 어포던스), **우리가 쓴 AC(판정 주체 분리)** 셋은 프레임워크가 주장할 수 있었던 효과지만 비교 공정성을 위해 양쪽에 동일하게 주어 소거됐다. 따라서 이 실험이 재는 처치의 **실질 잔여분은 RED 원문 제출 의무 + 페이즈 분할 + SDD 산출물 강제 셋뿐**이다.
3. **모든 Gate가 React + @testing-library에 결합된다.** React 이외 구현은 원천 배제된다. 다만 컴포넌트 분할·상태 관리는 규정하지 않는다.
4. **E2E를 포기했다.** 라우팅·실제 이벤트 순서·브라우저 고유 동작에서 jsdom과 실브라우저가 갈리는 버그는 잡지 못한다. 조사 §6-3("웹 도메인 결정론적 AC의 상한")에 대해 이 실험이 주는 답은 **"jsdom 수준까지"**로 좁혀진다.
5. **접근성은 accessible name 유무 1개만 Gate이고 나머지는 측정하지 않는다.** AC-08은 `aria-label="x"`로 통과한다.
6. **AC 동결은 파일 권한이 아니라 채점 시 복원으로 사후 보장된다.** 세션 중 조작 자체는 막지 못한다. 그룹 하나가 가짜 초록불을 보며 헛돌아 재실행 비용을 물 수 있고, 그 착각 자체가 M3의 측정 대상이다.
7. **적대적 에이전트에는 안전하지 않다.** postinstall 스크립트 등 채점 시점에 개입하는 경로는 막지 못한다. "정직한 자기 자신이 상대"라는 전제가 깨지면 이 설계는 무효다.
8. **n=1, 단일 머신, SAC Enforced 환경, 순서 효과 미통제.**
9. **DOM 계약을 프롬프트에 주는 것 자체가 설계 지시다.** 맨 Claude Code라면 받지 않았을 정보를 (a)도 받는다. 양쪽 동일하므로 비교는 공정하지만 **"완전한 백지 베이스라인"은 아니다.**
10. **프레임워크는 이 베이스라인의 관찰된 실패를 보고 설계된다 → 설계 편향이 있다.** (별도 앱으로 회피하면 일이 두 배라 감수하기로 한 선택. n=1 명시와 같은 태도.)

## 10. 종료 조건 (2026-08-02 등록 — **재실행 결과를 보기 전**)

### 왜 이 절이 필요한가

세 라운드 연속으로 같은 패턴이 반복됐다.

```
결과를 본다 → 흠을 발견한다 → 정당한 흠이다 → 조건을 고치고 재실행
```

r3(지표 4개가 천장) · r4(1순위가 RED 실행을 오독) · r5(승리가 오라클 열람과 상관) 전부 이 모양이고, **셋 다 판단 자체는 옳았다.** 문제는 이 패턴에 정지 조건이 없다는 것이다. 어떤 실험이든 사후에 흠은 나오고, 흠이 나올 때마다 고치면 실험은 영원히 안 끝난다.

§0이 **실험자 본인의 사후 손질**을 막는 장치라면, 이 절은 **실험자 본인의 무한 재설계**를 막는 장치다. 같은 이유로 결과를 보기 전에 박는다. 조건 변경은 이번(AC 제목 축약)이 **3회차이자 마지막**이다.

### 10.1 실행 완료 — 판단이 들어가지 않는다

```
① exp/ac/todo.ac.test.tsx의 it() 제목을 ID만으로 축약 (r5 §3-가)
   → 검증: 단언 로직 diff 0줄 + 시드에서 gateAC 0/8 유지(§5 Red-Check 재실행)
② §0 재동결 — ac/* 해시 교체 + 사유 기록
③ (a) 3회 + (b) 3회 실행 — Opus, 같은 프로토콜(§7.3)
④ 유효 3+3 확보 → 실행 종료
```

**라운드 유효 판정** (§7.3과 동일, 새 기준 없음):

```powershell
# 유효 = acRunOk true  AND  permission_denials 비어 있음
Get-ChildItem exp\runs\verdict-a2t*.json, exp\runs\verdict-b2t*.json |
  ForEach-Object { $j = Get-Content $_ -Raw | ConvertFrom-Json; "$($j.label)  acRunOk=$($j.acRunOk)" }
```

레이블·디렉터리는 `a2t{,b,c}` / `b2t{,b,c}` (t = title-shortened 조건). 기존 `a2*`/`b2*` 산출물은 **별도 조건의 결과**로 보존하고 덮어쓰지 않는다.

### 10.2 재실행 사유 화이트리스트 — 여기 없으면 재실행하지 않는다

| 사유 | 처리 |
|---|---|
| `acRunOk: false` | 그 라운드만 재실행 |
| `permission_denials` ≠ 0 | 그 라운드만 재실행 |
| 계측기 버그 | **재실행 없음.** §0 계측기 예외대로 전수 재측정 + 사유 기록 |

**그 외 전부 금지.** 특히 다음은 재실행 사유가 아니다 — 점수가 예상과 다름, 지표가 무정보로 보임, 더 나은 지표가 떠오름, 조건이 아직 불공평해 보임, n이 작아 보임. **이것들은 전부 §10.4의 리포트 §4(한계)로 간다.**

### 10.3 판정 규칙 — 승패를 정의하지 않는다

n=3에서 중앙값 1점 차를 "이겼다"고 부를 근거가 없다. r1 §2.4가 이미 *"통계적 유의성을 노리고 반복 실행하는 건 의도적으로 하지 않는다"*고 정했다.

> **관측된 차이를 그대로 싣고, 유의성은 주장하지 않는다.**

따라서 **(b)가 이기든 지든 동률이든 리포트는 똑같이 나온다.** 세 경우의 문장을 미리 등록한다 — 어느 쪽이 나와도 사후에 새로 쓰는 문장이 없도록.

| 결과 | 리포트에 쓸 문장 (사전 등록) |
|---|---|
| (b) > (a) | "얇은 스펙 + 제목 축약 조건에서, SDD 절차는 첫 구현 제출 점수를 `X`→`Y`로 올린다. 대가는 비용 `N`배다. n=3, 유의성 주장 없음." |
| (b) = (a) | "프로세스 강제(SDD 단독)의 잔여 효과는 관측되지 않았다." — r3 §6-(A)를 얇은 스펙 조건까지 확장하는 데이터다. |
| (b) < (a) | 그대로 싣는다. 처치가 점수를 깎았다는 관측이며, 비용 교환비와 함께 보고한다. |

**세 번째 경우에도 실험은 성공이다.** 이 실험의 산출물은 "프레임워크가 이겼다"가 아니라 **비교 리포트**이기 때문이다(r1 §1 완성 조건).

### 10.4 리포트 = 완성물. 목차를 지금 박는다

산출물은 **`docs/REPORT.md` 한 장.** 아래 5절이 전부 채워지면 이 실험은 끝이다.

```
1. 1순위 firstImplOracle — (a)×3 vs (b)×3, oracleTrace 병기
2. 비용 교환비 — cost / turns / 벽시계
3. 별도 조건 결과 — 완전 스펙 계열(전 지표 8/8 = 무정보)과 얇은 스펙 계열(제목 미축약)
4. 한계 — §9 전체 + 아래 4건
5. 프레임워크 트랙으로 넘기는 입력 — 이 실험이 답한 것 / 답할 수 없는 것
```

§9에 더해 리포트 §4에 반드시 들어갈 4건:

1. **단언 실패 원문으로 정보가 샌다.** 제목을 축약해도 `expected [] to deeply equal [ 'A', 'B' ]`는 남는다. 완전 차단은 불가능하고 목표는 "구현 전에 통째로 읽히는 것"만 막는 것이었다.
2. **조건을 3회 바꿨다.** 완전 스펙 → 얇은 스펙 → 얇은 스펙 + 제목 축약. 각 변경의 사유는 r3·r5에 기록돼 있으나, **변경 자체가 신호 탐색으로 읽힐 수 있다는 점을 숨기지 않는다.**
3. **처치는 SDD 조각 하나뿐이다.** r1이 구상한 셋(TDD 강제 / SDD / 페이즈 분할) 중 뒤의 둘은 r4 §4에서 **의도적으로 제외**됐다. 이 실험은 그 둘에 대해 아무 데이터도 내지 않는다.
4. **잰 범위는 jsdom 결정론 채점이 가능한 난이도까지다.** 긴 세션·큰 코드베이스·컨텍스트 관리는 이 설계로 영원히 측정되지 않는다.

### 10.5 안 하는 것 — 명시하지 않으면 효력이 없다

| 안 함 | 근거 |
|---|---|
| n을 3보다 늘린다 | r1 §2.4 — 논문급 실증이 목표가 아니다 |
| TDD 강제·페이즈 분할을 이번 실험에 추가한다 | r4 §4 — 별도 처치. 섞으면 어느 조각이 값을 했는지 분리 불가 |
| 과제를 바꾼다 | r3 §6-(B)에서 배제 |
| 지표를 추가·교체한다 | 세 번 바꿨다. `firstImplOracle`로 끝낸다 |
| `gateAC`를 결론에 쓴다 | 세 조건 전부 8/8. 이 과제에서 영구히 무정보(r5 §4) |

### 10.6 이 절의 발효

**이 절은 등록 시점부터 유효하고, 결과를 본 뒤에는 고칠 수 없다.** 고치고 싶어지는 순간이 정확히 이 절이 겨눈 순간이다. 그때 할 일은 조건을 바꾸는 것이 아니라 **§10.4의 리포트 §4에 한 줄 더 적는 것**이다.
