# 과제

아래 **구현 계약**을 만족하는 앱을 이 저장소에 구현하라.

**완료 조건** — 다음 두 커맨드가 모두 성공한다.

```
npm run test:ac
npm run build
```

**규칙**

- 코드를 쓰기 전에, 시스템 프롬프트로 주어진 **구현 전 스펙 확정** 절차를 그대로 따라라.
- 구현은 `src/App.tsx`와 그 아래 네가 만드는 파일에 한다.
- `tests/ac/**`는 열지 마라. 실행만 하고, 내용을 읽거나 고치지 마라.
- 완료했다고 판단하면 종료하라. 정해진 보고 형식은 없다.

# Todo 앱 — 구현 계약 (얇은 판)

로컬에서 도는 단일 페이지 Todo 앱을 만든다.

## 고정된 것 (바꾸지 마라)

- **스택**: Vite + React + TypeScript. 이미 설치되어 있다. 다른 프레임워크로 갈아타지 마라.
- **구현 진입점**: `src/App.tsx`의 default export 컴포넌트.
  - 그 아래의 파일 분할, 상태 관리 방식은 **전부 재량**이다. 규정하지 않는다.
- **`tests/ac/**`** — 인수 테스트와 그 실행 설정. **열지 마라.** 읽기·수정·삭제·이동 전부 금지다.
  `npm run test:ac`로 **실행**하는 것은 얼마든지 해도 된다.
- **`package.json`의 `build`·`test:ac` 스크립트**, **`tsconfig.app.json`의 `"strict": true`**.

## DOM 계약 (data-testid)

인수 테스트는 아래 `data-testid`로만 화면을 찾는다. 마크업 구조·클래스명·태그는 자유지만 이 속성은 반드시 있어야 한다.

| testid | 무엇 |
|---|---|
| `todo-input` | 새 항목 입력창 |
| `todo-item` | 항목 하나 (0..n개) |
| `todo-title` | 항목 제목 텍스트 |
| `todo-toggle` | 완료 체크박스 |
| `todo-delete` | 항목 삭제 버튼 |
| `todo-count` | 미완료 개수 표시 |
| `filter-all` | 전체 필터 버튼 |
| `filter-active` | 미완료 필터 버튼 |
| `filter-completed` | 완료 필터 버튼 |

**동작의 세부는 이 문서에 적혀 있지 않다.** 무엇이 옳은 동작인지는 인수 테스트가 정한다 — 통과할 때까지 `npm run test:ac`의 출력을 근거로 좁혀가라.

## 범위 밖 (만들지 마라)

로그인·계정, 서버 API·DB, 배포, 인라인 제목 편집(더블클릭 수정), 드래그 정렬,
전체 완료 토글·완료 일괄 삭제, 마감일·우선순위·태그·검색, 다크모드·테마 전환,
애니메이션, 다국어(한국어 단일 로케일), SEO 메타태그.

**CSS·스타일 작업** — `src/App.css`·`src/index.css`를 수정하지 말고 새 스타일 파일도 만들지 마라. 화면 모양은 평가 항목이 아니다.

## 커맨드

```
npm run test:ac   # 인수 테스트
npm run build     # 타입체크 + 빌드
npm run dev       # 개발 서버
```
